# ADR-06：IBKR 接入——先用 TWS 自动连接；开发期延迟行情（修订）

- 状态：已定（2026-10-22，Dylan）
- 取代：V4.1 第 2 章 ADR-06 中“TWS/IB Gateway + IBC 自动登录”的部分；库仍为 ib_async，经 BrokerAdapter 隔离
- 决策人：Dylan

## 背景

Dylan 希望“在 IBKR 的 TWS 打开的情况下自动进行连接”。账户已就绪，但尚未订阅实时行情，计划在模拟验证前订阅。

## 决策

### 连接方式

1. 首期用 **TWS**，不用 IB Gateway + IBC；IBC 自动登录与无人值守降为后续可选任务（P2，不在 M1）。
2. 连接由后台 tradingd 完成（桌面 App 只显示状态）。tradingd 的连接监督器在 TWS 打开后自动连接、断开后带退避重连。
3. **端口与账户安全规则（硬性）：**
   - 只探测 `127.0.0.1`。端口按运行模式白名单：PAPER 模式只连模拟盘端口（TWS 默认 7497），
     **绝不连接实盘端口（默认 7496）**，即使它开着。
   - 连上后先读取账户 ID 与账户类型，必须与受保护配置中登记的模拟账户一致（模拟账户通常以 `DU` 开头），
     不一致立即断开并进入 SAFE HALT。
   - B-03 只读阶段使用 TWS 的 Read-Only API 设置，B-05 才放开下单。
4. TWS 关闭、每日自动重启、每周需要手机二次验证的完整登录：系统检测到断连即进入“券商窗口 / DEGRADED”，
   停止新增订单并告警；恢复后先对账再恢复。这一步需要 Dylan 人工完成登录。

### 行情

5. 开发期允许用 **延迟行情** 跑通链路，由数据门禁的“允许延迟行情”开关控制：
   - 开关位于受保护配置（config/risk），只能 Dylan 修改；
   - 只在 PAPER 模式生效；开关打开时 ModeManager **拒绝进入任何实盘模式**（有测试强制）；
   - 延迟行情在界面与日志中始终标注“延迟”。
6. G2 门禁的“模拟账户必须拿到实时行情”仍是硬条件，不因开关而放宽。Dylan 订阅实时行情最晚要在 G2 之前
   （按并行排期约第 5 周，2026 年 11 月下旬）。

## 理由与代价

- TWS 更直观、Dylan 已在使用；省去 IBC 部署。
- 代价：无人值守能力弱于 Gateway + IBC——TWS 必须保持打开，每周二次验证需人工；夜间 TWS 意外退出时只能停止
  新增风险并告警（券商侧保护性止损仍在）。

## 影响

- B-03：+0.5 工日（端口白名单探测、账户核验、断连状态）。
- F-05：−0.25 工日（不部署 IBC），增加 TWS API 设置核对（Socket 端口、Read-Only、可信 IP 127.0.0.1）。
- D-05 / R-03：+0.5 工日（延迟行情开关及“开关打开即拒绝实盘”的测试）。
- 运行手册 S-11 增加“TWS 重启与二次验证”步骤。
