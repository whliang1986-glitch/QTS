# ADR-04：客户端形态——原生桌面 App（修订）

- 状态：已定（2026-10-22，Dylan）
- 取代：V4.1 第 2 章 ADR-04 中“桌面壳可选（S-06，P2）”的部分
- 决策人：Dylan

## 背景

V4.1 原方案是 React + TypeScript 的 Web 客户端由服务器托管，Tauri 桌面壳为 P2 可选。Dylan 要求客户端是
“正常的桌面端 App”。

## 决策

1. 客户端以 **Tauri 打包的 Windows 原生桌面 App** 为主形态（S-06 由 P2 可选改为必做，进入 M1）。
   界面仍是同一套 React + TypeScript 前端（S-04），浏览器访问保留为备用（如手机查看与急停）。
2. 桌面 App 只做界面与遥控，不持有数据库、券商密钥或模型密钥；所有动作经 apid 的认证 API。
3. 后台交易核心（tradingd、apid、workerd、guardd）是独立的 Windows 服务，**生命周期不归桌面 App 管**：
   - App 启动时探测服务状态：已运行则接入；未运行则请求系统服务管理器启动（需要时提示管理员授权）。
   - App 关闭、最小化到托盘、崩溃，都不停止服务，不影响订单与风控。
   - App 不提供“停止服务”按钮；停服务走运行手册。
4. 托盘图标显示模式（PAPER / LIVE）、连接状态与告警；断连时明确提示“数据可能已过期，服务器仍在运行”。

## 理由与代价

- 满足“正常桌面 App”的使用习惯，同时保持 ADR-02 的“客户端崩溃不影响订单”。
- 代价：S-06 工作量增加（服务拉起/接入、托盘、安装包、可选代码签名），并从 M2 前移到 M1 侧线。

## 影响

- S-06：P2 → P1，M2 → M1（侧线），1.5 → 3 工日。
- S-01：+0.5 工日（Windows 服务安装与“拉起或接入”协议）。
- S-04：Playwright 用例在桌面壳内外各跑一次关键流程（模式标识、急停四控件、断连提示）。
