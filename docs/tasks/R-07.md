## 设计

- **预期持仓** = 持仓调整合计 + 本系统全部有效成交（买正卖负，被更正取代的成交不计）。
  持仓调整（迁移 0006 `position_adjustments`，只追加）只有三类：
  - BASELINE：人工确认“以券商持仓为基准”（首次启动、备份恢复、人工处理差异后），只能在 HALT 下由人工发起，逐字输入确认短语；
  - CORPORATE_ACTION：与公司行动数据匹配上的调整，同一事件只能用一次（`(kind, reference)` 唯一）；
  - ACKNOWLEDGE：人工确认一笔外来成交（数量变化必须为 0，由触发器强制；持仓差异由 BASELINE 处理）。
- **Reconciler.reconcile(kind)** 每次核对：
  1. 账户：本进程已完成启动校验；
  2. 订单：SUBMITTING / UNKNOWN 未决订单；券商未结束订单按 OMS 回报认领口径认领（与 R-03 共用 `claim_open_orders`）——
     外来、重复、账户归属不一致、本地终态而券商未结束、本地未结束而券商没有、剩余数量或限价与本地（签发量 / 最后一次被接受的改单）不一致；
  3. 成交：券商近期成交（默认回看 7 天）中属于本系统的必须已入账；外来成交与账本里的未匹配成交必须已被人工确认；
  4. 持仓：逐标的比较；不一致时取公司行动数据匹配（预期 × 各未用事件比例 = 券商，允许零股向下取整），
     匹配上的写 CORPORATE_ACTION 调整、记为已解释；匹配不上、公司行动数据取不到、负持仓都是未解释。
  - 盘中容忍正常时序：下单中（SUBMITTING）、订单条款不符（部分成交未回报、改单进行中）、本地终态而券商未结束、
    本地未结束而券商没有、本系统成交未入账、持仓不一致——同一键在最近三次对账里出现两次才算未解释，首次记为待观察
    （PENDING，不停机但也不算对账通过）；UNKNOWN、外来、重复、负持仓、账户不符、取数失败一律立即升级。
    启动与日终一次即算。
  - 订单条款与签发值、最后一次被接受的改单、尚无结果的改单中任一相符即可。
  - 券商记录的账户不是已校验账户 → 未解释（首期单账户）。
  - 对账过程中任何异常（取数、账本读取、写调整）→ `reconcile_failed` 未解释；**先 SAFE HALT，再写报告**，
    报告写不进去也照样停机。
  - 报告写审计 `reconciliation`（每项代码、状态、键与说明）。
  - `last_clean()` 只认**本实例**最近一次对账：没有未解释、没有待观察项，且晚于最近一次 HALT（不看账本里以前进程的报告）；
    供恢复检查（ResumeChecks.reconciled）使用。对账通过**不会**自动恢复交易。
  - 公司行动：只用已生效、晚于该标的最近一次基准、尚未用过的事件；比例用整数对（新股 / 旧股）精确比较；
    多个事件一起解释时逐事件各写一条调整，每个事件只能用一次。
  - 采用基准：有 UNKNOWN / SUBMITTING 订单或本系统成交未入账时拒绝；写入前再确认一次仍在 HALT；
    审计记下每个标的的调整量与确认的成交号。
- arch_scan 只收紧：`recon-write`（持仓调整写入与对账审计动作名只在 storage 与 risk/reconcile.py）、
  `recon-adopt`（采用基准的入口与确认短语只在 risk/reconcile.py 与 server/api）。

## 剩余风险

- 采用基准的多条调整与审计不在同一事务：中途崩溃会留下部分调整（reference 带批次号，可追溯），之后对账会发现差异。
- 静态扫描拦不住拼接出来的对账审计动作名；但 `last_clean` 只认本实例内存里的报告，伪造账本审计不影响恢复判断。
- 账本打开时只核对触发器存在且会中止，不核对触发条件文本（沿用已有做法）；后续可改为比对触发器 SQL 哈希。
- 未匹配成交表不区分账户；多账户时会全部挂到当前账户（偏严，误报方向）。
- 很久以前、当时持仓为 0 而从未用过的公司行动事件会一直有效；之后若有无成交记录的持仓变化恰好成比例，可能被误解释。
  D-04 接入时给事件设回看上限（如只看最近一次对账一致之后的事件）。
- 抖动差异若每三次只出现一次，会一直停在待观察；待观察的那几次报告不算对账通过，但中间干净的报告算。持续抖动应由 S-07 告警。
- 采用基准一次确认回看期内全部外来成交与未匹配成交；S 组界面须先预览将写入的调整量与成交号，再要求输入确认短语。
- 多事件公司行动走“精确比例”匹配（券商保留零碎股）时，中间调整量仍按截断取整记录；合计正确，只是单条调整量与实际不符。
- 被取消的对账不停机、不写报告（只作废上一次结果）。
