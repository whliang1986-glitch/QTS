## 目标

撤单、改单与成交任意交错之后，本地的成交量、剩余量、有效下单数量与终态都与券商事实一致；
改单必须重新过风控（新的、已落账、从未用过的决定），一个决定只能用于一次改单。

## 非目标

- 保护性止损的撤单与急停（R-05）；改单的风控规则本身（R-01）；IBKR 改单异步拒绝的映射（B-05）。

## 接口与不变量

- `OrderManager.request_amend(intent_id, *, amendment_id, new_price, new_quantity, decision)`：
  - 只允许 SUBMITTED / PARTIALLY_FILLED，且没有待发的撤单、没有结果未定（未记录或 UNKNOWN）的改单；
    SUBMITTING、UNKNOWN、CANCEL_PENDING、终态一律拒绝（`AmendRefusedError`，不落账、不调用券商）；
  - 保护性止损暂不允许改单（R-04 定好止损改单规则后再开放）；
  - 决定必须已落账、属于该意图、从未被签发或别的改单用过，且决定时间严格晚于本订单已用过的全部决定；
    `OrderAmendment` 校验（新决定 id、时间不早于原决定、
    ALLOW 等于意图数量 / REDUCE 等于批准数量、价格在跳动上）；新数量必须大于已成交；
  - 改单请求（含决定）在调用券商**之前**落账（迁移 0005：`order_amendments`，decision_id 唯一；触发器保证决定属于同一意图、
    不是签发用过的决定），amendment_id 幂等：重放参数一致不再调用券商，参数不同或属于别的意图拒绝；
  - 改单结果是事件（`order_amendment_results`，最后一条为当前结果；触发器限定先后：无 → 任意，UNKNOWN → ACCEPTED / REJECTED，
    ACCEPTED → REJECTED（券商异步拒绝），REJECTED 终结）：接受 ACCEPTED；`AmendmentRejectedError` / `UnknownOrderError` →
    REJECTED；其他异常 → UNKNOWN 并通知 `on_unresolved`；`resolve_amendments` 按查单结果（数量与价格是否等于改单值）补记结果；
  - 有效下单数量 = 当前结果为 ACCEPTED 的最后一次改单数量（否则签发数量）；结果未定期间，全部成交按
    “有效数量与未定改单数量中较大者”判定，绝不按旧的较小数量提前判 FILLED；查证核对接受两者之一。
- 撤单竞态（O-01 已实现，本任务以随机测试固定）：撤单中部分成交保持 CANCEL_PENDING、撤单中全部成交转 FILLED、
  撤单被拒按累计成交回到活动状态、重复撤单不重复调用券商、提交中 / UNKNOWN 的撤单挂起后补发。
- 状态机不新增事件：改单不改变订单状态，只改变有效数量与价格。

## 验收标准

- [x] 改单：价格与数量生效、按新数量判定全部成交、幂等、必须新决定（原签发决定与上一次改单决定都不能复用）、未落账决定拒绝
- [x] 改单在错误状态（提交中、撤单中、数量不大于已成交）被拒且不落账、不调用券商
- [x] 券商拒绝 / 结果未知时有效数量保持原值并记差异
- [x] hypothesis 随机交错成交、撤单、确认 / 拒绝撤单、加量 / 减量改单后：成交量、有效数量、终态与券商事实一致，无非法转移
- [x] 加强版随机测试：回报暂存后乱序放出、改单在途时送达回报、改单随机被拒 / 发出前失败 / 发出后失败、随时查证；
      收尾查证后成交量、有效数量、终态与券商一致，每次真正的撤单请求只调用券商一次，被拒的改单不落账
- [x] 改单在途成交不提前判 FILLED；UNKNOWN 改单阻止新改单并可查证转正（ACCEPTED / REJECTED 两种）
- [x] 保护性止损改单拒绝；决定属于别的意图、REJECT、时间不晚于已用决定、价格不在跳动上都拒绝且不落账
- [x] ruff、mypy、全部测试、lint-imports、arch_scan 通过
- [x] safety-reviewer 评审：第一轮 REQUEST CHANGES（B1 未定改单导致误判 FILLED、B2 UNKNOWN 无法转正，I1–I4，S1–S5）；
      第二轮 REQUEST CHANGES（R1 券商未处理完即记 REJECTED、R2 查证与在途改单冲突）；第三轮 APPROVE，
      其建议（取消时不卡在途、长期未定逐轮升级、两条异常路径的测试）已一并处理

## 移交

- **O-05**：启动时对结果为空或 UNKNOWN 的改单调用 `resolve_amendments`（查单核对 total_quantity 与价格）后再恢复交易。
- **B-05**：IBKR 改单可能异步被拒（错误码回调）；适配器映射为改单结果后，OMS 追加 REJECTED（结果事件表允许 ACCEPTED → REJECTED）。
  **IBKR 适配器的 `modify_order` 必须等券商确认新数量与价格（openOrder 回报）后才返回，否则抛异常进入 UNKNOWN**：
  同步返回的 ACCEPTED 不能只表示“请求已发出”，否则减量改单可能让本地先判 FILLED、之后被异步拒绝时券商仍挂着余量。
- **R-01（G3 前硬前置）**：对改单重新评估价格与数量，签发新的决定；决定写入评估对象或其哈希
  （amendment_id、new_price、new_quantity），OMS 核对后才能消费——当前决定不绑定价格，任何新的 ALLOW 都能批准任意新价格。
- **R-04 / R-06 / R-07**：定保护性止损的改单规则（例如只允许收紧，或只允许公司行动调整）后再开放止损改单。
