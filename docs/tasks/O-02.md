## 目标

重复提交与重复回报不产生第二张订单或重复记账；成交更正按“取代”入账，有效成交量始终等于券商最终认定的数量。

## 非目标

- 佣金后到的入账口径（B-03）、日终与 Flex 对账（R-07）、崩溃恢复（O-05）。

## 允许修改范围

- 可以改：`server/oms/manager.py`、`server/storage/{schema.py,ledger.py}`、新迁移 `0004_execution_corrections.py`、
  `tests/integration/oms/test_order_manager.py`、`tests/integration/storage/test_ledger.py`、本任务单。
- 不得改：受保护路径、`scripts/arch_scan.py`、其他任务的公共接口。

## 接口与不变量

- 幂等（O-01 已建立，本任务补测试）：同一意图与决定重复提交、重启后（新 OrderManager 实例）再提交、并发提交，都只有一张券商订单；
  同一状态回报重复推送只写一次事件。
- 成交去重：execution_id 唯一；同一成交重放时数值先规范化（`canonical`：500.050 → 500.05，4.0 → 4），不会被误判为冲突。
- 成交更正（迁移 0004）：
  - 更正后的成交另起一行入账，`execution_supersessions` 记录“被取代 → 取代”，同一事务写入；
  - 一笔成交只能被取代一次，一笔更正只能取代一笔；触发器 `execution_supersessions_no_cross_intent` 要求两者属于同一意图、同一券商订单，且不能取代自己；
  - 有效成交 = 全部成交 − 被取代的成交；`filled_quantity` 与部分 / 全部成交的判定只看有效成交；
  - 更正链（更正的更正）逐级取代；更正重放幂等；
  - 更正先到：券商原文存入未匹配成交表等待；原成交（或上一级更正）入账时自动配对、补做取代（递归处理更正链）；
    查单结果先入账普通成交、再入账更正；被更正的成交已被别的更正取代时照实存入并记差异；
  - 更正重放：取代关系已存在且内容相同静默忽略，内容变了记 `correction_conflict`，保留第一次的事实；
  - 每次更正写差异审计 `execution_corrected`；终态后更正使数量不足时另记 `fills_missing`，状态不变，交对账。
