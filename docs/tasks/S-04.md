## 目标

用 React + TypeScript + Vite 做客户端核心页面（V4.1 10.3）：
- 总览、订单、持仓、风险、急停，以及始终可见的模式标识；
- 界面只是遥控器和显示器，所有动作走 apid 的认证 API；
- 同一套前端以后由 Tauri 打包成桌面 App（S-06，ADR-04）。

## 非目标

- 市场、策略中心、回测实验室、日志告警（S-05）；待审批队列（S-10）；桌面壳与托盘（S-06）。
- 持仓、净值、现金的数据源：tradingd 发布状态快照之前，页面明确显示“暂无数据”，不伪造。
- 不在客户端保存令牌以外的任何数据。令牌只放 sessionStorage（关闭页面即清除），不放 localStorage。

## 接口与不变量

- 只用生成的 `web/src/api/types.gen.ts`，不手写接口类型。
- **模式标识**：每页顶部都显示模式（PAPER / HALT / 未知）与连接状态。
  - 断开或数据过期时醒目提示“数据可能已过期，服务器仍在运行”；
  - 账本读不了（503）显示“未知”，不显示旧值冒充当前值。
- **急停四个控件**（V4.1 7.3：四个独立按钮，不合并成一个）：
  1. 停止新增（stop_new_orders，须填原因）；
  2. 撤销开仓单（cancel_open_orders）；
  3. 撤销保护性止损（高危：先申请二次确认，再输入 tradingd 的确认短语）；
  4. 紧急平仓（高危：先预览 preview_flatten，再二次确认，并输入确认短语）。
  - 每个按钮执行前都有确认对话框；高危操作还要求输入确认短语；
  - 默认不撤保护性止损：撤止损只能经第 3 个控件操作。
- **幂等**：每次操作生成一个 request_id。
  - 收到 504、断网或超时、503（retry_same_request_id）时进入“结果未知”，这个状态是粘性的：之后只能同号重试，或显式放弃；
  - 命令状态放在 App 级内存里：关闭面板、切换页面不会丢编号，刷新页面会丢（运行手册写明）；
  - 高危命令的确认号过期后重新申请，编号不变。
- **viewer**：不显示命令控件（服务端也会拒绝）。

## 验收标准
