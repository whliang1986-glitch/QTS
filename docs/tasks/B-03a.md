## 目标

把 ADR-06 的连接硬性规则、断线重连与重启窗口、IBKR 专有代码的映射写成可测试的代码。B-03b 只需把 ib_async 接到窄接口 `IbClient` 上，再到模拟盘核对映射。

## 非目标

- 不引入 ib_async，不连接任何 TWS / Gateway。
- 不实现行情、下单、撤单、查单（B-04 / B-05）；不实现 guardd 的跨 clientId 撤单验证（B-03b 在模拟盘实测）。
- 不新增受保护配置：登记的模拟账户 ID 与账户类型沿用 C-04 的 `ModeConfig`（受保护配置 `[mode]` 的 `account_id`、`expected_account_type`），由装配层传入。

## 接口与不变量

- `ConnectionPolicy`：参数在构造时校验，任何一条违反都抛 `ConnectionPolicyError`。
  - 主机只能是字面的 `127.0.0.1`；
  - 只有 PAPER 模式能连接券商；实盘模式在 G7 之前一律拒绝；
  - 端口只允许 7497；7496、4001 以及不在白名单的端口都拒绝；
  - 连接必须是只读的（B-05 放开下单）；
  - 登记的账户必须以 `DU` 开头。
- `verify_account`：连接后核验账户，不一致抛 `AccountMismatchError`，报错信息不回显账户号。
  - 券商只管理登记的这一个账户；
  - 账户类型（CASH / MARGIN）与登记一致；INDIVIDUAL 这类取值或缺失，视为无法确定，按不一致处理；
  - 基础货币是 USD。
- `ConnectionSupervisor`：
  - 断线后按指数退避重连，有上限；连接成功后连续失败计数清零；
  - 券商重启窗口内主动断开，且不重连；
  - 账户核验失败时：断开，状态改为 HALTED，停止重连，并向调用方抛出异常（装配层据此进入 SAFE HALT）；
  - 核验超时等暂时性错误：断开后重试，不留下只核验了一半的连接；
  - `trading_allowed()` 同时满足以下条件才为真：已连接、账户已核验、本次连接之后已对账（`mark_reconciled`）、底层连接仍在；
    任何断开、重连、1100 或进入窗口，都会清除“已对账”；对账用连接代号绑定到本次连接；
  - 每次状态变化都发出 `ConnectionEvent`。
- 映射（全部未实测，B-03b 核对）：
  - `order_state`：认不出的状态抛 `MappingError`，不猜测；中间状态返回 None；Submitted 且已有成交时为部分成交；
  - `order_type`：STP、STP LMT、TRAIL 等识别为止损，认不出的归为 OTHER（撤单需要确认）；
  - `error_info`：信息类代码不上报为错误，认不出的错误码归为 OTHER 且不可重试。

## 验收标准

- [ ] 实盘端口、非本机、实盘模式、非只读、非模拟账户都无法构造连接参数
- [ ] 账户不一致：断开并停止重连；重连之后必须重新对账才允许交易
- [ ] 重启窗口：断开、不重连、不允许交易
- [ ] ruff、mypy（win32 与 linux）、pytest、lint-imports、arch_scan 通过

## 必须覆盖的失败场景

- [ ] 端口 7496 / 4001 / 4002，主机 localhost 或局域网地址，模式为实盘、回测或 HALT
- [ ] 多账户、零账户、账户号不同、账户类型不同或无法确定、货币不是 USD
- [ ] TWS 没开（连续连接失败，退避）、核验超时、连接悄悄断开
- [ ] 认不出的订单状态、Filled 但仍有剩余、负的成交量

  - 用 ib_async 实现 `IbClient`，在 TWS 模拟盘核对映射表与账户摘要字段（AccountType 的取值）；

  - 适配器把 1100 / 1101 / 1102 交给 `note_broker_error`。
