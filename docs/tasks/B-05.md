## 目标

在只读适配器之上加分配订单号、下单、改单、逐单撤单，只用于模拟盘。
验收要点：限价单、拒单、撤单、当日过期在模拟盘上可以复现，契约套件通过。这两项都要等联调。

## 安全边界

能否真的下单，要同时过四道关：

1. 连接策略：
   - 只允许 PAPER 模式、本机、模拟盘端口 7497、DU 开头的账户。
   - 实盘端口在任何模式下都拒绝；G7 之前不存在实盘模式的连接。
   - 本任务只放开一点：PAPER 模式可以 `readonly=False`。
2. 适配器：
   - 只读适配器只接受只读策略。
   - 下单适配器只接受非只读策略。
3. 客户端：非只读连接要在构造时显式写 `allow_orders=True`，默认只读，忘了配置时不会意外放开。
4. TWS 设置：Read-Only API 由 **Dylan 本人**在 TWS 里取消勾选（F-05 清单），我不会替他操作。

其他规则：
- 下单只接受 OMS 签发的票据，票据里带着风控决定。适配器不做风控判断，也不放宽任何规则。
- 订单类型只有限价单和保护性止损单（止损单），没有市价单。GTC 只给保护性止损用。
- 不在内部重试。同一订单号只发一次，发送失败也不重发，由 OMS 计时进入 UNKNOWN 后先查单。
- 撤单只能逐单进行，没有全局撤单。止损单和认不出的类型，没有显式确认一律不撤。
- 别的 clientId 下的单和 TWS 手工单，本连接不能改、不能撤。遇到时明确报错，不假装成功，也不当作“没有这张单”。

## 做了什么

- `server/broker/ibkr/connection.py`：PAPER 模式允许 `readonly=False`；`readonly` 必须是 bool 本身。
- `server/broker/ibkr/client.py`：
  - 新增 `allow_orders` 开关，默认关闭；
  - 非只读连接必须显式开启这个开关；
  - 本机和模拟盘端口的限制不变。
- `server/broker/ibkr/adapter.py`：只读适配器拒绝非只读策略。
- `server/broker/ibkr/trading.py`：
  - `ib_order(ticket, account_id)`：把票据转成 IBKR 订单。
    - 数量用风控批准的数量，必须是正整数股。
    - Decimal 转成 float 后要核对一遍，变了就拒绝，不悄悄取整。
    - 订单号必须是正整数。
    - 同时写入账户、orderRef（意图 ID）、有效期；GTD 的到期时间用 UTC 写法。
    - `transmit=True`，`outsideRth=False`。
  - `IbkrPaperAdapter`：
    - `next_order_id`：取连接分配的请求编号（OMS 再取 max(券商, 账本 + 1)）。
    - `place_order`：
      - 先核对账户，再确认合约（必须有 conId、是股票或 ETF、美元计价）。
      - 先占订单号再发送。重复的订单号拒绝；发送失败也不重发。
    - `modify_order`：
      - 只改本连接下的单，而且只改价格和数量。
      - 已结束的单和没有的单，都报 UnknownOrderError。
      - 撤单进行中，或新数量不大于已成交量，报 AmendmentRejectedError。
      - 改单时复制一份新订单发送，不改动 ib_async 持有的原订单。
    - `cancel_order`：
      - 只撤本连接下的单。
      - 止损单和认不出的类型，必须显式确认。
      - 已结束的单和没有的单，报 UnknownOrderError。
      - `perm-` 开头的外来单，报 BrokerUnavailableError。
    - 回报事件沿用只读适配器的处理。撤单后 ib_async 会先报 PendingCancel，对应 CANCEL_PENDING。

## 评审修复（safety-reviewer 第一轮 REQUEST CHANGES，没有 P0）

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 重复订单号的检查和占号之间隔着一次 await。同号并发时可能发出两次，第二次会被 IBKR 当成改单 | 检查通过后立刻占号，放在任何 await 之前；补了并发测试 |
| P1 | 改单和撤单只按订单号找单，不核对意图和券商侧类型 | 改单要求 orderRef 与意图一致，券商侧类型与意图一致，OTHER 一律拒绝；撤单要求订单带 orderRef |
| P2 | 改单发送失败时的处理和下单不一致 | 统一报 BrokerUnavailableError，文案改成“结果未知，先查单” |
| P2 | `allow_orders` 构造后还能改 | 改成只读属性 |
| P2 | 订单已在撤销时还会再发一次撤单 | 不再重复发送 |
| P2 | 合约白名单里有 "ETF" | IBKR 的 ETF 也是 STK，白名单只留 STK |
| P2 | 测试缺口 | 补了：时区偏移、止损改单写入 auxPrice、账户不一致、Inactive、OTHER 类型撤单、改单发送失败、缺 conId 或非美元合约 |
| P2 | “三道开关”“四道开关”说法不一 | 统一为四道 |

## 剩余风险（接装配层时处理）

- **监督器重连**：B-03a 的连接监督器重连时固定用只读连接。只读模式下 ib_async 不同步本连接的挂单，`ib.trades()` 会不完整，去重和找单就会失效。装配时只能二选一：让监督器使用 `policy.readonly`，或者下单适配器不经监督器、自己重连。
- **合约口径**：确认合约时没有核对 primaryExchange、conId 和 `ticket.instrument` 是否一致，只看了 conId 存在、STK、USD。联调时核对，必要时在 Instrument 里登记 conId 再比对。
- **盘外止损**：保护性止损设了 `outsideRth=False`，只在正常交易时段触发，盘前盘后不会触发。
  - 协调助手 2026-11-05 决定先用这个默认，作为“模拟盘跑一段时间后复核”的待办；
  - 如果 Dylan 另有决定，以他为准；
  - 联调时仍要核对实际触发行为（见联调清单第 8 条）。

## 联调时必须核对（Dylan 取消勾选 Read-Only API 之后；在这之前不能下单）

1. **契约套件**：在 IBKR 模拟盘上跑 `tests/contract/broker_contract.py`，需要另写 IBKR 的驱动器。
2. **限价单**：挂单、成交、部分成交的回报顺序；`orderStatus` 的数量什么时候到。
3. **拒单**：价格不在最小跳动上、数量不对时的报法。IBKR 可能报成 Cancelled，需要结合错误码 201 来区分。
4. **撤单**：先报 PendingCancel，再报 Cancelled；撤一张已经成交的单时，错误码是 161 还是 10148。
5. **当日过期**：DAY 单收盘后的报法，可能是 Cancelled，也可能是 Inactive。
6. **GTD**：到期时间的写法 `yyyyMMdd HH:mm:ss UTC` 能不能被接受，到期后怎么报。
7. **改单**：改价、改量的回报；改单被拒时 Trade 里的订单是否保持原值。
8. **保护性止损**：`outsideRth=False` 时，盘前盘后不会触发止损。需要核对这是否符合 R-04、R-06 的要求。
9. **订单号**：`getReqId` 与 TWS 下发的 nextValidId 是否一致；重连后订单号有没有回退。
10. **外来单**：别的 clientId 的单能不能撤（guardd 方案，B-02 待实测清单第 1 条）。
