## 目标

apid 对客户端提供 `/v1` REST 查询、命令入口与 WebSocket 事件流：
- 查询只读账本；
- 命令一律经本机通道交给 tradingd，由 tradingd 按 request_id 去重；
- 由 OpenAPI 生成 TypeScript 类型。

## 非目标

- 不做正式的令牌签发、吊销、TLS 与高危命令的二次确认令牌（S-03）。本任务只定义认证接口。
  生产入口在 S-03 之前拒绝启动（失败即关闭），不提供“无认证”模式。
- 不做持仓、净值、现金查询：这些数据来自券商同步与风控的持仓口径，apid 不能 import risk / broker
  （import-linter `no-broker-from-decision-layers` 含间接依赖）。改由 tradingd 发布状态快照，
  随 S-04 / B 组接入（见移交）。
- 不做行情、告警事件流（D 组、S-07）。
- 不做 Web 客户端（S-04）。
- 不提供任何修改风控限额的 API（V4.1 10.1：限额只走受保护配置）。

## 接口与不变量

- `server.api.app.create_app(ApiDeps)`：
  - `GET /v1/status`：模式、HALT（原因、时间、操作者）；
  - `GET /v1/orders?limit=`：最近订单的摘要与最新状态；
  - `GET /v1/orders/{intent_id}`：意图、状态历史、成交；
  - `GET /v1/commands/catalog`：可用命令、分级与参数；
  - `POST /v1/commands`：`{request_id, name, params}`；
  - `WS /v1/stream`：先认证，再推送状态与订单事件。
- 认证：`Authenticator` 协议（令牌 → `Principal(name, role)`），S-03 提供实现。
  - 每个 HTTP 路由、WebSocket 都要认证，没有匿名路由；生产不开放 `/docs` 页面。
  - viewer 只读，命令只给 owner。
- 命令：
  - 名称白名单与参数键白名单在 apid 先校验一遍（tradingd 再严格校验）；
  - 操作者取认证结果，不接受请求体自报；
  - 分级：只读 / 控制 / 高危（V4.1 10.1）。高危命令必须带 tradingd 给出的确认短语；二次确认令牌在 S-03 加。
- 幂等：request_id 由客户端生成，重试不换（CLAUDE.md）；apid 不保存命令状态（ADR-14），也不自行重发。
- 结果语义：
  - 连不上 tradingd：503，命令确定未发出，可重试；
  - 已发出但断开或超时：504，结果未知，必须用同一 request_id 重试查询原结果，不得换号重发；
  - 入口拒绝：409；
  - 暂时性失败：503，可用同一 request_id 重试；
  - 已执行：200，返回 `ok`、`detail`、`replayed`。
  - tradingd 内部出错（非规则拒绝）：503，结果未确认。副作用可能已发生（tradingd 不记录这类结果），
    提示先查看状态，再用同一 request_id 重试。
- apid 对账本只读（只读模式 + query_only），单写者不变。
- 严格模式：请求模型拒绝未知字段（V4.1 4 章）。

## 验收标准

- [ ] OpenAPI 导出到 `docs/api/openapi.json`，TS 类型生成到 `web/src/api/types.gen.ts`；
      测试比对仓库里的文件与当前代码生成的一致（接口改了忘记重新生成即失败）。
- [ ] 命令幂等：同一 request_id 重试返回原结果（`replayed=true`），不执行第二次；同号换参数被拒绝。
- [ ] 无令牌、令牌无效、viewer 发命令都被拒绝；WebSocket 不认证不推送。
- [ ] 账本不可读时查询返回 503，不返回空列表冒充“没有订单”。

## 必须覆盖的失败场景

- [ ] 发出后超时：504，提示用同一 request_id 重试；重试拿到原结果，命令只执行一次。
- [ ] tradingd 不在：503，命令未发出。
- [ ] 未知命令、多余参数、请求体多余字段、request_id 不合法：422，不发给 tradingd。
- [ ] 请求体自报操作者：被拒绝（未知字段）。
- [ ] apid 用只读连接：试图写账本失败。
