## 原则

1. **先安全，再好看。** 不为好看减少任何安全提示或确认步骤。
2. **克制。** 大面积用中性色，强调色只用少量。
3. **信息分层。** 第一眼要能看到：当前模式、系统是否正常、账户总览。
4. **颜色不是唯一信号。** 盈亏、模式都带符号和文字（▲▼、正负号），对色弱用户友好。
5. **中英文都好看。** 英文更长，布局不能被撑坏（S-12 之前先用长文案压测）。

## 视觉语言

- **主题**：默认深色，同时提供浅色；可以跟随系统，也可以手动切换。两套主题的正文对比度都至少达到 WCAG AA（4.5:1）。
- **颜色**：统一用 CSS 变量定义：
  - 背景三层；
  - 文字三级；
  - 一个品牌强调色；
  - 四个语义色：正常、警告、危险、信息；
  - 一对色弱友好的盈亏色：蓝 / 橙，不用红 / 绿作为唯一区分。
- **字体**：系统无衬线字体栈（Segoe UI、Microsoft YaHei UI、PingFang SC）。价格、数量、时间用等宽数字（tabular-nums）。
- **间距与形状**：间距按 4 / 8 的刻度；圆角两档；尽量少用阴影，层次靠底色深浅区分。
- **图标**：统一使用线性图标（内联 SVG）。
- **动效**：只用于两处：状态切换时淡入淡出，数据刷新时轻微高亮。系统开启“减少动效”时关闭。

## 组件

- **模式标识**：固定在顶部，三种状态。每种状态除了颜色，都必须有文字。
  - PAPER：平静的蓝绿色；
  - HALT：醒目的红色条带，并带图标；
  - 未知：琥珀色，并说明“数据可能已过期”。
- **急停区**：
  - 与其他内容单独隔开；
  - 危险操作用红色描边，但不过分抢眼；展开确认后按钮才变成实心红；
  - 每个确认步骤都要写清楚“这会做什么”。
- **表格**：
  - 行高适中，表头固定，数字右对齐，状态用小标签；
  - 空状态要有说明和图示；
  - 可以用键盘操作。
- **总览**：
  - 数字卡片：净值、现金、当日盈亏、持仓数；
  - 一条简洁的净值曲线；
  - 没有数据时显示骨架屏和“暂无数据”。
- **提示条**：加载、成功、失败、超时四种，样式统一。失败提示要说人话，并给出下一步怎么做。
- **布局**：桌面优先；缩到手机宽度仍可用（单列布局，导航移到底部）。

## 不做

- 炫酷的交易大屏、霓虹色、闪烁的数字。
- 为了好看而减少安全提示或确认步骤。

1. **设计基础**：变量、主题切换、字体与间距规范，以及一页“组件陈列室”。陈列室展示按钮、标签、表格、卡片、提示条、模式标识的全部状态，深浅两套都要有。
2. **截图把关**：用 Playwright 给组件陈列室和五个页面截图。
   - 深色、浅色两套 × 桌面（1440）、平板（834）、手机（390）三种宽度；
   - 存到 `docs/design/screenshots/`；
   - Ada 看截图把关，改到满意后再套用到所有页面。
3. **视觉回归测试**：关键页面保存截图基线。
4. **无障碍检查**：对比度、焦点顺序、键盘操作、屏幕阅读器标签（axe-core 加上手工用例）。
5. **Tauri 壳**（S-06）沿用同一套变量。
