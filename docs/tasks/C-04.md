## 目标

运行模式的唯一事实来源（V4.1 6.2）：启动校验、HALT 持久化与人工恢复、实盘切换门禁；落实 ADR-06（延迟行情开关）
与 ADR-15（账户类型与风控口径）。

## 非目标

不读取配置文件（C-05 负责版本化加载；这里接收已解析的 `ModeConfig`）；不连券商（账户事实由调用方传入，
B-03 之后来自 BrokerAdapter）；不做运行状态机 NORMAL / DEGRADED / SAFE HALT 的健康检查（R-08）；
不做急停四级的撤单动作（R-05）。

## 设计

- 位置：`server/risk/mode_manager.py`（风控拥有 HALT；依赖 storage 的账本与 domain 模型）。
- 模式持久化在账本 `mode_changes`；**每次模式变化与相关审计在同一个事务里写入**
  （`LedgerRepository.commit_mode_and_audits`，C-03 的新增接口），不会出现“审计已写、HALT 未写”。
- `ModeConfig`（来自受保护配置，C-05 加载）：请求模式、账户 ID、**登记的账户类型**、风控口径、延迟行情开关、配置版本。
  配置自身校验：延迟行情开关只能配 PAPER；保证金口径要求登记类型也是保证金。
- `start(config, account)`：
  1. 请求实盘 → `LiveModeLockedError`；请求 HALT、账户 ID 不一致、口径放宽而真实账户不是保证金 → `StartupRefusedError`。
     两者都先把 HALT 与本次账户观察写入账本（同一事务），再抛出。
  2. 真实账户类型与登记不一致、或与该账户上次观察到的类型不同、或换了账户 → SAFE HALT（HALT 并说明原因）。
  3. 上次状态是 HALT → 保持 HALT。否则进入请求的模式。
  4. 任何异常（含存储失败）都在本进程内闩锁为拒绝，`require_trading_allowed()` 从此一律拒绝，不依赖账本。
- `require_trading_allowed()`：闩锁、无状态、HALT、非 PAPER 模式一律拒绝（首期只有 PAPER 能新增风险）。
- `halt(reason, actor)`：对空原因、含空格或过长的操作者名容错，保证尝试落盘；写入失败则闩锁并抛出。
- `resume(target, actor, checks)`：要求本进程启动校验已通过、目标是配置请求的模式、真实类型与登记一致、
  当前处于 HALT、六项检查全为真（StrictBool）、操作者不是程序名（不区分大小写）；被拒也写审计。
- `observe_account(account)`：供 B-03 在重连时调用，账户 ID 或类型与启动时不同即 SAFE HALT。
- `request_live_switch(...)`：G7 之前一律拒绝并写审计。
- 实盘锁的纵深防御：代码中没有任何解锁开关；迁移 0002 的触发器拒绝在 mode_changes 写入实盘模式；
  arch_scan 新规则 `mode-write`：模式变更写入只能出现在 `server/risk/mode_manager.py`。
- 原因文本中的账户号脱敏（如 `DU****567`）；审计明细保留完整账户号。

## 账户升级为保证金时的操作顺序（写给 Dylan）

1. 在 IBKR 完成升级后，系统下次启动会因“真实类型与登记不一致”进入 SAFE HALT（提示修改受保护配置）。
2. Dylan 修改受保护配置：登记类型改为 MARGIN（口径可继续保持 CASH，从严）。
3. 重启后系统**仍保持 HALT**（重启不会自动解除）。如果第 1 步之前没有在升级后的账户上启动过，原因显示为
   “账户类型变化”；如果启动过，保持的是第 1 步的 HALT，原因仍是那条“与登记不一致”——这时配置已经改好，
   提示可以忽略，直接进入第 4 步。
4. 完成检查后由 Dylan 人工恢复；之后再重启不会因同一次变化再次 HALT。
5. 运行中重连时如果发现账户变了，系统进入 SAFE HALT 并要求**重启**（本进程不允许恢复）。
