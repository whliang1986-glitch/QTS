## 目标

V4.1 7.1–7.2：风控是唯一能把意图交给 OMS 的入口，给出 ALLOW / REDUCE / REJECT / HALT 四种结论；
风控不可用时不放行。并完成 O-03 移交的 G3 硬前置：**决定绑定评估对象**，一个 ALLOW 不能被拿去批准
别的意图、别的价格或别的数量。

## 设计

- `server/risk/engine.py`：`RiskEngine.submit(intent)` / `amend(intent_id, ...)` / `decide(subject)`。
  - 顺序：模式门禁（`ModeManager.require_trading_allowed`）→ 规则集就绪 → 上下文采集（超时拒绝）→ 逐条规则 → 汇总。
  - 失败即关闭：模式不允许、规则集缺失或为空、上下文失败或超时、规则抛异常 → REJECT（命中 mode_gate /
    rule_set_missing / context_unavailable / risk_timeout / rule_error）。
  - 汇总：HALT > REJECT > REDUCE > ALLOW。HALT 经 ModeManager 持久化停止。REDUCE 取各规则允许数量的最小值并向下取整股；
    没给数量、不小于原数量、取整后为 0、改单 → 按 REJECT。只缩数量，不改方向、类别与价格。
  - 改单数量（O-03 约定）：新数量大于意图数量 → 评估前拒绝（amend_quantity）；规则全部放行且新数量小于意图数量 →
    REDUCE（批准数量 = 新数量，摘要仍绑定新数量）；等于意图数量 → ALLOW。
  - 模式状态读不出来、规则返回值不合法同样不放行。
  - 决定先落账再调用 OMS；落账失败不调用。同一意图重试沿用已签发的决定（不重新评估、不重复下单）；
    同一意图 ID 内容不同 → REJECT（intent_conflict）。
- 规则接口：`Rule.check(subject, context) -> RuleResult | None`，带 rule_id 与版本；`RuleSet(version, rules)` 版本写入决定。
  阈值规则（R-02，参数来自 Dylan 提交的受保护配置与 ADR-16 的运行时调整）、数据门禁（R-03）、默认禁用与止损豁免（R-04）
  都以规则加入，本任务不定任何阈值。
- **决定绑定评估对象**：`RiskDecision.subject_digest`（server/oms/binding.py）：新单 = 意图全部内容的规范化 SHA-256，
  改单 = 意图摘要 + amendment_id + 新价格 + 新数量。OMS 在签发（`_check_submission`）与改单（`_amendment`）时重算核对，
  对不上或没有摘要一律拒绝。摘要模块放在 oms：领域层不允许 hashlib，risk 可以导入 oms。
- **arch_scan 收紧**：新增类别 `risk-decision`（RiskDecision 只能在 domain、storage、oms、risk、broker、backtest 中出现），
  策略、AI、API 不得构造或引用风控决定。只收紧，DYNAMIC_EXEMPTIONS 未动。

## 移交

- **R-02**：参数模型与 ADR-16 运行时调整（受保护配置定上下限，面板只在范围内调；调松须 Dylan 二次确认）；
  参数缺失时规则集为 None → 全部拒绝。
- **R-03**：上下文提供者接入行情与账户（新鲜度门禁）。**R-04**：默认禁用与保护性止损豁免规则。
- **R-04 / R-05**：REDUCE 目前对任何订单类别生效；缩小保护性止损数量等于让部分仓位失去保护，HALT 也会拦截
  保护性止损与减仓单——由 R-04（止损豁免）与 R-05（急停下允许的减风险动作）定规则。
- **R-02 / R-03**：同步的 `rule.check` 没有耗时上限，只对上下文采集设了超时；加入真实规则时定耗时预算。
- **S-01 / OMS**：同一意图并发两次提交会在签发前查重处产生误报差异；tradingd 按 intent_id 串行化。
- 改单新数量不大于已成交量时，决定先落账、再由 OMS 拒绝（失败即关闭，留下一条用不上的决定）；R-02 有持仓与成交上下文后在规则里提前拒绝。
- R-01 之前已签发、没有摘要的意图，重试提交会被拒绝而不是按幂等返回状态（失败即关闭，开发期无此类数据）。
- **S-01**：tradingd 启动时装配 RiskEngine（ModeManager 启动校验 → 券商连接与 OMS 对账 → 接受意图）。
