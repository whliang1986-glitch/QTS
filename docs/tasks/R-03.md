## 设计

- **RiskContext 新增**：`quotes`（各标的报价）、`clock_skew_ms`（本机 − 券商，带符号）、`account_synced`
  （持仓、现金、订单自上次连接以来已同步；None 为未知）、`delayed_data_allowed`（ADR-06）。
- **DataGateRule**（`server/risk/data_gate.py`，加入 `build_rule_set`）：开仓、减仓（含紧急平仓与改单）逐项检查，
  任一不满足即拒绝，原因是模块常量：
  1. 账户已同步（不是 True 一律拒绝）；
  2. 时钟偏差已知且 |偏差| ≤ max_clock_skew_ms；
  3. 有该标的报价，标的一致，没有任何质量标记；
  4. 延迟行情只在受保护配置允许时接受（ADR-06，配置校验保证只限 PAPER），年龄上限加交易所规定的 15 分钟延迟
     （`DELAYED_FEED_LAG`，单位定义，不是可调阈值）；允许延迟行情不放宽实时报价；
  5. 按已知时钟偏差换算成券商时间后，报价时间不晚于“券商时间 + 时钟偏差上限”，年龄 ≤ max_quote_age_ms；
  6. 买价、卖价都有且不交叉，价差（相对中间价）≤ max_spread_bps；
  7. 报价有最新价，且与风控使用的 last_prices 一致。
  **开仓**还要求全部持仓与挂单标的的报价同样通过 3–7（净值、总敞口、单标的占用都依赖这些价格）；
  减仓只依赖本标的。
  **保护性止损豁免**：它不新增风险，数据不可信时拒绝它会让持仓失去保护；它的专项规则仍要求最新价可用且止损价低于最新价。
- **LedgerContextProvider**（`server/risk/context.py`）：来源全部以协议注入（risk 不得 import broker，适配器按结构满足）。
  - 持仓、现金来自券商，持仓只保留本账户的；本单标的有规格才取报价（急停快照的占位对象不取），
    持仓与挂单标的都取；最新价取自报价；
  - 未结束订单：**先取券商快照、再读账本**（OMS 先落签发记录后下单，读取间隙里新下的单不会被误判为外来）。
    本地视图为本账户、已签发、未终态（含 SUBMITTING / UNKNOWN 与撤单中）；数量取签发量与所有未被拒改单中的最大值
    减已成交，买单价取最高、卖单价取最低；再与券商事实取更保守者（剩余量取大，买价取高、卖价取低）；
  - 券商侧有本系统不认识的本账户未结束订单，或标的、方向与本地不一致 → `open_orders=None`，并报告状态不可信
    （调用方接 `ModeManager.safe_halt`）；按“原因 + 券商订单号”去重，回调失败下次重试，出现新订单会再报；
    本地已终态而券商仍显示未结束 → 本次 `open_orders=None`，不报告（多半是回报时差，交 R-07）；
  - 券商订单的认领与 OMS 回报认领同一口径：orderRef + 登记的券商订单号 + permId；同一意图两张券商单即不一致；
  - 现金只用本账户的；`now` 在取完数据后才取（报价年龄不少算取数耗时）；
  - 净值 = 现金合计 + Σ 持仓 × 最新价，任一持仓没有最新价即 None；近期签发取一分钟窗口；
  - 任何来源抛错 → 对应字段 None（不是 0，不是空映射），由用到它的规则拒绝。
- `ModeManager.delayed_data_allowed()`：已完成启动校验且配置允许时为 True。

## 验收标准

  拒绝（失败即关闭，影响可用性），评估是否并发取数。

## 需要 Dylan 决定（不阻塞）

- 延迟行情的年龄上限按“报价陈旧上限 + 15 分钟”处理（仅在受保护配置允许延迟行情的模拟盘）。如需更严，可在配置里关掉延迟行情。
- 紧急平仓同样要过数据门禁：行情陈旧时急停平仓会被拒（失败即关闭），此时只能靠保护性止损和第 1、2 级急停。
- 保护性止损豁免数据门禁，它的“止损价低于最新价”检查可能用到陈旧且偏高的最新价，放行一张提交即触发的止损。
  它仍受成本价区间约束，效果是保护性卖出，暂按可接受处理；如要更严，可让止损也要求报价新鲜（代价是数据异常时持仓无保护）。

## 已知取舍

- **保护性止损豁免数据门禁（维持现状，宁可有保护）**：行情陈旧时，止损的“止损价低于最新价”检查可能基于偏高的旧价，
  挂出后立即触发，等于一次保护性卖出；它仍受成本价区间、数量等于持仓、来源与参数等专项规则约束，不会新增风险。
  反过来，若止损也要求报价新鲜，数据异常的时段里新持仓将没有止损保护，风险更大。开发方建议维持豁免，协调方同意；
  Dylan 可随时要求改为更严的口径。
