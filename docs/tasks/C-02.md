## 目标

把 V4.1 6.3 的 OMS 订单状态机写成 domain 里的**数据**（转移表）加一个纯函数 `transition(status, event)`，
非法转移抛 `IllegalTransitionError`；统一事件模型；时间先后约定（信号 < 下单 < 成交）。

## 非目标

不做数量累计、幂等去重、持久化与恢复（O-01 至 O-05）；不做对账（R-07）。

## 对 V4.1 6.3 表的三处解读（请 Dylan 验收时确认）

1. **撤单等待中的部分成交**：V4.1 表写 CANCEL_PENDING → PARTIALLY_FILLED。这里改为 CANCEL_PENDING 收到部分成交后
   **仍停留在 CANCEL_PENDING**（已成交数量由 O-01 累计）。否则随后到达的撤单确认会落在 PARTIALLY_FILLED 上，
   要么被判非法，要么只能放开 PARTIALLY_FILLED → CANCELLED，削弱“撤单请求发出不等于撤单成功”的语义。
2. **券商主动撤单与撤单被拒**：允许 SUBMITTED / PARTIALLY_FILLED 收到“券商撤单”转 CANCELLED；
   CANCEL_PENDING 收到“撤单被拒”回到活动状态，**目标由 has_fills（累计成交是否大于 0）推出**：
   有成交 → PARTIALLY_FILLED，无成交 → SUBMITTED。调用方不能指定目标。
3. **提交中即成交**：IBKR 的成交回报可能先于接单确认到达，允许 SUBMITTING 收到部分 / 全部成交直接转
   PARTIALLY_FILLED / FILLED（成交本身证明券商已接单）。

## 不变量

- 终态（FILLED、CANCELLED、REJECTED、EXPIRED、REJECTED_BY_RISK）不再转移。
- **成交入账独立于状态转移**：成交按 execution_id 去重后必须入账，无论订单处于什么状态（含 UNKNOWN 与终态）
  （IBKR 的 orderStatus 与 execDetails 是两路回调，“撤单确认后才到达撤单期间的成交”“已 Filled 后才到达最后一笔
  成交”都是常态）；状态机层面这类回报是非法转移，O 组据此生成差异事件与告警，**不得丢弃成交，也不得因此 HALT**。
- UNKNOWN 只能通过“查询券商后观察到的状态”转出；从 UNKNOWN 再次发送（重发）是非法转移。
- 风控之前不能发送；风控拒绝是终态 REJECTED_BY_RISK。
- `transition()` 入口把状态与事件规范为枚举，原始字符串不会走错分支。
- 统一事件模型 `OrderEvent`：event_id、intent_id、kind、UTC 时间、correlation_id，以及与事件类型匹配的
  observed / has_fills（不匹配即拒绝构造）。
- 时间：信号时间 < 下单时间 < 成交时间；信号时间必须晚于其依据的 bar 结束时间；所有参数规范为 UTC，
  不带时区一律 TimeOrderingError。

## 移交给后续任务（必须在对应任务单的验收标准中出现）

- **O-01**：
  - 订单事件落库的唯一路径是“先 transition() 再写账本”（ledger 的 append_order_event 不自己判断转移）。
  - 撤单被拒时用累计成交数量计算 has_fills，不得由回报直接给出目标状态。
  - 重复回报（同一状态反复推送，例如多次 Submitted / Filled）在调用 transition() 前去重，记录后忽略，不得升级为 HALT。
  - 终态后到达的成交必须入账并生成差异事件（加故障测试：Cancelled 之后到达 exec、Filled 之后到达最后一笔 exec）。
  - 查单结果“券商查无此单”：保持 UNKNOWN 或进入 SAFE HALT，按 orderRef 多轮查证，**不得映射为 REJECTED 后重下**。
  - SUBMITTING / UNKNOWN 状态的开仓单不能直接撤：急停与 guardd 遇到时挂起，等 ACK 或查单后再撤，不得静默跳过。
  - UNKNOWN 期间收到成交：立即入账并触发查单；成交只是证据，状态仍须经 BROKER_STATUS_OBSERVED 转出。
  - 离开 SUBMITTING 时取消提交超时定时器；迟到的 SUBMIT_TIMEOUT 记录后忽略，不升级为 HALT。以上两条加故障测试。
  - permId 从 openOrder、orderStatus、execDetails 任一路先到的取得即落库（写字段，不是状态转移，终态下也允许）；
    “orderId 在 placeOrder 之前持久化”是 SUBMITTING 成交格的安全前提，必须有测试；
    无法关联到任何已持久化订单的成交，入账为未匹配成交并生成差异事件，不得丢弃。
- **B-03 / B-05**：IBKR 状态映射——Inactive、被拒单以 Cancelled 报出（错误码 201）、DAY 单到期以 Cancelled 报出、
  保护性止损长期停在 PreSubmitted（映射为 BROKER_ACK）、撤单因“已成交”被拒时改发 FULL_FILL。
- **B 组 / 回测**：时间检查是严格小于；SimBroker 必须定好时间粒度（下单与成交至少相差一个时间单位），
  不得为通过检查人为加偏移。
- 断线时 SUBMITTED / CANCEL_PENDING 保持原状态，由重连对账（R-07）修正；只有 SUBMITTING 超时进入 UNKNOWN。
