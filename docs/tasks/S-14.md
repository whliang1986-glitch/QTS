## 一、三层定义（Dylan 2026-11-04 确认）

所有交易都在风控之下完成。三层各管各的，下一层绝不会因为上一层而自动打开：

1. **自选**：关注与候选。加入自选不会下单，也不会让它变得可以交易。
2. **建议**：策略与情报分析（T-11、A-14）对标的给出建议，只是提议。
3. **下单**：只有在**交易名单**里、并且通过风控全部限额逐笔校验的意图，才会交给 OMS 下单。

情报分析命中的标的，如果不在交易名单里，只给提示和建议，不下单。

## 二、自选

- **增删、分组、标签、备注**：通过 apid 命令操作，只有 owner 令牌能改，每一步都写审计。数据存 api.db 的新表，走结构迁移，只追加。
- **列表显示**：
  - 代码、名称、所属行业或 ETF；
  - 最新价与涨跌，并注明行情是实时、延迟还是不可用。延迟行情不能当实时显示；
  - 是否持仓、仓位占净值的比例；
  - 状态：仅自选 / 待确认 / 已在交易名单；
  - 风控是否允许交易（交易名单状态加资格检查结果）；
  - 最近的情报数量（A-11 接入后）。
- **订阅上限**：自选会用掉行情订阅额度（IBKR 同时订阅的数量有限）。自选数量设上限，超出部分不订阅实时行情，并标明“未订阅”。

## 三、交易名单与“加入交易名单”按钮

### 存放与机制（按 ADR-16）

- 交易名单存在**账本**里，用只追加的变更记录推出当前名单，走 ADR-16 的运行时变更。
- 受保护配置 `config/risk/` 里只放**硬上限**和**资格规则**，只能由 Dylan 本人提交。
- **加入属于“调松”**：先生成待确认变更；Dylan 用独立的确认短语二次确认后才生效；变更记录写明谁、何时、哪只、原因。
- **移出属于“调严”**：立即生效，同样留记录。
- **只有 owner 能操作**，操作者取自令牌身份。AI 和策略都没有这个入口（arch_scan 按 ADR-16 第 3 条强制）。
- 自选页的按钮只是 ADR-16 变更的一个入口。放宽交易名单不能通过自选页绕过二次确认。

### 资格检查（加入前先查，结果直接显示）

不合格时按钮变灰，并逐项写明原因。建议值见第五节，最终以 Dylan 在受保护配置里确认的为准：

- 只限美股 ETF 现货（个股要等 T-11 和 S-15 验证后，再由 Dylan 放宽）；
- 券商可以交易，合约规格完整（default_deny 的现有检查）；
- 不是杠杆、反向 ETF，也不是衍生品；
- 流动性：近 60 个交易日的日均成交额不低于门槛；
- 价差：买卖价差的中位数不高于门槛；
- 上市满 1 年（回测和波动率估计需要足够的历史）；
- 名单总数不超过硬上限。

### 界面状态

每只标的显示：仅自选 / 待确认（等 Dylan 二次确认）/ 已在交易名单。
待确认的变更可以撤回；确认之前，风控仍然按“不在名单”处理。

## 四、验收标准

- [ ] 自选增删改走 apid 命令，只有 owner 能做，写审计；viewer 只能看
- [ ] 加入自选后，风控对该标的的判断不变（测试：自选里的标的、不在交易名单的，意图被拒）
- [ ] 加入交易名单生成待确认变更；没有确认短语不生效；确认后写只追加记录
- [ ] 移出交易名单立即生效并写记录；之后该标的的新开仓意图被拒，减仓与保护性止损照常
- [ ] 资格检查不合格时按钮不可用，并显示原因；服务端同样校验（不能只靠界面）
- [ ] 名单总数达到硬上限后，不能再加入
- [ ] 策略、AI 路径没有调用交易名单变更的入口（arch_scan 与测试）
- [ ] 延迟或不可用的行情明确标注
