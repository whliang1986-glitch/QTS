## 目标

把交易核心需要的数据来源接成 `CoreInputs`，并用真实的 tradingd 入口跑通一遍：
意图 → 风控 → OMS → 券商 → 成交回到账本。这里的券商是 FakeBroker，**不连 TWS，不下真单，不是 IBKR 联调**。

## 改动

`server/app/wiring.py`（新增）

- `Feeds`：数据来源。运行模式、标的、组件、风控参数、行情必须显式提供；账户同步、时钟偏差、日初净值、
  策略回撤、止损冷却默认返回 `None`；公司行动默认在取数时报错。这里没有“默认通过”的值。
- `core_inputs`：组装 `CoreInputs`。
- `health_reporter`：券商组件固定看 `broker.connected`；其他组件看注入的检查。
  只有检查明确返回 `True` 才算健康，出错或返回其他值都算故障；没有检查的组件不上报，按“从未报告”算故障。
  检查了未登记的组件时报错。
- 组件清单缺关键组件时，`core_inputs` 报错，tradingd 拒绝启动。

`server/app/__main__.py`

- 新增 `TimeWiring.wire`：`broker_window`、`session_day` 与调度器来自同一份日历和窗口。
- `TimeWiring.inputs` 和 `production_broker` **没有改**，生产入口继续拒绝启动。

## 不做的事

- 不改风控入口和订单执行行为，也不改 `config/risk`、架构扫描和 import-linter 契约。
- 生产代码不依赖 FakeBroker（契约 `fake-broker-test-only`），只有测试注入它。
- 不接入 `IbkrPaperAdapter`、`IbkrQuoteSource`：生产入口接入真实券商须 Dylan 批准，并且先要解决下面的残留风险。

## 残留风险（接入 IBKR 前必须处理）

| 问题 | 影响 |
|---|---|
| `ConnectionSupervisor._try_connect` 写死 `readonly=True` | 这只影响走监督器的路径，适配器自己按策略连接。ib_async 的代码显示，只读连接同时跳过未结订单和已完成订单的同步，主要影响重连或重启后的旧订单（与 TWS 的实际行为未实测）；模拟盘下单要走非只读连接。监督器重连也不会恢复适配器的账户 |
| 监督器还没有接入，`broker.connected` 为 True 不等于券商可交易 | `server/` 里没有地方构造 `ConnectionSupervisor`，tradingd 直接调用 `broker.connect()`。收到 1100（API 还连着，TWS 与 IB 服务器已断开）时，适配器只转成 `BrokerError`，OMS 只记一条警告；`connected`、健康和心跳都正常，意图继续走风控，可能发给券商，guardd 也不会介入。接入时要：在 tradingd 构造监督器；把 1100、1101、1102 转给 `note_broker_error`；券商健康看连接和 1100 状态（`state` 为 `CONNECTED`），不含对账条件；“本次连接之后已对账”单独作为新单门禁接 `trading_allowed()`，对账成功后调用 `mark_reconciled`（目前没有调用方）。**健康和心跳不能直接用 `trading_allowed()`**：启动时上报在对账之前，每次重启都会 SAFE HALT；心跳因此失败时 tradingd 崩溃重启，命令端点关闭，人工恢复走不通；只跳过心跳，guardd 又会在等人工处理时撤开仓单。`BROKER_DOWN` 期间心跳是否继续、guardd 是否介入，接入时明确决定并测试。代价：这样接入后，任何一次 1100 都让关键组件故障，写入持久化 SAFE HALT，短暂断线也要人工恢复 |
| 账户同步、时钟偏差、日初净值、策略回撤、止损冷却、公司行动都还没有真实实现 | 默认全部“不知道”。前五项未知时新增风险被拒；账户同步或时钟未知时减仓单和紧急平仓也被拒。没有进入 SAFE HALT 时，只有保护性止损能过 `data_gate`。**SAFE HALT 下保护性止损和紧急平仓都过不了风控**（运行状态门和模式门都拒绝），须人工恢复；有持仓时不能以为止损还能下。要逐项实现 |
| 公司行动来源缺失 | 持仓差异单独出现的那一轮，取数报错，立刻 SAFE HALT；差异本身仍标 PENDING，但 `source_unavailable` 不走盘中时序容忍。同一轮已有其他差异时不取数，容忍照常。这是 fail closed，但接入后可能频繁需要人工恢复。盘中这条路径由 `test_reconcile.py` 覆盖，本任务的用例走的是 STARTUP 对账 |
| 行情、账户同步等组件还没有真实的健康检查 | 没有检查就不上报，运行状态机按故障处理 |
| `news`、`model` 在组件清单里，但 M3 才有 | 缺 `news` 的检查：它是 DATA 类，`data_ok` 恒为 False，SAFE HALT 恢复不了。缺 `model` 的检查：可以恢复，但一直 DEGRADED，`degraded_allowed` 默认为空，所有策略的新单被拒。接入 M1 时要二选一：从组件清单移除这两项；或者都保留，同时修改恢复门槛（解决 `news` 的恢复）并为策略登记 `degraded_allowed`（解决两者造成的 DEGRADED），须评审。只改门槛不够。**不得用常量 `True` 充当健康检查**，那就是“默认通过” |
| 同一事实有两个来源 | `checks["account_sync"]` 与 `Feeds.account_synced` 相互独立，可能一个报健康、另一个是 `None`。结果 fail closed，但接入时应从同一来源取值 |
| `health_reporter` 校验的清单可能不是运行状态机用的那份 | 它校验传入的 `components`，运行状态机用 `Feeds.components`。不一致时上报报错，tradingd 崩溃重启。接入时两边传同一个对象 |
| 关键组件校验只在 `core_inputs` | `build_trading_core` 和 `RunStateMachine` 都接受空清单，直接构造 `CoreInputs` 能绕过，这时健康门禁等于没有。生产入口没有这条路径。后续任务 B-05x（已登记在 `docs/tasks/README.md`）：把校验下沉到风控层（本任务不改风控入口） |
| `_run` 还没有传 `report_health` | 默认空操作，全部组件“从未报告”，启动即 SAFE HALT；接入时要传 `health_reporter`，并把它构造时的 `ValueError` 转成拒绝启动（78），否则守护进程会反复重启 |
| `mode_config`、`instruments`、`parameters` 没有真实加载 | 接入时补；风控参数涉及 `config/risk`，须 Dylan 批准 |
| 健康上报挂在心跳循环上 | 上报在端点自检之后，实际间隔可达 `heartbeat_seconds` 加 10 秒。这个间隔达到关键组件的 `stale_after`（30 秒）就会触发持久化 SAFE HALT，比如配成 25 秒。默认 15 秒没有问题；启动时还没有校验。另外，启动时上报之后 `core.start()` 还要查单和对账，结束时立刻评估，真实 IBKR 下超过 30 秒就会每次重启都 SAFE HALT；同步的健康检查、事件循环阻塞、机器休眠也会造成报告过期。本任务的用例用固定时钟，没有走到报告过期这条路径 |
| 端到端用例没有接调度器和 guardd | 这两部分由各自的测试覆盖，没有一起跑过 |
| 本任务的结果来自 FakeBroker | 不能作为 IBKR 联调证据，B-04、B-05 的联调项仍未验证 |

## 测试

`tests/integration/app/test_wiring.py`

- 端到端：恢复之前 SAFE HALT、单子到不了券商；人工采用基准、对账、恢复后，同一类意图放行并到达 FakeBroker；
  同一 `intent_id` 重投不多下一张单；成交的数量和价格回到账本。
- 五个“不知道”的来源逐个留成默认，其他都可用：先确认恢复成功，再确认意图被这一项对应的规则拦下，券商没有订单。
- 账户同步或时钟未知时，减仓单同样被拒。
- 公司行动来源缺失：持仓一致时可以恢复；拆股对不上时对账报告记下来源不可用，意图被拒、恢复失败。
  对照用例：同样的拆股，来源正常时能解释。
- 行情取数失败：恢复成功后意图被 `data_gate` 拦下，券商没有订单。
- 关键组件没有健康检查：恢复失败，意图被拒。`news` 没有检查：恢复同样失败。`model` 没有检查：可以恢复，但新单被拒。组件清单为空：tradingd 拒绝启动；关键组件缺失或被标成非关键：组装时报错。
- 健康上报：断线、读连接状态出错、检查出错、返回值不是 `True` 都算故障；不接受自定义券商检查和未登记的组件。
- 时间来源：`wire` 和调度器用的是同一份日历和窗口。
- 接口形状：`IbkrQuoteSource` 符合 `QuoteSource`（mypy 检查，不连接）。
- 生产入口：券商和数据来源两个入口都继续拒绝启动。
