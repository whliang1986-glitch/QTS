## 安全评审

safety-reviewer 第一轮 REQUEST CHANGES，两个 P1，都已修复：
1. 许可证判定先判 LGPL，“GPL OR LGPL”这类混合许可会被放行；
2. Python 包的 License 字段只看第一行，而且认不出的许可也放行。

修法是三步判定：
1. 在许可全文里找强传染许可，去掉 LGPL 字样后再找 GPL；
2. 再找 LGPL，判为需确认；
3. 最后过白名单，认不出的一律禁止。

需确认和禁止都会让检查失败，人工登记过的除外。同时加强了字体检查，WebSocket 路由改为从应用里读取。
第二轮 **APPROVE**。第二轮的 P2 建议也一并处理了：去掉“OSI Approved”、嵌套组合表达式要求人工登记、拦截 GPLv3 这类缩写、字体地址后缀与文件后缀共用一份。

剩余项，不阻断合并：
- vulture 按名字忽略的范围偏宽，以后尽量改成精确到具体对象；
- 工作流里的 Action 改成按提交 SHA 固定；
- CI 检查 THIRD_PARTY.md 是否过期（Windows 与 Linux 的包集合不同，需要按平台过滤）。
