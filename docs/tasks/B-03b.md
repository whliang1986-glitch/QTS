## 目标

把 ib_async 接到 B-03a 的窄接口上，实现 BrokerAdapter 的只读部分。联调时只需要接上 TWS，逐条核对字段与映射。

## 做了什么

- **依赖**：`ib-async>=2.0,<3`（锁定 2.1.0）。附带 `aeventkit`、`nest_asyncio`。
  - 许可：两者的 PyPI 分类都误标为 Other/Proprietary，随包附带的 LICENSE 全文都是 BSD-2-Clause。
    已人工核对，登记在 `scripts/check_licenses.py` 的 REVIEWED 里。
  - **tzdata**：ib-async 声明 `tzdata<2026`，会把时区数据退回 2025 年版。ib-async 只通过 zoneinfo 读时区数据，
    新版数据向后兼容，所以在 `[tool.uv] override-dependencies` 里覆盖它的上限，保持最新（2026.6）。
    新增美东夏令时切换的固定日期测试。ib-async 放宽声明后删掉这项覆盖。
  - 不调用 `ib_async.util.patchAsyncio` / `startLoop`（它们用 nest_asyncio 改动事件循环）。测试确认导入 ib_async 后事件循环没有被改动。
  - pip-audit：无已知漏洞。
- **`server/broker/ibkr/client.py`**：`IbAsyncClient`，实现 B-03a 的 `IbClient`（连接、断开、是否连接、管理的账户、账户摘要）。连接时 readonly 固定为 True。
- **`server/broker/ibkr/convert.py`**：ib_async 对象到统一类型的纯函数。
  - 数值：float 先转字符串再转 Decimal，不带二进制误差。UNSET_DOUBLE（约 1.8e308）、NaN、Infinity 一律拒绝；可为空的价格返回 None。
  - 现金：已结算 = SettledCash，未结算 = TotalCashValue − SettledCash，缺任何一项都拒绝（ADR-15）。
    两个标签各自必须恰好有一条 USD 取值；为负或已结算大于总现金都拒绝。
  - 订单：带条件或可调整止损的订单归为 OTHER（撤单需要确认）。不是本连接下的单（含 TWS 手工单）
    一律用 `perm-<permId>` 作订单号，permId 也没有就拒绝。
  - 订单还没被券商完整确认（状态为空或中间状态，或挂单的成交量加剩余量对不上订单总数）时抛
    `PendingOrderError`：快照失败、稍后重查；事件路径不产生事件，等后续的状态回报。
  - 成交：佣金回报到来前的空占位当作“还不知道”，不记成 0；佣金币种为空或不是 USD 都拒绝。
  - 非股票、ETF 的品种照样上报，代码后标出品种，交给对账当作差异。
- **`server/broker/ibkr/adapter.py`**：`IbkrReadOnlyAdapter(BrokerAdapter)`。
  - 连接：先 `check_policy`，再只读连接，再 `verify_account`；任何一步失败都断开并上抛。
  - 快照：持仓与成交只取登记账户的；挂单用 reqAllOpenOrders（含 TWS 手工单与别的 clientId 的单），已完成订单 `apiOnly=False`。出现别的账户的订单时抛出，不静默丢弃。
  - 按 orderRef 查单：挂单、已完成订单与成交合并。
  - 下单、改单、撤单、分配订单号：B-05 之前一律 `BrokerUnavailableError`。
  - 回报事件：订单状态、成交、佣金、错误（信息类代码不上报）、断线。转换失败上报 `MAPPING` 错误，不吞掉。
    事件队列满时记 ERROR（需要重新对账），不阻塞 ib_async 的回调。

## 评审修复（safety-reviewer 第一轮 REQUEST CHANGES，没有 P0）

| P1 | 修法 |
|---|---|
| 已完成订单的成交量很可能是 0（ib_async 的 completedOrder 只给状态） | 已完成订单改用 `order.filledQuantity`，剩余量 = 订单数量 − 成交量；测试用 ib_async 真实的形态 |
| 已结算现金大于总现金时会放行 | 为负、已结算大于总现金一律拒绝 |
| 账户摘要不同币种混在一起 | 现金两个标签各自必须恰好有一条 USD 取值，否则拒绝；非金额标签取值冲突也拒绝 |
| 事件不过滤账户，重连握手阶段的事件会进队列 | 核验之后才订阅、断开时退订；事件逐条核对账户，不一致或未核验就上报不可信，并让适配器回到未核验状态 |
| 别的账户的持仓和成交被静默丢弃 | 与订单一样抛出 |
| 跨 clientId 订单号撞号、`perm-0` | 不是本连接的单一律用 `perm-<permId>`；permId 也没有就拒绝 |
| 平均成本精度超限会让持仓快照失败 | 平均成本是参考值，按 10 位取整；成交价、数量、佣金仍然严格 |
| 底层客户端自己不校验端口 | `IbAsyncClient.connect` 也只连本机、模拟盘端口、只读、clientId 为正 |
| 文档夸大了“只读” | 写明 ib_async 的 readonly 不能在 TWS 侧禁止下单；真正的只读靠 TWS 的 Read-Only API 设置，联调实测 |

P2 已处理：
- 回调全部包了异常处理；
- 只有订单相关错误码的 reqId 才当订单号；
- 错误消息经 `mask_text` 脱敏；
- 事件队列满时回到未核验状态；
- 追踪止损的价格为空；
- 品种不明的合约拒绝，期权等带合约编号；
- 佣金回报核对成交编号与币种；
- 中间状态的订单让快照失败，不静默漏掉；
- 账户核验失败后停机，不再重连；
- 自己断开只发一条 DISCONNECTED。

## 联调时必须核对（核对前不得据此下单；B-05 之前本来就只读）

评审新增的三条，最先核对：
- **TWS 已勾选 Read-Only API**，并实测一次下单请求被 TWS 拒绝（不经过本适配器）；
- 已完成订单的成交量是否在 `order.filledQuantity`；挂单快照里 orderStatus 是否可能还没到（现在按“还没确认”让快照失败）；
- 撤单的 Cancelled 报文里剩余量是“未成交部分”还是 0（是 0 的话现在会上报不可信，要放宽为按成交量判断）；
- 账户摘要是否为订阅缓存、多久刷新一次（现金的 `as_of` 现在记读取时刻）。

原有的七条：

1. 账户摘要的字段：`AccountType` 能否区分 CASH / MARGIN（B-03a 已知多半是 INDIVIDUAL，现在按“无法确定”拒绝），`SettledCash`、`TotalCashValue` 的含义与币种。
2. `reqPositionsAsync`、`reqAllOpenOrdersAsync`、`reqCompletedOrdersAsync(apiOnly=False)`、`reqExecutionsAsync` 的返回内容，以及 TWS 手工单的 orderId 是否为 0。
3. 订单状态映射（B-03a 清单）：`Inactive`、DAY 单到期的报法、错误码 202 的语义。
4. 断线时 `disconnectedEvent` 的触发时机；`disconnect` 幂等（半连上、握手超时后能释放 clientId）。
5. 佣金回报的时机与空占位的形态。
6. guardd 跨 clientId 撤单（B-02 待实测清单第 1 条）。
7. 1100 / 1101 / 1102 要接到 `ConnectionSupervisor.note_broker_error`；接入装配层时做。
