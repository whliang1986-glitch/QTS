## 目标

V4.1 7.2：做空、杠杆、衍生品、市价单默认禁用，无专项规则即禁止；保护性止损单只在方向、数量、类型、来源全部合规时放行。

## 设计

- 第一道防线在领域层（C-01 已有，本任务未改）：OrderType 只有 LIMIT / STOP，AssetClass 只有 STK / ETF，开仓只能买、减仓只能卖、
  止损单只能是保护性止损且只能卖出；跳过校验的构造方式（model_construct、model_copy(update=...)）被禁止。
- 第二道防线 `server/risk/default_deny.py` 的 `DefaultDenyRule`（无专项规则即禁止）：按评估时的券商事实检查；
  所需上下文缺失一律拒绝，不当成 0。拒绝原因是模块常量，测试按完整文本断言。
  - 只放行三种（类别, 方向, 类型）：开仓买入限价、减仓卖出限价、保护性止损卖出止损；其余一律拒绝；
  - 标的有规格且与意图一致、可交易（require_tradable）、STK / ETF、乘数 1；
  - 持仓与现金必须属于意图账户；任一持仓为负即拒绝（待对账）；
  - **不加杠杆**（杠杆固定 1.0，不是参数）：本单名义 + 其他未结束买单名义 ≤ 可用现金
    = 已结算 + min(未结算, 0)（未结算的买入应付款先扣，同一笔钱不用两次）；已挂买单缺限价即拒绝；
  - **不做空**：减仓卖出 + 其他未结束减仓卖单 ≤ 持仓；没有正持仓即拒绝；保护性止损不占减仓额度；
  - 改单时自己那张旧单不计入占用（新内容替代旧内容）。
- 保护性止损专项检查内嵌在 DefaultDenyRule 中（不依赖 RuleSet 是否漏装另一条规则），满足全部条件才放行：
  来源 `strategy_id == PROTECTIVE_STOP_SOURCE`；止损参数已批准；持仓、未结束订单、最新价可用；持仓为正；每个持仓标的
  至多一张；**数量必须等于持仓**（防止小止损单占位挤掉真正的止损，也与“不缩量”一致）；成本价 ×（1 − 批准距离）
  ≤ 止损价 < 成本价；止损价在最小跳动上；**止损价低于最新价**（否则提交即触发，等于市价卖出）。
  止损距离是 Dylan 批准的参数（附录 A 草案 10%），由 R-02 从受保护配置加载；参数缺失即拒绝全部保护性止损。
- 引擎（R-01 移交）：保护性止损不缩量——REDUCE 改判 REJECT，追加命中 `protective_stop_not_reducible` 并记 ERROR 日志。
- `RiskContext` 扩展：持仓、未结束订单（`OpenOrder`：已签发、尚未确认终态的全部订单，含 SUBMITTING / UNKNOWN 与撤单中）、
  现金（未结算为负表示买入应付款）、标的规格、最新价；提供者在 R-03 / S-01 接入。
- arch_scan 只收紧：新增 `protective-source`（PROTECTIVE_STOP_SOURCE 及其字面量只能在 domain、oms、risk）与
  `protective-class`（OrderClass.PROTECTIVE_STOP 只能在 domain、oms、risk、guard、backtest）。

## 允许修改范围

- `server/risk/default_deny.py`（新建）、`server/risk/engine.py`（上下文字段、保护性止损不缩量）、

## 移交

以下标 **G3 前置** 的必须在 G3 之前完成：

- **S-01（G3 前置）**：IPC 入口拒绝策略提交 `order_class=PROTECTIVE_STOP` 或 `strategy_id == PROTECTIVE_STOP_SOURCE` 的意图；
  保护性止损走只能由 OMS / 持仓事件触发的专用入口（字符串来源只是第二层）。评估与签发按账户串行化，避免两次并发评估
  互相看不到对方而超买超卖。
- **R-03（G3 前置）**：上下文提供者：持仓、现金（明确 settled 是否已扣当日买入应付款，与本任务口径一致）、
  未结束订单（已签发未终态的全部订单，含 UNKNOWN；券商侧有本系统不认识的订单即拒绝）、标的规格、最新价；
  持仓、现金、行情的 as_of 新鲜度门禁。
- **R-06（G3 前置）**：OMS 随持仓创建保护性止损，止损数量随持仓同步；止损与减仓同时成交的超卖窗口——下减仓单前先撤旧止损
  重建，或止损与减仓进同一 OCA 组，或止损占用减仓额度（模拟账户可能是保证金账户，IBKR 不一定拒绝超卖）；
  持仓已跌破止损线时如何处理由 Dylan 定。止损价在盈利区（锁定利润）首期不允许，Dylan 定规则后再开放。
- **R-02**：从受保护配置加载 `ProtectiveStopParams` 与 ADR-16 运行时调整；组装 RuleSet。阈值类规则（单笔上限、敞口、
  未成交订单数）必须豁免保护性止损（附录 A：未成交订单数不含止损），否则缩量会被改判拒绝、持仓失去保护。
- **R-05**：HALT 下是否放行保护性止损与减仓单（降低风险的动作）。
- **R-05 / R-07**：任一标的出现负持仓即拒绝全部订单（失败即关闭），其他正常持仓的止损与减仓也挂不上；
  定这种状态下其他持仓靠什么保护，是否只对该标的拒绝。
- **R-06**：最新价已跌破“成本价 ×（1 − 距离）”时不存在合规止损价，持仓无保护——必须发 P0 告警（保护性止损缺失），
  不能只静默拒绝；处理方式由 Dylan 定。碎股持仓（券商侧出现）无法满足“止损数量等于持仓”，同样告警（B-05 核实）。
- **R-03**：上下文提供者只返回意图所属账户的未结束订单（OpenOrder 没有 account_id），写进验收条件。
- **S-04 / R-06**：arch_scan 的 `protective-class` 目前不允许 api、broker、storage 引用 `OrderClass.PROTECTIVE_STOP`；
  展示“保护性止损覆盖情况”时改用只读视图字段，或在当时提交放宽申请由 Dylan 批准（放宽 arch_scan 须 Dylan 本人同意）。
