## 目标

在 `server/domain/` 建立无 I/O 的领域模型：Decimal 与 UTC 强制、序列化稳定、规格缺失即拒绝、订单类别创建后不可改。

## 非目标

不做订单状态转移（C-02）、持久化（C-03）、模式切换逻辑（C-04）、风控规则（R 组）、数据质量判定（D-05）。
Experiment / ModelRun / EvidenceRecord 等 M2、M3 对象留到对应任务。

## 允许修改范围

`server/domain/`、`tests/unit/domain/`、`tests/property/`、`scripts/arch_scan.py`（新增 domain 无 I/O 规则）及其测试、
`pyproject.toml` / `uv.lock`（pydantic 依赖）。

## 接口与不变量

- 价格、数量、金额是 Decimal：拒绝 float 与 bool、NaN / sNaN / Infinity；字符串只接受规范写法
  （拒绝空格、下划线、前导 +）；最多 10 位小数、15 位整数。从 JSON 读入必须是字符串或整数。
- 订单与成交数量是正整数（首期整股，ShareQuantity）；持仓数量是带符号数量（SignedQuantity，记录券商事实）。
- 时间必须带时区（utcoffset 不得为 None），统一换算为 UTC，并重建为纯 datetime（不让子类流入）。
- 币种首期只允许 USD；资产类别只允许 STK、ETF。
- 订单类型只有 LIMIT 与 STOP（没有 MARKET）；STOP 只能用于保护性止损，且只能 SELL。
- 首期仅多头：OPEN 只能 BUY，REDUCE 只能 SELL（放开做空需另行批准）。
- LIMIT 必须有限价；STOP 必须有止损价；GTD 必须有到期时间，且晚于创建时间；只有保护性止损可以 GTC。
- RiskDecision：只有 REDUCE 带缩减数量；REDUCE、REJECT、HALT 都必须说明命中的规则。
- 所有模型 frozen、未知字段拒绝。绕过校验的入口全部关闭：`model_construct`、`copy()`、`model_copy(update=...)`
  抛 TypeError；已有实例传入时一律重新校验（`revalidate_instances="always"`）。
- 修改只能走 `evolve()`，由类变量 `evolvable_fields` 白名单控制：OrderIntent、RiskDecision、RuleHit、Execution
  完全不可修改（同一幂等键只对应一份内容）；BrokerOrder 只能补录一次 perm_id；Account 的 account_id 不可改。
- Instrument 缺 tick_size 或交易日历时，`require_tradable()` 抛 `InstrumentSpecMissingError`；exchange 是必填字段，
  缺失在构造时即被拒绝。
- domain 只能导入白名单内的纯计算模块，不得使用 open / print / exec 等内置，不得读取系统时钟
  （arch_scan 规则 domain-io、domain-clock）。

## 剩余风险与后续登记

- B-01：IBKR 返回的价格（如 avgCost 为 float）入域前必须先按规则量化为不超过 10 位小数的 Decimal，否则会被拒收。
- C-03：存储层对 perm_id 再加一道“只能补录一次 + 唯一”约束（BrokerOrder.evolve 的检查可被显式 super() 调用绕过）。
- arch_scan：`__setattr__` / `__delattr__` 在 oms 以外全局禁止，storage 或 api 若确需使用要登记 DYNAMIC_EXEMPTIONS
  并经 Dylan 批准；domain 中修改 decimal 全局上下文（getcontext）暂未禁止，留待需要时收紧。
