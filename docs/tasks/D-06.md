## 目标

行情、公司行动、特征快照、回测明细按 V4.1 5.2 的目录落盘为 Parquet；原始层与标准化层不可变、按版本保留；
manifest 记录来源与内容哈希；DuckDB 按绑定的版本读取；保留任务按 5.4 的默认保留期清理可删除的数据。

## 非目标

- 不实现数据供应商适配器、DataJob 回补与质量门禁（D-01、D-02、D-05）。
- 不做行情湖备份（5.5：默认不备份，保留 manifest）。

## 允许修改范围

- 可以改：`server/data/lake.py`（新建）、`tests/unit/data/test_lake.py`、`pyproject.toml` / `uv.lock`
  （pyarrow、duckdb，开发依赖 pyarrow-stubs）、本任务单。
- 不得改：受保护路径、其他任务的公共接口。

## 接口与不变量

- 目录：`raw/<dataset>/date=YYYY-MM-DD/v=NNN/`、`normalized/<dataset>/date=…/v=NNN/`、`features/<id>/`、
  `backtests/<策略>/<版本>/<实验>/`、`quotes/date=…/`，每个目录含 `data.parquet` 与 `manifest.json`。
- manifest 两个哈希：`content_sha256`（去掉元数据、合并分块后的 Arrow IPC 哈希，用于幂等）与 `sha256`（文件字节，防篡改）；
  manifest 必须与所在目录（层、数据集、分区、版本号、层级深度）一致。pyarrow 升级后先抽样确认同内容仍幂等。
- `write_partition`（raw / normalized）：逻辑内容与最新版本相同则幂等返回；不同则写 v+1，旧版本保留；
  先写临时目录再原子改名（目标已存在即失败，不覆盖），文件设为只读。数据集名、日期类型、时区严格校验。
- `write_bars`：MarketBar → 固定 schema（价格 decimal(18,6)、数量 decimal(24,4)、UTC 微秒时间戳），lineage 记录原始分区；
  每根 K 线的开始时间（UTC 日期）必须落在分区日期内，(symbol, start) 唯一；normalized 下 bars_* 数据集强制该 schema。
  注意：将来 bars_1m 的盘后数据（美东 20:00 = UTC 次日 0 点）按 UTC 日期归属。
- `snapshot(dataset, start, end)` 返回每日最新版本号；`read_bars(..., versions=)` 按绑定版本读取，没有分区、没有版本或没有该版本即报错；
  只读 bars_ 数据集；一次读入字节、校验哈希与 schema 后再解析（失败即关闭）；读出只接受 Decimal（保留列 scale）与 UTC datetime。
- `write_snapshot`（features / backtests / quotes）：不可覆盖；快照 id 只能小写、不以点结尾、不用 Windows 保留名；quotes 段必须是真实日期。
- `plan_retention` 只预演：特征快照 90 天（与决策关联的永久）、报价快照 30 天、回测每策略保留最近 10 个版本 + 已发布版本；
  raw、normalized 永不进入计划。保护集合（keep_features、published_backtests）是必填参数。
  `apply_retention` 只删 features/<id>、quotes/<date>、backtests/<策略>/<版本> 这一层，再次排除保护集合，
  目标不得解析到 raw / normalized 之下；有一条不合规即整批拒绝。

## 验收标准

- [x] 原始层不可变：同内容幂等、新内容新版本、已存在的版本目录不会被覆盖、文件只读、篡改可检出
- [x] 标准化 K 线 Decimal / UTC 往返一致；按绑定版本读取可复现；缺失版本失败即关闭
- [x] 保留任务可运行：按策略生成计划并执行，越界路径整批拒绝
- [x] ruff、mypy、全部测试、lint-imports、arch_scan 通过
- [x] safety-reviewer 评审：第一轮 REQUEST CHANGES（1–7 含两处失败时放行），修改后第二轮 APPROVE；
      第二轮建议 1–4（合并分块、读回异常统一、只读 bars_、manifest 层级）已改，5 的 Linux 目录锁由 CI 验证

## 移交

- **D-01 / D-02**：供应商数据先 `write_partition("raw", …)`，标准化后 `write_bars(…, lineage=[raw.key])`；DataJob 幂等重跑依赖同内容幂等。
- **T-04**：实验记录 `snapshot()` 的结果，回测用 `read_bars(versions=…)`。
- **R-07 / 运维**：保留任务每日运行一次，先记录计划再执行；`keep_features` 由账本中与决策关联的快照 id 提供。
