## 目标

V4.1 附录 A 的阈值“由你批准并版本化，AI 无权修改”，按 ADR-16（Dylan 2026-10-24 确认）开放受控的运行时调整：
受保护配置定启动值与硬性上下限；面板只在范围内调；调严立即生效，调松须 Dylan 二次确认；重启以保存值为准。
本任务只做后端，不定任何数值；R-02 的阈值规则在 R-02b。

## 设计

- `server/risk/parameters.py`
  - `SPECS`：16 个进入面板的阈值，每个写明名称、单位、类型（比例 (0, 1] 或正整数）、哪个方向更松、层级、说明——**没有数值**。
  - `parse_parameters`：从 `[parameters.<name>]` 读取恰好 start / hard_min / hard_max 三项；缺参数、多参数、多余键、类型不对、
    hard_min ≤ start ≤ hard_max 不成立 → ConfigError（加载失败，风控拒绝一切新增风险）。浮点按 Decimal 解析（C-05）。
  - `ParameterStore`：生效值 = 启动值 + 按顺序重放的已生效调整；保存值超出新配置上下限时取更严一端并告警。
    - `tighten`：必须严格更严、在上下限内、写明操作者与原因；立即生效。
    - `request_loosen`：必须严格更松、在上下限内；只记待确认请求，返回逐字确认短语。
    - `confirm_loosen`：短语一致、请求仍待确认、当前值仍等于请求时的旧值、仍在上下限内才生效。`cancel_loosen` 取消。
    - 变更记录写在只追加的审计表（action = risk_param_change：时间、操作者、类别、旧值、新值、原因、配置哈希）；无新迁移。
- `server/risk/rulesets.py`：`build_rule_set(params)` 按当前参数组装规则集（目前为 R-04 的 DefaultDenyRule，止损距离来自参数），
  版本 = 参数版本；`rule_source(store)` 交给 RiskEngine，每次评估现取（调严立即生效）；没有参数 → None → 全部拒绝。
- `server/risk/engine.py`：`rule_set` 可以是固定规则集或可调用的来源；来源抛异常按规则集缺失处理（失败即关闭）；
  引擎内置检查的决定版本记为 `engine`。
- `scripts/arch_scan.py` 只收紧：新增 `risk-param-write`（变更记录动作名、类别、写入方法只能在 risk/parameters.py）与 `risk-param-loosen`（request_loosen / confirm_loosen 只能在 risk/parameters.py 与 server/api），
  AI、策略、risk 其他模块没有调松入口。
- `docs/runbooks/risk-parameters.template.toml`：参数清单模板，start 为附录 A 草案值（待批准），**上下限故意留空**，不填完无法加载；
  由 Dylan 审阅后自行复制到受保护配置目录并提交。开发方不写受保护配置。

## 验收标准

- [x] 参数定义齐全（名称、单位、类型、方向），代码中没有任何阈值数值
- [x] 配置缺失或不合法即加载失败，风控拒绝一切新增风险
- [x] 调严立即生效并记录；调松须二次确认（短语、待确认、值未变、上下限内）；可取消；不能重复确认
- [x] 重启以保存值为准；越界取更严一端
- [x] 规则集每次评估现取；来源异常拒绝
- [x] 调松入口 arch_scan 收紧并有正反用例
- [x] 模板与参数定义一致，且上下限未填时无法加载
- [x] 变异检查（2026-10-24，第二轮评审后重做）：注入 19 种缺陷，17 种检出（含重放不核验调松请求、补零按小数位算、
      并发重复确认）；2 种为等价变异（重放的配置版本核对、`is_finite`），保留作纵深防御
- [x] 防伪造的边界（如实说明）：**主控是写权限**——只有 tradingd 持有账本写权限（S-01）；import-linter 禁止 ai、strategy
      依赖 storage 与 risk（no-ledger-from-ai-strategy），也禁止依赖 api（no-api-from-ai-strategy）；arch_scan risk-param-write
      限定变更记录的动作名与写入方法。重放核验（请求的方向、上下限、规范短语、配置版本、旧值；确认与请求逐项一致）只是纵深防御，
      能挡住损坏与粗糙伪造，**挡不住构造严密的成对伪造**，也不能证明记录出自 parameters.py
- [x] 第三轮评审 N-1：重放过程中每一步都把值夹进当前上下限（与对外生效值同一口径），被夹回的参数仍可正常调松 / 调严；
      先写失败测试（上限类、下限类各一例）再修复
- [x] 配置文件换版后，已确认的调松一律作废（比 ADR-16 第 4 条“重启以保存值为准”更严的解读，已报 Dylan 确认）；
      调严的保存值只要比新启动值更严就继续有效
- [x] ruff、mypy、全部测试、lint-imports（6 kept）、arch_scan 通过（2026-10-24：1798 passed）
- [x] safety-reviewer 评审（第一轮 REQUEST CHANGES：I-1 伪造记录绕过二次确认、I-2 止损距离取 1、I-3 inf / nan，S-1–S-8；第二轮 REQUEST CHANGES：成对伪造仍可通过重放；第三轮 REQUEST CHANGES：N-1 夹值后无法调松；均已修改；第四轮 APPROVE）
