## 目标

调度一律由交易日历驱动：夏令时、提前收市、节假日都由日历决定，内部一律 UTC。

## 设计

- `server/data/calendar.py`：`TradingCalendar.nyse(start, end, adhoc_closures, adhoc_early_closes)`，底层 exchange_calendars
  4.x 的 XNYS 日历（第 2 批选型）；对外只暴露 UTC datetime 与 `Session(day, open, close, early_close)`，不泄漏 pandas 类型。
  只表示常规交易时段（不含盘前盘后）。
- 查询：`is_trading_day`、`session`、`is_open`（开盘时刻算开市，收盘时刻不算）、`next_session`、`sessions_between`。
- 临时休市 `adhoc_closures` 与临时提前收市 `adhoc_early_closes`：由受保护配置登记（C-05），优先于库的规则，只能减少交易时间
  （不支持临时开市或推后收盘）。
- 失败即关闭（抛 `CalendarDataError` / `CalendarRangeError` / `ValueError`）：登记类型不是 date、超出范围、登记在本就休市的日子、
  同一天同时登记两种覆盖、提前收市时间推后或早于开盘；库数据违反不变量（UTC、open < close、同一 UTC 日期、不重叠、在范围内）；
  查询超出范围；不带时区的时间。构造时做防御性拷贝。

## 剩余风险与移交

- 库对未来年份的节假日依赖规则推算；每年 NYSE 公布次年日程后，把次年已知日期补进测试（年度运维清单，S-11）。
- **升级 exchange_calendars 前**：先核对已登记的临时休市是否已被新版本收录，已收录的要从登记中删除，否则启动会因
  “本就不是交易日”而失败（失败即关闭方向；写入 S-11 运行手册）。
- pytest 只忽略一条 exchange_calendars 触发的 pandas 弃用警告（按模块过滤实测无效，警告归属 pandas 内部）；升级 pandas 前需复测。
- C-05：`adhoc_closures`、`adhoc_early_closes` 从受保护配置加载并版本化。
- T-01 / S-01：调度器只能通过本日历计算时点；数据门禁（D-05）用它判断“应有数据的交易日”。
- 盘中熔断、个股停牌不属于日历，由券商与数据状态判断（D-05 / R-03）。
