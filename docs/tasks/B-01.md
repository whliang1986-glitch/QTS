## 目标

所有券商调用隔离在统一的 `BrokerAdapter` 接口后面；一套契约测试可以对任一适配器运行
（现在跑 FakeBroker，B-05 原样跑 IBKR 模拟盘），用来发现模拟与真实券商的行为差异。

## 非目标

不实现 IBKR 适配器（B-03 / B-05）；不实现故障注入与撮合内核（B-02）；不实现 OMS（O 组）。
为了让契约套件有可运行的对象，本任务附带一个最小 FakeBroker（立即接单、由测试驱动成交），B-02 在其上扩展。

## 设计

- `server/broker/base.py`：
  - `OrderTicket`：OMS 签发的订单票据 = 意图 + **风控决定对象** + **实际下单数量** + 已持久化的券商订单号 + 标的规格。
    构造时校验：标的规格完整且乘数为 1、标的与意图一致、价格在最小跳动上、决定属于本意图且结论为 ALLOW / REDUCE、
    ALLOW 时数量等于意图数量、REDUCE 时数量等于批准数量且不超过意图数量。
  - `OrderAmendment`：改单只能改价格与数量，附带针对新价格与数量的**新**风控决定（不得复用原票据的决定，
    新决定不得早于原决定）；类别、方向、标的、类型、有效期、账户在类型层面
    不可表达（C-01 的意图不可变保持成立）。
  - arch_scan 规则 `order-ticket`：只有 oms 能构造票据与改单；broker 包内票据类型名只能出现在类型标注、
    isinstance / issubclass 的第二个参数与导入中（`base.OrderTicket(...)`、别名、作为参数传出都被拒）。
  - 撤单逐单进行，没有全局撤单；撤保护性止损必须显式 `allow_protective_stop=True`（只有 LIMIT 可不经确认撤销，STOP 与认不出的类型 OTHER 一律需要确认），
    arch_scan 规则 `protective-cancel` 把这个参数限制在 oms 与 broker 实现里（guard 不能用，撤单调用也不得用 `**` 展开参数）。
    是否为止损单以**券商侧**订单类型判断（外来止损单没有票据）。
  - 券商侧事实与 domain 分开：`BrokerExecution`（orderRef、订单号可空，数量可为小数）与 `OrderRecord`
    （orderRef 可空，类型为 `BrokerOrderType` LIMIT / STOP / OTHER 并保留原始类型、价格可空、原始有效期）
    能表达 TWS 手工单、别的 clientId 与券商强平；OMS 匹配后再转成 domain 的 `Execution`。
  - `BrokerError.retryable` 只表示查询类请求可重试，从不授权重发订单。
  - 回报事件：`OrderStatusUpdate`（含 permId、原因、错误码）、`ExecutionReport`（含 permId）、`CommissionReport`、
    `BrokerError`（扩充的错误类别 + 是否可重试）、`ConnectionEvent`。
  - 查询：`open_orders`、`completed_orders`、`executions(since, until, order_ref)`（时间必须带时区）、
    `lookup_order(order_ref)` 返回全部匹配的订单与成交（空 = 暂未查到，不是“从未下过”）。
  - `OrderRecord` 带完整券商事实：账户、标的、方向、类型、价格、有效期、总量 / 已成交 / 剩余、状态、来源。
  - 适配器不得在内部重试下单，超时由 OMS 计时进入 UNKNOWN。
- 契约套件 `tests/contract/broker_contract.py`：随机 orderRef 前缀、只断言本用例的订单、收尾逐单撤掉本用例挂单、
  完整记录事件并断言先后顺序；部分成交、无持仓止损单等依赖精确撮合的用例由驱动器能力开关控制。
- 最小 FakeBroker：立即 ACK 并分配 permId；成交价不得劣于限价；撤单期间部分成交保持 CANCEL_PENDING；
  改单先校验再修改；时钟严格递增；运行级前缀避免重启后编号冲突；连接与断开发出连接事件。

## 契约（适配器必须满足）

1. 未连接时任何调用（含改单、已完成订单、查单）都抛 `BrokerUnavailableError`；连接发出 CONNECTED 事件。
2. 订单号唯一且单调递增，**重连后仍继续递增**。
3. 下单后第一个状态事件是 ACKNOWLEDGED，orderRef 等于 intent_id，最终带 permId；账户不一致抛 `AccountMismatchError`。
4. 同一券商订单号重复下单抛 `DuplicateOrderError`（IBKR 适配器须自行记录已提交订单号，重启后从未成交与已完成订单恢复）。
5. 成交通过 `ExecutionReport` 报出，成交价不劣于限价，状态与成交的 permId 一致；`executions(since, order_ref)` 能查回。
6. 部分成交时已成交 + 剩余 = 总量；改单数量不大于已成交量被拒（驱动器支持时）。
7. 撤单先 CANCEL_PENDING 再 CANCELLED；撤或改不存在的订单抛 `UnknownOrderError`；撤保护性止损需显式确认。
8. `lookup_order` 能查回未成交与已结束的订单；查不到返回空结果。
9. 改单只改变价格与数量，方向与类型不变。
10. 没有任何全局撤单入口。
11. 断开发出 DISCONNECTED 事件。
12. 外来挂单与外来成交（无 orderRef）如实出现在 `open_orders`、事件流与 `executions` 中（驱动器能注入时）。

## 移交（必须出现在对应任务单的验收标准中）

- **O-01**：只设一个票据签发工厂；签发前从账本按 decision_id 读回已持久化的风控决定，核对意图内容、结论与是否已被消费；
  broker_order_id 的持久化与决定的消费记录同一事务；OMS 不对外暴露接受票据的公共方法。订单号取
  max(券商 nextValidId, 账本最大值 + 1)。佣金后到的入账方式（与 B-03 一起定）。
  改单的风控决定按 amendment_id 消费（一次决定只能用于一次改单），风控对改单重新评估价格与数量。
  未匹配的外来成交入账为未匹配成交并生成差异事件，不得丢弃。
- **R-01**：风控决定落账并带规则版本；决定的评估对象（含价格与数量）写入决定或其哈希，供 O-01 核对。
- **guard / R-05**：撤单按账本中的订单类别（创建时持久化、不可变）只撤 OPEN；类别查不到或券商事实显示是 STOP 一律不撤并告警；
  判定写成 domain 纯函数共用；guardd 只拿到只含撤单与未成交订单查询的窄接口（独立 clientId，B-03）。
  R-05 定稿时把 `allow_protective_stop` 的允许范围从整个 oms 收窄到急停二次确认所在的单个文件。
  注意：非 LIMIT 一律需要确认才能撤，IBKR 的 LOC、LIT、MIT 等会映射为 OTHER，急停撤这类开仓单时会被拦下，
  属于预期的失败即关闭，R-05 需显式处理（按账本类别确认后再带确认参数撤）。
  arch_scan 在 guard 中只允许 `x.cancel_order(oid)` 形式的直接调用（不带关键字参数、不取方法对象、不转发）。
- **B-02**：可控的撤单确认（撤单期间成交、撤单被拒）、成交先于 ACK、重复回报、拒单、DAY 到期（含 IBKR 以 Cancelled 报出）、
  断线期间状态漂移、重启窗口内下单被拒、下单响应丢失、终态后迟到成交、撤单因已成交被拒、成交更正；
  现金随成交变化（买入减已结算、卖出加未结算）、初始持仓、加权成本、负持仓的可见性；佣金后到（成交先报、佣金另报）。
- **B-03 / B-05**：IBKR 状态与错误码映射（见 C-02 移交）；契约在模拟盘运行时的驱动器实现（可成交限价）、
  撤单后剩余量的规范化、本套件留下的持仓清理（REDUCE 卖出走 OMS）；把 IBKR 订单类型映射为 `BrokerOrderType`
  （STP、STP LMT、TRAIL 等止损类都要识别为止损，撤单时按券商侧类型要求确认）；外来订单注入需人工在 TWS 下单；
  外来单可能 `broker_order_id` 为 0 或与别的 clientId 重复，撤单与对账以 permId 为准；限流封装在适配器内；Flex 对账独立为 R-07 的数据源。
