## 目标

IBKR 历史日线经 `DataProvider` 接口接入，并通过和 FakeDataProvider 同一套的契约测试，供基准策略计算信号（V4.1：M1 先用 IBKR 历史数据）。

## 做了什么

- `server/broker/ibkr/history.py`：向 IBKR 取日线的窄接口。ib_async 只能在 broker/ibkr 里 import，所以放在这里。
  - `qualify_stock`：合约必须确认，有 conId、是 STK、美元计价；否则报 UnknownContractError。
  - `fetch_daily_bars`：
    - 请求参数：`reqHistoricalDataAsync`，`whatToShow=TRADES`、`useRTH=True`、`barSizeSetting="1 day"`。
    - 单次请求最多 365 天。
    - 返回的日期乱序或重复，就拒绝整批。
  - `daily_bar`：转成 Decimal。
    - NaN、UNSET、价格 ≤ 0、成交量为负，一律拒绝。
    - 日期必须是 date，datetime 也拒绝（日线不该带时刻）。
    - 原始字段存成 JSON 文本，原样进原始层。
- `server/data/ibkr_provider.py`：`IbkrHistoryProvider`，实现 `DataProvider` 接口。
  - 能力：只提供日线。不能列出全部标的，不提供公司行动和交易日历，这些一律明确报 UnsupportedCapabilityError。不含退市标的。
  - 开盘和收盘时间取自交易日历（D-03），因为 IBKR 只给日期。
    - 区间内没有交易日：返回空批次，不发请求。
    - 区间内有交易日，IBKR 却一根都没给：报“供应商不可用”，不当作“没有数据”。
    - IBKR 给出了日历上不是交易日的日期：整批拒绝。
  - 复权口径标成 `ibkr_split_adjusted`。IBKR 日线会追溯调整拆股、不调整分红，所以不冒充未复权序列；D-04 遇到这个口径会拒绝再做复权。
  - **一次 `fetch_bars` 只发一次请求。**
    - 首尾交易日相距超过一年时直接拒绝，由调用方切分。D-02 本来就按“标的 × 年”分片。
    - 这样 D-02 按调用计的限速，就等于按请求计。
  - 限速：10 分钟 50 次。IBKR 的限制是 10 分钟 60 次，这里留了余量，由 D-02 执行。
  - **ib_async 的实际行为：** 超时、限速违规（162）、没有数据权限（354、10167）时，ib_async 不抛异常，而是返回空列表。
    - 所以区间内有交易日、返回却为空时，一律报 ProviderUnavailableError，让调用方稍后重试。
    - 共用连接的 RaiseRequestErrors 设置不改。
    - 代价：区间跨过上市日时，也会报“不可用”，需要收窄区间。
  - 确认合约：
    - 有超时；超时或连接出错报 ProviderUnavailableError。
    - 返回的合约代码必须与请求的代码一致。
    - 空结果按“未知标的”处理。D-02 对未知标的会记为失败、不重试，也不会把它移出标的池。
  - 拉取时间取在请求之前，取早不取晚：下游靠它判断当天的 K 线是否已收盘。时钟不带时区时直接拒绝。
  - 连接层抛出的异常报 ProviderUnavailableError；数据口径对不上（MappingError）原样上抛。
  - 授权条款链接先填 IBKR 官网首页。准确的市场数据和 API 条款页面，等 F-05 开通账户时核对后更新。

## 联调时必须核对（核对之前，基准策略不得用这里的数据下单）

1. 把契约测试的 `provider` 夹具换成连着 TWS 模拟盘的客户端，原样跑一遍。
2. `endDateTime` 的写法 `yyyyMMdd 23:59:59 US/Eastern` 和 `durationStr="N D"` 能不能被接受；返回的区间是否刚好包含首尾两天。
3. 日线的 `date` 是不是 date 类型（`formatDate=1`）。
4. 成交量单位：股，还是 100 股一手。
5. 复权口径：TRADES 日线是否只调整拆股；分红是否需要另外取（D-04）。
6. 请求频率：10 分钟 60 次的限制；违规时报错误码 162，看它是否走 ProviderUnavailableError。
7. 没有数据权限时的报法（错误码 354、10167），以及当天数据什么时候可以取到。
8. 授权条款的准确链接。
9. 确认合约时，“找不到合约”（错误码 200）与其他错误能不能区分开。现在两种都得到空结果，都按“未知标的”处理。
10. `end` 落在今天之后（`endDateTime` 是未来时间）时，IBKR 是否接受。
11. 当天的日线收盘后多久能取到。

## 评审修复（safety-reviewer 第一轮：REQUEST CHANGES）

| 级别 | 问题 | 修法 |
|---|---|---|
| P0 | ib_async 超时、报错时返回空列表，不抛异常。多段请求里有一段为空时，会静默缺一年数据 | 不再在内部拆段，一次调用只发一次请求；有交易日却为空，报“不可用”。替身改成按真实行为返回空列表 |
| P1 | 限速按调用计数，但一次调用会发多次请求 | 一次调用只发一次请求，超过一年拒绝 |
| P1 | 确认合约没有超时 | 加了超时，超时报“不可用” |
| P2 | 拉取时间取在请求之后；时钟不带时区时会被静默换算 | 改在请求之前取，并拒绝不带时区的时钟 |
| P2 | 没有核对返回合约的代码 | 代码不一致时拒绝 |
| P2 | `end` 超过今天、错误码 200 的区分 | 加入联调核对清单 |
