## 目标

workerd 每轮先在决策窗口里运行一次策略调度，把意图放进 outbox，再照常投递给 tradingd。

## 做了什么

- `server/app/strategy_runner.py`：`StrategyRunner`。
  - 不在运行窗口内时直接返回，不读任何数据。
  - 每个交易日只认真跑一次：第一轮跑完（不论结果）就记下日期。这样避免卖单在 4 分钟窗口内成交后，重跑当天就买入（T-02 评审记录的问题）。
  - 外部数据（持仓、账户与行情输入、数据门禁、账户 ID）由 `RunnerSources` 注入。任何一项出错，当天跳过，不拿缺省值硬跑。
  - outbox 本身出错时上抛。
  - `check_delivery`：运行窗口加投递间隔必须短于意图限龄，否则拒绝启用（T-01 移交）。
  - 默认调度：开盘后 30 分钟决策，运行窗口 4 分钟，回看 400 个日历日（基准策略约需 230 根日线），发布延迟 1 小时。
- `server/app/workerd.py`：`run_workerd` 新增可选的 `runner` 与 `clock`。
  - 调度在线程里运行（读数据湖、算策略都是阻塞操作）；出错只记日志，不影响投递。
  - 参数不兼容时拒绝启动（退出码 78）。

## 生产接入

生产 workerd 暂时不传 `runner`：持仓、账户、已结算现金、止损记录、实时报价的真实来源，要等账本只读接口与 B-03、B-04 才有。
在那之前策略调度不启用，workerd 只做投递，行为与之前完全相同。接入时只需在 `__main__` 里装配 `RunnerSources`。

## 验收标准

- [x] 窗口外不读数据、不运行；窗口内每个交易日只跑一次；周末与休市不跑
- [x] 账户、持仓读不到时当天跳过，不入队，不补跑
- [x] 运行窗口加投递间隔不短于意图限龄时，拒绝启用（workerd 退出码 78）
- [x] workerd 每轮调用调度；调度出错不影响后续轮次与投递
