## 目标

把一条条资讯变成结构化事件，并评估它的可信度。

## 设计要点

1. **事件结构**：事件类型（政策、监管、财报、并购、供给冲击、诉讼、宏观数据等）、主体（公司、行业、国家）、
   方向（正面、负面、不确定）、确定性（已官宣、官方文件、主流媒体报道、传闻）、时间、来源列表、原文摘录。
   输出必须符合 A-03 的结构化协议，字段不合法即拒绝。
2. **合并**：不同来源报道同一件事合并成一个事件，记录所有来源；后续报道只更新，不新建。
3. **可信度**：
   - 由来源等级（A-15 的 `credibility`）、独立来源的数量、是否有官方文件来决定；
   - 只有社交媒体来源的事件一律标“未核实”，单一未核实来源不能用于交易（V4.1 9.6）；
   - 模型给出的判断要经 A-08 独立复核，复核冲突时标“有争议”，不进入交易信号。
4. **可回放**：保存模型版本、提示版本、输入与输出（A-05），同样的输入可以复现结论。

## 验收标准

- [ ] 事件字段经协议校验；非法输出被拒绝并记录
- [ ] 同一事件的多条报道合并，来源可追溯
- [ ] 只有社交媒体来源的事件标为未核实，下游无法用于交易（测试）
- [ ] 复核冲突时标“有争议”
- [ ] 提示注入测试通过（V4.1 11.2 第 17 项）

## 回滚

停用事件抽取即可；资讯存档不受影响。
