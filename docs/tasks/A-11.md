## 目标

从 A-15 登记的数据源持续收集资讯，去重、打时间戳、存档，并按标的和行业归类。
重要资讯推送到网页和 Telegram，每天生成一份情报简报。

## 非目标

- 不下单，不生成订单意图，不影响风控。首期只做“收集、整理、提醒”。
- 不判断涨跌（那是 A-12、A-14 的事）。

## 设计要点

1. **采集**：workerd 按各数据源的限速定时调用适配器（A-15）；单个数据源出错只影响它自己。
2. **存档（只追加）**：每条资讯记录 `source_id`、平台原始编号、发布时间、系统收到时间、正文或摘要、链接、内容哈希。
   存进数据湖，原始层不可变（D-06）。回测只能用“系统收到时间”早于决策时间的内容，防止偷看未来。
3. **去重**：同一条内容（哈希相同）只存一次；不同来源报道同一件事的合并放在 A-12 做。
4. **归类**：按代码与公司名匹配标的，按行业分类匹配行业与 ETF；匹配不确定的标为“待确认”。
5. **提醒**：只推送与持仓、关注池相关的重要资讯，分级走 AlertHub（P2 只进面板，P1 推送）；限速防刷屏。
6. **每日简报**：收盘后汇总当天与持仓、关注池相关的资讯，附来源链接；由 A-01 的模型生成摘要，摘要旁标“AI 生成”。
7. **不可信输入**：资讯内容一律当数据；送进模型时与指令隔离；社交媒体来源标“未核实”。

## 验收标准

- [ ] 多个假数据源并行采集；一个出错不影响其他
- [ ] 存档只追加，带两个时间戳；同哈希只存一次
- [ ] 回测接口按“收到时间”截断，有前视泄漏测试
- [ ] 提醒只针对持仓与关注池，有限速
- [ ] 提示注入样例（资讯里写“立即买入”之类）不改变任何状态，并被标出

## 回滚

停用采集任务即可；存档保留。
