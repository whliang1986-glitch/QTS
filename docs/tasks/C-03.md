## 目标

ledger.db 的表结构、迁移与 Repository：连接参数强制、只追加、幂等写入、失败即关闭。

## 非目标

不建 tradingd 进程与单写者进程隔离（S-01）；不建 meta.db、api.db（各自任务）；不做备份调度与异地副本（S-08）；
不在存储层判断订单状态转移（O-01 先调用 transition() 再落库）。

## 设计

- 依赖：SQLAlchemy Core 2.0 + Alembic（ADR-05 已定，不用 ORM）。
- 连接（`open_ledger`）：WAL、synchronous=FULL、foreign_keys=ON、recursive_triggers=ON、busy_timeout；
  WAL 设置失败即拒绝打开（防网络盘）；只读连接用 SQLite 只读 URI 加 `query_only`，供其他进程使用。
- 表：orders、broker_orders、perm_ids、order_events、executions、risk_decisions、command_log、audit_events、
  mode_changes。全部只追加，每张表三个触发器：
  - `<表>_no_update`、`<表>_no_delete`：禁止 UPDATE、DELETE（含 UPSERT 的 DO UPDATE）
  - `<表>_no_replace`：BEFORE INSERT 发现唯一键已存在即中止，堵住 `INSERT OR REPLACE` / `REPLACE INTO`
    （REPLACE 先删后插，默认不触发 DELETE 触发器——评审 C-03 阻断项）；recursive_triggers 是第二层
- 打开账本时核对迁移版本为最新，且 27 个触发器全部存在，缺一个就拒绝（防止日后 batch 迁移重建表时丢失触发器）。
- 唯一约束：intent_id、execution_id、request_id、broker_order_id、perm_id（一个意图一个 permId，一个 permId
  只属于一个意图）、order_events.event_id、audit event_id、mode_changes.change_id（后两者让重试不写出重复记录）。
- 金额与数量存 Decimal 字符串；时间存定长 UTC ISO 字符串（固定到微秒，按字符串排序即按时间排序）；
  完整对象存 C-01 的稳定 JSON（payload）；历史按自增 seq 排序。
- 幂等写入：同键同内容返回 False；同键不同内容抛 `ConflictError`；外键等其他约束违反、锁超时、只读写入抛
  `StorageError`。读路径的数据库错误与损坏记录同样抛 `StorageError`。
- command_log：同一 request_id 返回原结果，不执行第二次；同 request_id 不同命令视为冲突。
- 迁移（`server.storage.migrate`）：Alembic 以编程方式运行；初始迁移是冻结快照（不 import 当前 schema）；
  整次迁移在一个事务里（关闭 pysqlite 对 DDL 的自动提交），失败整体回滚；升级、降级前对已有非空库用
  `VACUUM INTO` 生成快照，并做 integrity_check 与逐表行数核对；账本有数据时降级必须显式 `allow_data_loss=True`。

## 剩余风险与移交

- **S-01**：单写者靠调用约定——只有 tradingd 以读写模式打开 ledger.db，其他进程只用 `read_only=True`；
  `_insert_once` 回查无竞态的结论以单写者为前提。
- **S-02**：command 字段应存“命令名 + 规范化参数”的指纹；“已执行未记录 / 已记录结果未知”的崩溃窗口用 PENDING
  状态处理。
- **O-01**：无法关联到任何已持久化意图的成交（外键会拒绝）要另建“未匹配成交”表入账并生成差异事件，不得丢弃；
  同一成交重放时数值表示（如 500.05 与 500.050）必须先由适配器规范化，否则会被判为冲突（失败即关闭的方向）。
- **B-01 / O-01**：模型新增带默认值的字段会让旧行 payload 与新序列化不一致，届时需要迁移或比较规则说明。
- **O-01**：给 executions 加复合外键 (intent_id, broker_order_id) → broker_orders，防止成交挂到属于另一意图的券商订单上
  （与“未匹配成交”表一起设计）。
- **迁移规范**（后续任何账本迁移）：batch 重建表必须重建该表三个触发器；涉及父表 orders 时用 `defer_foreign_keys`
  并在提交前跑 `foreign_key_check`；迁移时 tradingd 必须已停止（备份后的行数核对以无并发写入为前提）。
- 原生 SQL 插入 seq = -1 的行会让之后的自动编号插入被拒（拒绝服务，失败即关闭方向）；文件权限是防线，暂不加 CHECK。
- **S-08**：备份的校验和、保留与清理（目前每次升级都备份，会逐渐累积）、异地副本。
- SQLite 触发器可被拥有文件写权限的人删除：打开时会因触发器缺失而拒绝；最终防线是文件权限（S-01 / S-08 的服务账户）与备份。
