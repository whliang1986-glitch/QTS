| 字段 | 内容 |

| 优先级 | P0 |

| 依赖 | S-01a（交易核心）、S-01b（进程间通道与 outbox）、S-01c-arch（装配层） |

## 范围

- **平台层 `InstanceLock`**（server/platforms/files.py）：单实例锁。
  - Windows 用 msvcrt.locking，Linux 用 fcntl.flock；macOS 明确未实现（P-MAC）。
  - 进程崩溃时由操作系统释放。保证 tradingd 是账本唯一写者，workerd、guardd 也各只有一份。
- **风控装配函数**（server/risk/assembly.py）：`build_trading_core(repo, broker, CoreInputs)`。
  - 按固定顺序接好 ModeManager → OMS → 风控上下文 → 对账 → 运行状态机 → 风控引擎 → 急停 → 交易核心。
  - 两个回调——OMS“订单状态无法查证”和上下文“状态不可信”——都持久化 SAFE HALT，且不拿核心锁。
  - 不导出 OrderManager。
- **进程守护**（server/app/supervisor.py）：
  - 崩溃后指数退避重启（1→60 秒，稳定 5 分钟后清零），连续崩溃 5 次升为 ERROR 告警。
  - 退出码 0（正常）和 78（拒绝启动）不重启。
  - 只用跨平台的 asyncio 子进程接口。
- **tradingd**（server/app/tradingd.py）：
  - 启动顺序：单实例锁 → 打开账本（未迁移就拒绝）→ 券商适配器 → 装配 → 连接券商（失败按崩溃退出）
    → 报告健康 → `core.start()`（启动校验失败就拒绝）→ 开两个端点 → 常驻。
  - 常驻：处理回报流、写心跳。回报流结束或任何常驻任务出错，都按崩溃退出。
- **guardd 看门狗**：
  - 判断与撤单规则在 server/guard/watchdog.py：心跳缺失、超过 90 秒或时间超前不可信时，只逐单撤满足**全部**条件的单——
    券商侧限价单、有 orderRef、账本意图是开仓买单、账本与券商订单号一致。
  - 减仓单、保护性止损、外来单、读账本出错或对不上的单，一律不撤。不带止损确认参数，账本只读。
  - 心跳文件 server/guard/heartbeat.py：原子替换写入；内容坏或不带时区按“没有心跳”处理。
  - 进程入口 server/app/guardd.py：单实例锁，券商不可用就拒绝启动，连接中断按崩溃退出。
- **workerd**（server/app/workerd.py）：outbox 的唯一投递循环。
  - 连接 tradingd 时核验服务端账户，并带超时。连不上或投递中断就下一轮重连重投。
  - 策略运行器在 T 组接入。
- **配置与命令行**：
  - config/runtime/processes.toml（路径、间隔、各进程账户）严格校验：路径分隔符一律写 /，未知键、非正整数一律拒绝。
  - `python -m server.app {supervise,tradingd,workerd,guardd}`。
- **给 Dylan 的说明**：docs/runbooks/S-01c-services.md（Windows 任务计划程序登录时启动、停止方式、单写者与文件说明；Linux 仅参考）。

## 生产入口的现状（如实说明）

IBKR 适配器在 B-03，行情与账户同步数据源在 D 组。在它们接入之前：
- tradingd 和 guardd 的生产入口都以退出码 78 拒绝启动，不拿 FakeBroker 顶替；守护进程也不会反复拉起它们。
- 测试里注入 FakeBroker，验证的是装配、启动顺序、端点、心跳、撤单规则和退出码。
  **这些不等于和真实 IBKR 联调过**：联调在 B-03 / G2 进行。

## 测试

  跨进程持锁时拿不到，持锁进程被杀后锁自动释放。

  - 启动失败退避重试；停止时终止子进程且不再拉起；各子进程独立守护。
  - 真实子进程崩溃后被重启。
- tests/integration/app/test_tradingd.py（9 项，真实账本 + 真实通道 + FakeBroker）：

  - guardd 在心跳缺失时撤掉开仓单；生产入口拒绝；第二个实例被拒；券商连不上、检查中断线都按崩溃退出。

## 评审记录

safety-reviewer 第一轮：REQUEST CHANGES，无 P0，P1 五项、P2 十二项。

- P1-1 guardd 断线后静默失效：契约断线抛的是 `server.broker.base.BrokerUnavailableError`，不是内置 `ConnectionError`。
  已修：每轮先查 `broker.connected`，两种异常都按崩溃退出。测试改用真实的 `FakeBroker.disconnect()` 与服务端断线。
- P1-2 tradingd 券商断线后既不重启也不重连，心跳照写。已修：心跳循环先查 `broker.connected`，断开即按崩溃退出、
  不再写心跳，由守护进程退避重启（重启后先查券商再对账）。测试用两种真实断线驱动，并断言心跳停止。
- P1-3 S-01b 移交的验收条件：
  - tradingd 入口按 created_at 限龄 → 已实现（`TradingCore(intent_max_age=…)`，装配时取 5 分钟；超前 5 秒以上同样拒绝）；
  - 端点自检 → 已实现：每次写心跳前对两个端点各建一次连接，连不上就按崩溃退出；
  - DAY 意图跨交易日作废 → 移交 S-01d（需要交易日历）；
  - Linux 套接字目录属主与权限 → 写入剩余风险（runbook 有手工步骤）。
- P1-4 安全时长可在普通配置里任意放宽 → 已修：guardd 心跳超时 ≤ 90 秒、≥ 3 倍心跳间隔、大于检查间隔；
  workerd 意图限龄 ≤ 5 分钟。只能调严，上限是代码常量，放宽须 Dylan 本人决定。
- P1-5 锁释放稍有延迟就永久停摆 → 已修：拿锁时最多等几秒；仍被占则以 75（EXIT_BUSY）退出，由守护进程退避重试，不再按 78 永久放弃。
- P2 已修：
  - 心跳写入遇 PermissionError 跳过一次；
  - 单写者锁放在账本旁（`ledger.db.lock`）；
  - 守护进程停止与拉起之间的竞态；
  - workerd 单轮投递加超时；
  - guardd 核对订单账户与账本一致；
  - 自定义异常改名为 `AdapterNotAvailableError`，避免与契约里的 `BrokerUnavailableError` 混淆；
  - 启动失败也断开券商；
  - 配置路径只允许仓库下的相对路径（禁止开头 /、盘符、..、空段）；
  - 补测试：账本里没有这张单、账户不一致、start() 意外出错、端点失效、锁旁置、BUSY 重试、停止竞态。
- P2 未改，写入剩余风险：心跳只说明进程活着、端点在、券商连着，不说明核心锁没卡死；
  tradingd 启动对账期间心跳未更新，guardd 可能先撤开仓单（方向保守）；命令日志写失败是否纳入 SAFE HALT（S-01a-confirm）。

### 第二轮

safety-reviewer 第二轮：REQUEST CHANGES，无 P0。第一轮的 P1-1 到 P1-5 逐条核实都已修好。新发现 P1 一项、P2 十一项。

- P1-A 入口限龄放在了幂等重放之前：已签发的意图在限龄之后重投时，会被回答成“过期拒绝”，与账本、券商的事实不符。
  - 已修：限龄和 expires_at 检查移到核心锁内，并且只对从未签发过的意图做；已签发的意图交给风控，按 intent_id 返回原决定。
  - 测试：已放行的意图 10 分钟后重投，返回同一决定，风控决定只有一份；从未签发的旧意图照样拒绝。
  - workerd 侧仍有同类问题：已投出但没拿到回答的意图，过期后会在本地记 EXPIRED（S-01b 时就有）。已写入移交（T 组）。
- P2 已修：
  - 端点自检整体限时（连接与关闭一起），并核对监听方就是本进程；
  - 自检产生的连接日志降为 DEBUG，不刷告警；
  - 自检之后再查一次券商连接，再写心跳；
  - 锁文件路径先 resolve()；
  - workerd 的锁跟着 meta.db 走；
  - guard_check_seconds 不得超过超时的三分之一；
  - 补了一项真实端点失效的自检测试（地址不存在）。
- P2 写入移交：
  - 安全上限常量重复定义，且没有机制保护：以后放进受保护配置，或者用架构测试钉住数值；
  - 配置类确定性错误（端点名被占、Linux 路径过长）目前按崩溃处理，会被反复重启；
  - guardd 在 tradingd 存活期间只看 connected 标志（B-03 加券商活性探测）。

## 移交 / 剩余风险

- B-03：实现 IBKR 适配器后替换 `production_broker` / `production_guard_broker`。
  实测跨 clientId 逐单撤单；不可行时开仓单改用短有效期，并写入 ADR（V4.1 7.6）。
- D 组 / S-01d：替换 `production_inputs`（行情、账户同步、券商窗口），健康上报接到真实组件；
  调度器负责 assess、盘中 / 日终对账。
- S-02：apid 加入守护进程清单。
- Windows 上停止等于强制结束，tradingd 按崩溃恢复，不依赖优雅退出；以后需要优雅停止时，再增加跨平台的停止通道。
- 心跳文件可以被同账户进程伪造：同账户不是安全边界（S-01b）。
- 心跳只证明“进程活着、两个端点能接受连接、券商连着”，不证明交易核心的锁没卡死（P2-2）。
- tradingd 重启后、启动对账完成前不写心跳：对账较慢时 guardd 可能先撤开仓单（偏保守，P2-10）。
- Linux 套接字目录属主 tradingd、权限 0750：代码没有强制，runbook 写了手工步骤；以后放进平台层的安装步骤。
- DAY 意图跨交易日作废：S-01d（调度器接入交易日历时一并做）。
- 命令日志写失败纳入 SAFE HALT（S-01a-confirm 剩余风险）：未处理，S-01d 评估。
- 意图限龄 5 分钟、心跳超时 90 秒的取值：放宽须 Dylan 本人决定；调严可改配置。
  这两个上限现在是普通代码里的常量（settings.py、assembly.py、watchdog.py），只靠评审守着；
  以后放进受保护配置，或者用架构测试钉住数值。
- workerd 对“已投出、没拿到回答”的意图过期后记 EXPIRED（S-01b 遗留）：T 组接入策略运行器时，
  回执要区分“从未投出就过期”与“投递结果未知”，后者交给 tradingd 按 intent_id 查证，策略不得据此重新生成信号。
- 确定性的配置错误（端点名被占、Linux 套接字路径过长）目前按崩溃处理，会被退避重启；以后归为拒绝启动（78）。
- guardd 在 tradingd 存活期间只看 connected 标志，不实际探测券商：B-03 给 tradingd 与 guardd 加券商活性探测。
- 来自 S-01c-arch 评审：
  - 给 arch_scan 增加 `app-import` / `fake-import` 收紧规则，拦字面量动态导入；
  - 券商适配器不暴露底层 SDK 对象。
