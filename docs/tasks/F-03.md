## 目标

把分层规则变成会失败的检查：违规 import 或违规调用使 pre-commit 与 CI 失败。

## 非目标

不定义 BrokerAdapter 与 oms 提交入口的真实接口（B-01、O-01、R-01）；不做类型层与进程层的运行时保护（见剩余风险）。

## 已批准的决定（Dylan，2026-10-22）

1. 允许直接 import broker 的包：oms、guard、backtest、data（以及 broker 自身）。
2. oms 的订单提交入口只允许 risk（及 oms 自身）调用。
3. strategy、ai、api 连间接依赖 broker 也禁止；它们需要的共享类型放进 domain。

评审中追加的同方向收紧（请 Dylan 验收时确认）：只有 risk、backtest 可以 import oms。

## 实现

两层检查，任何一层违规都让 pre-commit 与 CI 失败：

1. `pyproject.toml` `[tool.importlinter]`（`uv run lint-imports --config pyproject.toml`）：
   - `domain-independent`：domain 不依赖其他层
   - `no-broker-from-decision-layers`：strategy、ai、api 不依赖 broker（含间接）
   - `broker-importers-allowlist`：其余分层不得直接 import broker（risk 可经 oms 间接依赖）
2. `scripts/arch_scan.py`（AST 扫描，失败即关闭）：
   - 唯一下单出口：下单 / 改单名只在 oms；撤单只在 oms、guard；全局撤单任何包禁止；名称的任何使用
     （调用、取方法对象、from-import 别名、partial）都算；包含 ib_async 驼峰原名 placeOrder / cancelOrder
   - 不得绕过风控：`submit_approved_intent` 只在 risk 与 oms
   - broker 包防洗名：受保护名只能出现在调用方不更宽的受保护名函数里；禁止模块级 `__getattr__`；
     受保护名函数只能用白名单装饰器
   - 反射：oms 以外，getattr / setattr / delattr / hasattr / getattr_static / `__import__` / import_module /
     attrgetter / methodcaller / resolve_name 只能以“参数全为字面量的直接调用”出现（且属性名不得是 dunder）；
     inspect.getmembers、vars、dir、globals、locals、`__dict__`、`__getattribute__`、`__builtins__`、
     sys.modules、runpy、importlib.util、builtins.* 一律禁止；豁免只能登记在 `DYNAMIC_EXEMPTIONS`（当前为空）
   - 导入白名单：broker（oms、guard、backtest、data）、oms（risk、backtest）、domain 只依赖自身；
     含相对导入、`server.xxx` 属性访问、导入函数的字面量参数，导入 server 根包视为导入全部分层
   - 券商 SDK：ib_async / ib_insync 只在 server/broker/ibkr
3. 分层登记：`KNOWN_LAYERS` 必须与 server/ 下的目录一致，且被契约完整覆盖（新分层不能默认放行）。
4. 接线：pre-commit（`always_run`）、CI 两个步骤、CODEOWNERS（`scripts/arch_scan.py`、`pyproject.toml`、
   `tests/arch/`）、CLAUDE.md、safety-reviewer 清单。

## 剩余风险与后续任务

- 静态检查做不到的（依赖注入、回调、运行时组装的对象）由类型层与进程层承接：
  - R-01：风控签发不可伪造的 ApprovedIntent；O-01：提交入口只接受该类型并在运行时校验
  - B-01：BrokerAdapter 只接受 OMS 签发的 OrderTicket，FakeBroker 拒绝无票订单
  - S-01：只有 tradingd 进程持有券商连接，workerd、apid 不加载 broker
- B-01：broker 私有辅助函数里调用 placeOrder 会被报，须内联到同名委托函数或在扫描器常量中登记。
  B-01 / O-01 / R-01 定接口时同步更新 `arch_scan.py` 的受保护名称。
- B-03：ibkr 包不得重新导出 SDK 对象（如 IB 实例）——写入 B-03 任务单。
- 命名约定：domain 枚举值、事件名、变量名不要使用受保护名称（如 `cancel_order`）；不要用 `dir`、`vars`
  作变量名。
- `DYNAMIC_EXEMPTIONS` 的任何新增都需要 Dylan 审批（CODEOWNERS）。
- 钩子已知局限：引号里含 `;` 的提交信息加 `-n` 仍可能漏判；`git config --get core.hooksPath`、
  `git add -n` 会被过度拦截。CI 与 CODEOWNERS 兜底。
- 回滚：删除 `scripts/arch_scan.py`、`tests/arch/test_{import_contracts,order_exit_scan,layer_registry}.py`、
  `tests/arch/_layout.py`、pyproject 中的 importlinter 段及 CI / pre-commit 对应步骤。
