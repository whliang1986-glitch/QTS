## 目标

验收要点：保护单随持仓创建、单独计数、纳入对账。

## R-06a：本 PR

- `server/risk/protective_coverage.py`：`check_coverage(account_id, positions, orders)`。
  - 纯函数，按**券商事实**逐标的核对。每个多头持仓都要有、并且只有一张卖出止损单，数量等于持仓。
  - 发现的问题分八类，单独计数：
    - 缺止损（MISSING）；
    - 数量不等（QUANTITY_MISMATCH）；
    - 多张止损（MULTIPLE）；
    - 没有持仓却挂着止损（ORPHAN，触发就会超卖）；
    - 碎股（FRACTIONAL）；
    - 不算覆盖的卖出单（UNRECOGNISED：止损限价、追踪、带条件、当日或 GTD 止损，交给人工）；
    - 卖出合计超过持仓（OVERSELL：止损加减仓，或没有持仓却挂着卖出限价单）；
    - 负持仓（NEGATIVE，交给对账）。
  - 只有 GTC 的普通止损单（STP）才算覆盖。卖出限价单是减仓，不算保护，但计入超卖检查。买入止损单不算。
  - 订单视图由调用方转换：risk 层不 import broker，所以止损限价、追踪止损要由调用方填成 "OTHER"。
  - 入参违约一律拒绝、不静默跳过：已结束的订单、负的或非有限的数量。
  - 已知限制：只按代码归并（首期只有美元计价的股票和 ETF）；空快照会得出“全部覆盖”，所以取数失败时不得调用（R-06b 接入时用测试锁住）。
  - 别的账户的数据一律拒绝，不静默过滤。
  - `alert_symbols()` 给出需要发 P0 告警（`protective_stop_missing`）的标的。负持仓由对账进入 SAFE HALT，不在这里告警。
- `docs/runbooks/R-06-order-precautions.md`：TWS 订单预防设置的核对手册。
  - 第一步：API 订单不绕过预防设置。
  - 第二步：填写数量、金额、价格偏离的上限。
  - 第三步：留下记录。
  - **数值由 Dylan 本人决定和填写**，不进代码、不进配置。

## R-06b：等决定和联调

1. **OMS 随持仓创建保护性止损。**
   - 买入成交后，按受保护配置里的止损参数（R-02）建单，止损数量随持仓同步。
   - 依赖 B-05 下单适配器，以及止损改单规则（O-03 的移交：只允许收紧，或只允许公司行动调整）。
2. **超卖窗口**：止损单和减仓单同时成交，会卖出超过持仓。我的方案是“下减仓单之前先撤旧止损，减仓结束后按剩余持仓重建”。
   - 这样做，减仓进行期间持仓暂时没有止损，属于短时风险。
   - 备选方案是把止损和减仓放进同一个 OCA 组。这要等联调核实 IBKR 在模拟账户上的行为。
3. **接入**：覆盖核对接入对账报告（R-07）和 guardd 的告警。
   - 现有告警文案“保护性止损缺失：{symbol}”不适用于超卖、多张、数量不等，接入时为它们加上 detail，或者单独设一个告警码；
   - 从券商记录转换成订单视图时，`STP LMT`、`TRAIL`、`TRAIL LIMIT` 都要填 "OTHER"（`mapping.py` 为了撤单确认把它们归为 STOP，那里不改）。
4. **公司行动**：拆股、合股之后，止损的数量和止损价按 D-04 的口径调整。

## 需要 Dylan 本人决定的事（已列入待办清单）

下面几件都涉及风控规则或订单执行行为，按变更控制只能由 Dylan 批准。协调助手和我只能提议；R-06b 的相关部分等他批准后再做。

1. **持仓已经跌破止损线怎么办。** 这时按 R-04 的规则算不出合规的止损价。
   - 协调助手的提议（2026-11-05）：
     - 发告警，同时禁止这只标的新开仓。这是一条新的风控规则；
     - 按“当前价下方固定距离”挂保护性止损。这个价格偏离了 R-04 的止损价规则；
     - 不自动减仓，减不减仓由 Dylan 在面板上决定。
   - 如果采用，“固定距离”是风控参数：
     - 放进受保护配置，代码里不写默认值；
     - 我在 R-06b 的计划里提议一个数值，并附上依据；
     - 没有这个参数时 fail closed：只告警、禁止开仓，不挂这张止损。
   - 其他可选做法：立即限价减仓；只告警，等 Dylan 处理。
2. **碎股持仓**（券商侧出现时）。
   - 协调助手的提议：止损数量向下取整，剩下的碎股单独告警。
   - 如果采用，R-06b 要同时调整核对口径（现在碎股持仓会一直报 FRACTIONAL），而且剩下的碎股本身没有保护。
   - 其他可选做法：只告警，由 Dylan 手动处理。
3. **TWS 订单预防设置的数值**：照手册填写，并把结果告诉我。
4. **保护性止损是否在盘前盘后触发**（`outsideRth`）。
   - 现在先用最保守的默认：只在正常交易时段触发，已写进 B-05 的复核项。
   - 这是订单执行行为，最终由 Dylan 确认。

## 评审修复（safety-reviewer 第一轮 REQUEST CHANGES，3 个 P1）

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 已结束的订单可能被算成覆盖 | 视图加上 `working`，已结束的订单直接拒绝 |
| P1 | 当日或 GTD 止损被算成覆盖 | 视图加上 `time_in_force`，只有 GTC 才算覆盖 |
