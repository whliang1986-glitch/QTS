## 背景

V4.1 涉及特征的内容只有三处：
- 第 4、5 章的特征快照存储（`lake/features/`）；
- 8.1 节的一条前视检查；
- D-06 的不可覆盖快照写入。

计划里没有任务负责因子本身。本任务补上这一块。

## 1 目标与边界

因子库是可复用的选股、择时信号唯一的登记处：
1. 手动添加、停用、删除因子，每一步都留记录；
2. 因子加入后自动验证，验证结果决定它能走到哪个阶段；
3. 回测、模拟盘、实盘共用同一份因子计算代码；
4. AI 可以提议新因子，但只能进入候选区，不能自己转正。

因子库不下单，不访问券商、账本和风控。它属于 strategy 或 data 层，沿用现有的 import-linter 契约：
不 import broker、storage.ledger、risk。

## 2 因子的定义

- **标识与版本**：因子 ID 加版本号。版本不可变，改算法或改参数就是新版本，旧版本保留。
- **两种定义形式**：
  - 声明式（首选）：用积木组合，积木包括收益率、波动率、均线偏离、成交量比、动量排名，加上窗口参数。手动添加和 AI 提议都优先用这种。
  - 代码式：Python 函数，统一接口 `compute(data_as_of, params) -> values`。只允许手动添加，AI 不能提交任意代码。代码哈希参与版本号。
- **输入声明**：用到的数据字段、回看窗口、预热天数。
- **元数据**：作者（手动或 AI）、假设说明（一句话，添加时必填）、创建时间。
- **防前视**：计算接口只拿到截至决策时刻 as_of 已发布的数据，与 T-01 的策略接口一致，从接口层面堵死前视。

## 3 生命周期

主线：候选（candidate）→ 已验证（validated）→ 正式（active）→ 停用（retired）。另有一个旁支状态：验证失败（rejected）。

- **候选**：只能用于回测和研究，不能被实盘策略引用。
- **已验证**：自动验证全部通过。
- **正式**：可以被策略引用。
  - 转正须 Dylan 批准，手动添加的因子也一样（2026-11-03 已批）；
  - AI 不能批准自己提议的因子。
- **停用**：新策略不能再引用；已有的引用仍可复现。
- **验证失败**：保留记录与失败原因，不删除，因为试验次数要计数。

## 4 手动添加与删除

**添加**：
- 经 API 或界面提交定义和假设说明。声明式填表单，代码式提交代码文件。
- 提交后立即做格式与安全检查：
  - 接口是否符合；
  - 有没有 import 被禁止的模块；
  - 有没有读取 as_of 之后的数据。
- 检查通过才作为候选入库，随后自动触发验证。

**删除规则**（2026-11-03 已批）：
- **候选、验证失败**：可以删除定义和缓存的因子值，但“试验登记”永久保留。
  试验次数用于多重检验校正，删除因子不能让它归零。
- **正式**：不能直接删除，只能先停用。
- **被引用过的**：被策略版本、实验记录或实盘决策引用过的因子，永不物理删除，只能停用。
  与决策关联的特征快照按 D-06 永久保留。

**审计**：
- 添加、转正、停用、删除都写审计事件，记录操作者、原因、时间。
- 转正和删除正式因子需要二次确认。

## 5 自动验证（必选）

自动验证只决定“能不能往前走”，不替代 Dylan 批准。流水线按顺序执行，任何一项红灯即判失败：

1. **前视检查**：逐日重算，用截断的数据重算，结果必须一致。
2. **确定性检查**：同样的输入算两次，结果逐位相同；NaN 和无穷大的比例不得超过阈值。
3. **覆盖率检查**：股票池里每个交易日的有效值比例达标；退市与缺数据的处理方式明确。
4. **预测力**：IC 与 RankIC，分 1、5、20 日三个持有期，样本内外分开计算。
5. **稳定性**：
   - 按年度、按市场状态（趋势 / 震荡 / 高波动 / 低波动）分别看，IC 方向一致且波动不过大；
   - 2020 年 3 月、2022 年等最差区间单独看。
6. **衰减**：IC 随持有期衰减的曲线要合理；衰减过快意味着换手过高。
7. **冗余**：与已有正式因子的相关性超过阈值即判冗余，除非有明显增量。
8. **换手与成本压力**：计算因子驱动组合的换手率；成本加倍后预测力仍然成立。
9. **多重检验校正**：每次验证都登记为 T-07 的一次试验，按累计试验次数提高门槛（Deflated Sharpe 思路）。
10. **样本外封存**：保留一段验证期，开发和调参时都看不到，只在最终验证时用一次。

**阈值**（2026-11-03 已批）：
- 放在普通运行配置里，起始值偏严，Dylan 可以调整；
- 调松须二次确认，并留下记录；
- 起始值先用已知因子（动量、低波动）校准。

**样本不足**：判“不可判定”，不算通过，报告里显示样本量。

**验证报告**：固化保存，内容包括数据版本、代码版本、参数、各项指标与结论。转正时报告附在审批记录里。

## 6 接口

- **T-01**：策略按“因子 ID + 版本”引用因子。
- **T-04**：回测调用同一个计算入口。
- **T-07**：每次验证登记为一次试验。
- **T-09**：策略版本记录它依赖的因子版本；因子停用时，列出受影响的策略。
- **D-07**：因子值绑定数据版本；数据修订后必须重算，结果作为新的一份。
- **D-06**：因子值按版本写入 `features/`，不可覆盖。
- **S-05**：“因子中心”页面。

## 8 验收标准

- [ ] 手动添加一个声明式因子和一个代码式因子，各自走完“候选 → 验证 → Dylan 批准 → 正式”。
- [ ] 故意偷看未来数据的因子必须判失败。
- [ ] 删除候选因子后，试验次数不减少。
- [ ] 删除被引用过的因子会被拒绝，只能停用。
- [ ] 同一个因子在回测、模拟盘、实盘三个入口算出的值完全相同。
- [ ] AI 提议的因子无法自行转正，也无法绕过复杂度上限和试验预算。
- [ ] 所有操作都有审计记录，验证报告可以复现。

## 9 风险

- **阈值不当**：可能误杀好因子，也可能放过坏因子。初期偏严，并用已知因子校准。
- **代码式因子是安全风险点**：只允许手动添加，并做静态检查。运行时放进沙箱：只读数据视图、无网络、不能写文件。
- **验证耗时**：按因子和股票池分片计算，并缓存结果。
- **样本有限**：首期股票池小，样本不足时判“不可判定”。
