## 目标

## 设计

- **组件登记**：名称、类别（DATA / ACCOUNT / OTHER）、是否关键、报告时效。组件主动 `report(ok, detail)`；
  从未报告或超过时效即视为故障（失败即关闭）。
- **assess()**：
  - 关键组件故障 → SAFE HALT，并经 `ModeManager.safe_halt` 持久化（同一组故障只写一次，出现新的关键故障再写）；
  - ModeManager 已处于 SAFE HALT（HALT 且降风险通道关闭）→ SAFE HALT（组件恢复也不解除）；
  - 非关键组件故障或处于券商重启窗口 → DEGRADED；全部健康 → NORMAL；
  - 状态本身算不出来（窗口判断、读模式出错）→ SAFE HALT。
  - 普通 HALT（人工急停）不是 SAFE HALT：模式门拦新增，运行状态仍可信，降风险单照常。
- **gate(subject)**（接入 `RiskEngine(run_gate=...)`，拒绝记 `run_state`）：
  - SAFE HALT → 拒绝；券商窗口 → 一律拒绝（含降风险单，券商此时不接单）；
  - 非关键故障 → 降风险单放行；其他策略必须登记在 `degraded_allowed` 且不依赖故障组件；
  - 门禁本身出错 → 拒绝。
- **resume_checks() / resume(actor)**：
  - data_ok / account_ok：全部 DATA / ACCOUNT 类组件健康；
  - orders_ok：没有 SUBMITTING / UNKNOWN 订单，未结束订单没有结果未确认的改单；
  - risk_ok：规则集可用；database_ok：`LedgerRepository.check_integrity()` 通过；reconciled：对账 `last_clean()`；
  - 每项检查出错记为不通过；`resume` 交给 `ModeManager.resume`（复核人工身份、目标模式 = 受保护配置请求的模式、G7 门禁）。

## 验收标准

- [x] 状态转移：NORMAL ↔ DEGRADED；关键故障 → SAFE HALT（持久化，组件恢复不自动解除）。
- [x] 券商窗口内不新增订单；降级时只放行获准且不依赖故障组件的策略与降风险单。
- [x] 恢复门槛六项逐项测试；任一不通过即拒绝恢复；非人工拒绝。
- [x] 接入 RiskEngine：运行状态拒绝落账为 `run_state`；门禁出错失败即关闭。

- ★ **S-01**：tradingd 组装 RunStateMachine 并把 `gate` 传给 RiskEngine 的 `run_gate`（未接入时引擎不做运行状态门禁）；

- ★ **B-03 / D-01 / D-05**：各组件按时效报告健康（券商连接与账户同步为关键 ACCOUNT 类；实时行情为关键 DATA 类）。

- ★ **S-01**：定期调用 `assess()` 时要捕获异常（SAFE HALT 写入失败会抛出），按 SAFE HALT 处理并告警。

  来源冒用的后果更大）。

## 剩余风险

- `orders_ok` 不把撤单中（CANCEL_PENDING）、OMS 重连对账未完成算作不通过；对账（reconciled）会覆盖订单状态差异。
- `database_ok` 只核对迁移版本与触发器，不做 SQLite 物理完整性检查（`PRAGMA quick_check`），S-08 备份恢复演练时补。
- 评估失败时的 SAFE HALT 只体现在运行状态里，不落盘（门禁照样拒绝）；关键组件故障才持久化。
