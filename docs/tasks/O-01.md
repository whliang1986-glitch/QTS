## 目标

OMS 成为唯一的票据签发者与订单状态的唯一写入者：风控放行的意图被签发、持久化、提交；
券商回报经 C-02 转移表推进状态；UNKNOWN 只能按 orderRef 查证后转出，永不盲目重发。

## 非目标

- 改单与撤单竞态（O-03）、属性测试与故障注入套件（O-04）、崩溃恢复与启动对账（O-05、R-07）。
- 成交更正冲正（O-02；本任务先照实存入未匹配成交）、佣金后到入账（B-03）、风控本身（R-01）。
- 保护性止损的撤单（R-05 二次确认路径）。

## 接口与不变量

- `OrderManager.submit_approved_intent(intent, decision)`（arch_scan：只由 risk 调用）：
  - 意图与风控决定必须已落账且内容一致；结论只能是 ALLOW / REDUCE；
  - 一个决定只能签发一次、一个意图只有一条订单链：已签发则幂等返回当前状态，绝不再下单；换决定重签拒绝；
  - 标的规格缺失、票据校验失败一律拒绝（`SubmissionRefusedError`），不下单；
  - 订单号 = max(券商 nextValidId, 账本最大值 + 1)；
  - 券商订单、签发记录（含决定与数量）与 SUBMIT_SENT 事件**在 place_order 之前同一事务**落账；
  - place_order 抛任何异常 → SUBMIT_TIMEOUT → UNKNOWN（结果未知，不重发）。
- `on_broker_event`：先 transition() 再写账本；SUBMITTING 时收到订单存在的状态先补 BROKER_ACK；
  撤单被拒用累计成交计算 has_fills；非法转移拒绝并写差异审计；终态后的状态忽略。
- 回报认领：orderRef 与订单号都必须存在、且指向同一张已签发订单，回报带的 permId 与已登记的不同即不认领；
  不认领的状态回报只写差异审计，不改状态（外来单的订单号可能撞号）。
- 成交：认领通过且标的、方向、账户一致、整股才入账；否则进未匹配成交表（不丢弃）；
  按 execution_id 去重；累计数量推进 PARTIAL_FILL / FULL_FILL；终态后的成交照样入账并写差异审计；
  permId 先到即落账（终态下也允许）；佣金后到时先记 0。
- UNKNOWN：`resolve_unknown` 按 orderRef 查单，先把查到的成交入账，再以 BROKER_STATUS_OBSERVED 转出；
  查不到保持 UNKNOWN，第 N 轮（默认 3）通知 `on_unresolved`（必填，由调用方 SAFE HALT），绝不映射为 REJECTED；
  同一 orderRef 下出现别的订单号、或查到的订单与签发不符，立即通知并保持 UNKNOWN。查证转出后补发挂起的撤单。
  UNKNOWN 期间到达的状态或成交只触发查证，不直接改状态。
- `check_timeouts`：到期仍在 SUBMITTING 才转 UNKNOWN；离开 SUBMITTING 即取消定时，迟到的超时忽略。
- `request_cancel`：只撤开仓 / 减仓单；SUBMITTING / UNKNOWN 挂起，确认后再撤；保护性止损拒绝。
- 账本（迁移 0003）：`ticket_issuance`（decision_id 唯一）、`unmatched_executions`，只追加触发器齐全；
  触发器 `executions_no_foreign_order` 保证成交挂在同一意图的券商订单上（等价复合外键）。
- 差异一律写审计事件 `order_discrepancy`（kind 区分），correlation_id 为 intent_id（一条订单链一个关联 ID）。

## 验收标准

- [x] 非法转移被拒（含部分成交后报拒单）；转移只经 transition()
- [x] UNKNOWN 可被查证解决（丢 ACK 超时后查到 ACK、UNKNOWN 中成交后查到 FILLED）；查不到保持 UNKNOWN、不重发、多轮后通知
- [x] C-02 移交：先转移后落库、撤单被拒用累计成交、重复回报不升级、终态后成交入账并记差异、查无此单不映射 REJECTED、
      SUBMITTING / UNKNOWN 不直接撤、UNKNOWN 期间成交触发查单、离开 SUBMITTING 取消超时、permId 先到即落、订单号先持久化、未匹配成交不丢弃
- [x] B-01 移交：单一签发工厂、读回已落账决定、决定只用一次（同事务）、订单号取 max、未匹配外来成交入账
- [x] C-03 移交：未匹配成交表、成交与券商订单的归属约束
- [x] ruff、mypy、全部测试、lint-imports、arch_scan 通过
- [x] safety-reviewer 评审：第一轮 REQUEST CHANGES（B1 回报归属过宽，I1–I5），修改后第二轮 APPROVE；
      第二轮建议 1（permId 属于别的意图即不认领）、2（查证时补登 permId）、4（并发测试断言）已改，3 写入 R-01 移交

## 移交

- **O-02**：成交更正（`corrects`）冲正后按新值入账，并从未匹配成交表关联；重复提交的幂等测试扩展。
- **O-03**：改单（OrderAmendment 的决定按 amendment_id 消费）与撤单竞态。
- **O-05 / R-07**：重启后对 SUBMITTING / UNKNOWN / 有签发无 ACK 的订单先查单；`_deadlines` 与撤单挂起集合在内存中，重启后由启动对账重建。
- **B-03**：CommissionReport 的入账口径（现在执行记录佣金 0 + 日志）。
- **R-01**：风控决定落账后调用 `submit_approved_intent`；`on_unresolved` 接 ModeManager 的 SAFE HALT。
  R-01 同时定口径：签发时核对传入的决定是该意图最新的决定、且未过期（评审 S6）。
  `submit_approved_intent` 抛任何异常（含并发时的 ConflictError / IllegalTransitionError）都不得换新决定重签，应先查状态。
- **R-07**：状态回报中的 filled_quantity 与已入账成交比对，不一致生成差异（评审 S8）。
- **迁移规范**：0003 的归属触发器只约束新插入的行；今后在已有数据的账本上加约束的迁移，先统计违规行，有违规即中止（评审 S9）。
