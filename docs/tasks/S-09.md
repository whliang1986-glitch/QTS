## S-09a：诊断包核心

`server/app/diagnostics.py`

- **先预览、再导出**
  - `build_bundle` 只在内存里生成；`Bundle.preview()` 按文件名列出每个文件和它的完整内容。
  - 确认后，再由 `zip_bytes` 打成 zip，也只在内存里。时间戳固定，同样的内容得到同样的 zip。
  - S-09a 原来有写盘的 `write_zip`；S-09b 改成直接发给客户端，服务端不写盘，就把它删了。下面评审记录里关于写盘的修复，随之不再适用。
- **全部脱敏**
  - 沿用 C-06 的 `redact` 和 `mask_text`：账户号只留前缀与后 3 位；像密钥的字段、SensitiveValue，一律替换成 ***。
  - 日志只取尾部，最多 500 行，读取不超过 2 MB，每一行都脱敏。
  - Decimal 转成字符串，时间转成 UTC。
- **不收集密钥**
  - 密钥目录下的文件，以及像凭据的文件（.pem、.key、.p12、.pfx、.kdbx、.env，或文件名像密钥），一律**报错拒绝**，不静默跳过。
  - 配置文件只收文件名和 SHA-256，不收内容：受保护配置的数值不会外流，哈希只用来核对版本。
- **只读、取数失败不中断**
  - 数据来源由调用方注入，例如模式与 HALT、最近订单、告警、最近一次对账；本模块不打开任何数据库。
  - 某个来源取数失败时，写进 `errors.json`（同样脱敏），其他来源照常打包。
- **清单**：`manifest.json` 记录生成时间、版本、Python 版本，以及全部文件名（不记操作系统：操作系统判断只能放在 server/platforms）。

## 评审修复（safety-reviewer 第一轮 REQUEST CHANGES，3 个 P1）

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 符号链接或目录联接可以把密钥目录带进来 | 原路径和 resolve 之后的路径都检查；路径本身或任一上级是链接时直接拒绝。Windows 的目录联接测试会真正执行；符号链接的测试在没有权限的机器上跳过 |
| P1 | 文件名里的账户号没有脱敏 | 文件名、zip 条目名、errors 的键全部脱敏；清单与实际文件一一对应 |
| P1 | 日志行只遮账户号；受保护配置可以当作日志传进来 | 日志的处理分三部分：<br>• 能解析成 JSON 的行走 `redact`；<br>• 其余文本把像密钥的 `键=值`、`Bearer` 令牌替换成 ***；<br>• 只接受 .log、.jsonl、.txt 后缀的普通文件，并且不能在 config/ 下 |
| P2 | 同名覆盖、保留名 | 重名报错；manifest、errors、configs 不能用作来源名 |
| P2 | 可以手工伪造 Bundle 直接写盘 | 包内容改为只读映射；写盘前校验条目名，不允许绝对路径、`..`、反斜杠 |
| P2 | 可能写进 config/，写到一半会留下半个文件 | 拒绝写进 config/；先写临时文件再改名，出错时删除半成品 |
| P2 | 读取尾部时没有上限；不带时区的时间、NaN | 读取有上限；不带时区的时间标成 `<naive>`；NaN 写成字符串，`allow_nan=False` |
| P2 | 凭据文件的黑名单不全 | 补上 id_rsa、.netrc、.pgpass、.ppk、.jks、.keystore、.gpg、.asc、.ovpn、证书等 |

第二轮 REQUEST CHANGES（1 个 P1）：带引号的键（`"api_token": "…"`、`{'password': '…'}`），以及 JSON 字符串里的 `键=值`，都会漏出密钥。修法：
- 匹配时允许键带引号，不带引号的值不跨括号，并认得转义引号；
- JSON 行逐个字符串叶子脱敏，不会弄坏 JSON；
- 半成品文件只删本次创建的；写盘改用硬链接，各个平台都不会覆盖已有文件。

- 还没有识别硬链接（`st_nlink`）；
- 被截断的来源不再是合法 JSON；

## S-09b：apid 接口

- `POST /v1/diagnostics/previews`：生成诊断包，返回全部内容（已脱敏）和 `preview_id`。
- `GET /v1/diagnostics/previews/{preview_id}/archive`：下载**预览过的那一份** zip。
- **权限与审计**：
  - 两个接口都只给 owner；
  - 都要先写审计（`diagnostics_preview`、`diagnostics_export`），写不进去就返回 503，不给内容。
- **数据来源**（`server/app/apid.py` 的 `diagnostics_builder`，都是只读）：模式与 HALT、最近订单、告警、api.db 审计，以及配置的日志文件和配置文件（只收哈希）。
- **不写盘**：
  - `PreviewStore` 把预览过的包暂存在内存里，保存 10 分钟，最多 3 份，先进先出；
  - 编号是不可猜的随机数；过期或不存在返回 404。
  - 这样不需要服务端输出目录，也就没有路径、覆盖、半成品这类问题。
- **出错**：生成失败（例如配置了不允许收集的文件）返回 503，不给部分结果，也不把原因（文件名）回给客户端。
- **内存**：已存的最多 3 份；同一时间只生成一份，正在生成时再请求返回 503。过期内容在下一次请求时才清掉。
- **审计能对上**：`diagnostics_preview`（打包前）、`diagnostics_preview_created`（带编号）、`diagnostics_export`（带编号和 zip 的 SHA-256）。

评审（第一轮 REQUEST CHANGES，2 个 P1，已修）：
- 来源里的自由文本（吊销原因、HALT 原因、告警参数）只遮了账户号，文本里的密钥会进包。现在来源和日志走同一套文本规则，并补上中文键（`密码=…`、`令牌：…`）和没有键名的令牌本体。
- 我删 `write_zip` 测试时，脚本的正则多删了 10 条与写盘无关的安全测试，任务单却还写着这些覆盖。已从提交版本恢复，这次用语法树只删 4 条写盘专属测试（可复现性那条改写成内存版）。

第二轮 REQUEST CHANGES（1 个 P1，已修）：`token=Bearer abc` 这种写法，键值规则先执行，只遮到 `Bearer` 这个词，令牌本体会留下。改成先遮 Bearer，并补了测试。同轮的 P2 也已处理：键长度和单行长度设上限（防止正则在超长文本上卡住）、脱敏后键冲突不丢数据、补了“失败后锁已释放”和“第二条审计失败”的测试、支持全角等号。

第三轮 APPROVE。同轮的 P2 已处理：超过 2 万字符的日志行整行省略，不截断（截断后 JSON 解析不了、令牌只剩半截，脱敏会变弱）。

已知限制：
- 非 JSON 行里嵌 JSON（`payload={"password": ["x"]}`）时，值不是字符串的密钥遮不住。
- **脱敏是尽力而为**：带空格的值（`password=my secret phrase` 只遮第一个词）、自然语言（`密码是 abc`）、中文引号，以及没被视为密钥键的 `Authorization: abc`，都遮不全。人工预览是最后一道关，这也是先预览再导出的意义。
- **最近一次对账报告没有收进来**：对账审计的动作名按 arch_scan 只能出现在 storage 与 risk/reconcile.py。要收进来，得改扫描规则（须 Dylan 批准）或在 risk 里加只读出口，留到以后。
- 错误说明（errors.json）保留异常原文，可能带路径；`api_audit` 带来源 IP 和令牌持有人名称。Owner 自己看没问题，交给支持人员前要看一眼（预览页有提示）。
- `ApidSettings` 的 `diagnostics_logs`、`diagnostics_configs` 默认为空，还没有接到 `processes.toml`，部署配置时再接。

## S-09c：网页诊断页（本 PR）

`web/src/pages/Diagnostics.tsx`，导航里的“诊断包”。

- **先预览、再下载同一份**：列出全部文件和内容；勾选“我已看完”后才能下载，重新生成要重新勾选。勾选是界面上的门槛，服务端不验证：持 owner 令牌和有效 `preview_id` 可以直接下载（都有审计）。
- **只给 owner**：只读令牌或身份还没确认时，只显示说明，没有按钮。
- **内容只在内存里**：不进存储、不进 URL；离开页面、退出登录、令牌失效、到期都丢弃；重新生成失败时，旧的那份也不再显示。
- **下载途中离开页面或退出**：取消请求，文件不落盘。
- **过期**：到有效期内容清掉、不能下载；服务端返回 404（过期或被更新的预览挤掉）时同样处理。
- **失败不显示成成功**：再次下载先清掉“已交给浏览器”的提示；200 但不是 zip（比如代理的网页）不存文件；预览回答结构不对时显示错误，不会让整个控制台白屏。
- **令牌**：下载用请求头带令牌，不进 URL（`client.ts` 的 `download`）。
- **提示**：页面写明脱敏是尽力而为，以及 `errors.json`、`api_audit` 里可能有什么。取不到的来源单独列出来。

补上了 S-09b 留下的缺口：`recent_orders` 用账本里真实的订单测试序列化，`status` 用真实的 HALT 模式记录（含原因文本脱敏）。

评审（第一轮 REQUEST CHANGES，4 个重要问题，已修）：
- 第二次下载失败时仍显示“已下载”；
- 退出登录后，在途下载仍会把文件存到磁盘；
- 新增的 Python 用例有两条断言空转（status 走的还是空视图，账户号本来就不在这两个来源里）；
- 失败路径（身份未确认、401、403、断网、竞态、存储）缺测试。

同轮的建议也已处理：提示改成“已交给浏览器下载”（页面无法确认文件落盘）、校验响应内容、令牌失效和到期时立刻清内容。

已知限制：
- “我已看完”只是确认动作，不验证真的看过。
- 文件全部展开显示，单个文件在页面上限高滚动；日志最多 500 行，没有另做分页。
- 客户端读取中断时，服务端的导出审计仍会记一次（审计在返回响应前写入），偏保守。
- 只测了 Playwright 的假接口（`web/tests/diagnostics.spec.ts`）和 Python 接口测试，两边没有连起来跑过。
