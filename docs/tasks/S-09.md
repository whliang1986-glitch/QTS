## 验收要点（V4.1）

诊断包脱敏，并且导出前可以预览。

## S-09a：本 PR

`server/app/diagnostics.py`

- **先预览、再导出**
  - `build_bundle` 只在内存里生成；`Bundle.preview()` 按文件名列出每个文件和它的完整内容。
  - 确认后，再由 `write_zip` 写盘。
  - 写盘的规则：目标已存在时不覆盖；时间戳固定，同样的内容得到同样的 zip。
- **全部脱敏**
  - 沿用 C-06 的 `redact` 和 `mask_text`：账户号只留前缀与后 3 位；像密钥的字段、SensitiveValue，一律替换成 ***。
  - 日志只取尾部，最多 500 行，读取不超过 2 MB，每一行都脱敏。
  - Decimal 转成字符串，时间转成 UTC。
- **不收集密钥**
  - 密钥目录下的文件，以及像凭据的文件（.pem、.key、.p12、.pfx、.kdbx、.env，或文件名像密钥），一律**报错拒绝**，不静默跳过。
  - 配置文件只收文件名和 SHA-256，不收内容：受保护配置的数值不会外流，哈希只用来核对版本。
- **只读、取数失败不中断**
  - 数据来源由调用方注入，例如模式与 HALT、最近订单、告警、最近一次对账；本模块不打开任何数据库。
  - 某个来源取数失败时，写进 `errors.json`（同样脱敏），其他来源照常打包。
- **清单**：`manifest.json` 记录生成时间、版本、Python 版本，以及全部文件名（不记操作系统：操作系统判断只能放在 server/platforms）。

## 评审修复（safety-reviewer 第一轮 REQUEST CHANGES，3 个 P1）

| 级别 | 问题 | 修法 |
|---|---|---|
| P1 | 符号链接或目录联接可以把密钥目录带进来 | 原路径和 resolve 之后的路径都检查；路径本身或任一上级是链接时直接拒绝。Windows 的目录联接测试会真正执行；符号链接的测试在没有权限的机器上跳过 |
| P1 | 文件名里的账户号没有脱敏 | 文件名、zip 条目名、errors 的键全部脱敏；清单与实际文件一一对应 |
| P1 | 日志行只遮账户号；受保护配置可以当作日志传进来 | 日志的处理分三部分：<br>• 能解析成 JSON 的行走 `redact`；<br>• 其余文本把像密钥的 `键=值`、`Bearer` 令牌替换成 ***；<br>• 只接受 .log、.jsonl、.txt 后缀的普通文件，并且不能在 config/ 下 |
| P2 | 同名覆盖、保留名 | 重名报错；manifest、errors、configs 不能用作来源名 |
| P2 | 可以手工伪造 Bundle 直接写盘 | 包内容改为只读映射；写盘前校验条目名，不允许绝对路径、`..`、反斜杠 |
| P2 | 可能写进 config/，写到一半会留下半个文件 | 拒绝写进 config/；先写临时文件再改名，出错时删除半成品 |
| P2 | 读取尾部时没有上限；不带时区的时间、NaN | 读取有上限；不带时区的时间标成 `<naive>`；NaN 写成字符串，`allow_nan=False` |
| P2 | 凭据文件的黑名单不全 | 补上 id_rsa、.netrc、.pgpass、.ppk、.jks、.keystore、.gpg、.asc、.ovpn、证书等 |

第二轮 REQUEST CHANGES（1 个 P1）：带引号的键（`"api_token": "…"`、`{'password': '…'}`），以及 JSON 字符串里的 `键=值`，都会漏出密钥。修法：
- 匹配时允许键带引号，不带引号的值不跨括号，并认得转义引号；
- JSON 行逐个字符串叶子脱敏，不会弄坏 JSON；
- 半成品文件只删本次创建的；写盘改用硬链接，各个平台都不会覆盖已有文件。

第三轮 APPROVE。剩余的事项都在 S-09b 处理：
- 只把 `build_bundle` 生成的包交给 `write_zip`，导出目录由服务端固定，并放在支持硬链接的 NTFS 或 ext4 上；
- 还没有识别硬链接（`st_nlink`）；
- 被截断的来源不再是合法 JSON；
- 按路径段名判断 config/，可能误伤部署路径。

## S-09b：之后

- **apid 接口**：只限 owner；先返回预览，再按预览结果导出下载；每一步都写审计。
- **装配数据来源**：都以只读方式接入，包括 ModeManager 的状态、最近订单与审计、告警、最近一次对账报告。
- **网页诊断页**：先预览全部内容，再导出。
- **日终报告**：当日订单与成交统计、日终对账结果、当日的 HALT 与告警，用 Markdown 和 JSON 两种格式。依赖 R-07 的日终对账。

## 测试

`tests/integration/app/test_diagnostics.py`，共 27 条（本机 26 条通过；符号链接那条因为没有权限而跳过，目录联接那条照常执行）。覆盖：
- 来源脱敏：账户号、密钥字段、SensitiveValue；Decimal 不会变成 float；
- 取数失败时记入 errors.json 并脱敏，不中断打包；
- 日志只取尾部，并且脱敏；
- 配置只收哈希；
- 像凭据的文件和密钥目录都会被拒绝；
- 来源名不合法、时钟不带时区时拒绝；
- zip 内容与预览一致、可以复现、不覆盖已有文件；
- 清单列出全部文件。

评审前测试发现了两个 bug，已修复：
- `.env` 文件没有被拦下，因为 `Path(".env").suffix` 是空的；
- 清单里漏了它自己。
