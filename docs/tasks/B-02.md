## 目标

FakeBroker 能精确注入 V4.1 11.2 中券商侧的故障；撮合内核（与 T-04 回测的 SimBroker 共用）能按 K 线撮合限价单与止损单，
并维护持仓、加权成本、已结算 / 未结算现金与佣金。

## 非目标

- 不实现 OMS、风控、对账、guardd（O、R、G 组）；本任务只提供它们验证故障场景所需的**注入手段**。
- 不实现 IBKR 适配器（B-03 / B-05），不连接任何真实券商。
- 不实现 SimBroker 适配器本身与回测循环（T-04），只提供撮合内核。

## 允许修改范围

- 可以改：`server/broker/fake/`、`server/broker/sim/`（新建）、`server/broker/base.py`（只做向后兼容的补充）、
  `pyproject.toml` 的 `[tool.importlinter]`（只新增更严的契约）、`tests/arch/test_layer_registry.py`、
  `tests/unit/broker/`、`tests/contract/`、`docs/tasks/B-02.md`。
- 不得改：`config/risk`、`config/live`、`secrets/`、其他任务的公共接口。

无。

## 接口与不变量

- `server/broker/sim/kernel.py`（纯计算，无 I/O、不读时钟）：
  - `match_bar(...)`：限价买在 `low ≤ 限价` 时成交，价格 `min(开盘, 限价)`；限价卖对称；止损卖在 `low ≤ 止损价` 时触发，
    价格 `min(开盘, 止损价)`（跳空按更差价成交）；止损买对称。按 K 线成交量的参与率限制成交量（整股，0 则不成交）。
    K 线开始时间早于下单时间时拒绝撮合（防前视）。
  - 佣金模型：`NoCommission`、`FixedCommission`（每股、最低、按成交额的上限比例），金额按分四舍五入。
  - `Ledger`：持仓（数量、加权成本，不含佣金；卖空到负数时如实显示、成本为空；成本未知的持仓加仓后仍未知）、
    已结算现金、按结算日的未结算现金；买入先扣已结算现金、不足再扣最早结算的未结算款；卖出款按结算日进入未结算，
    `settle(日期)` 转为已结算；成交更正按差额调整（等同于当初按更正值入账）；拆股 / 合股调整数量与成本；
    现金分红计入已结算；静默调整持仓（模拟券商侧变动，用于对账场景）。
- `server/broker/fake/`：
  - `FakeBrokerServer`：券商侧状态（订单、成交、账本、多个 clientId 的连接），订单号全局单调；
    事件只发给已连接的客户端（订单事件发给下单的客户端，外来事件发给全部客户端），断线期间的事件**丢失**。
  - `FakeBroker`：一个 clientId 的连接，实现 `BrokerAdapter`；`FakeBroker(account)` 仍可独立使用（B-01 契约不变）。
    server 上的下单、改单、撤单入口是私有的，只由客户端调用；券商侧撤单用 `broker_side_cancel()` 模拟。
  - 买入资金不足（购买力 − 其他未成交买单占用 < 成交额 + 预估佣金）以拒单回报（INSUFFICIENT_FUNDS），改单同样重检；
    购买力默认只算已结算现金（`buy_with_unsettled` 打开后加上未结算）。
  - 现金账户默认拒绝数量超过持仓的卖单（NO_PERMISSION）；保证金账户券商侧照收，卖空由本地风控禁止。
  - 按 K 线撮合的成交时间不早于 K 线开始；暂存的事件只投递给暂存时已连接的客户端。
  - import-linter 契约 `fake-broker-test-only`：除 backtest 外的 server 包不得导入 `server.broker.fake`。
- `base.py` 补充：`BrokerExecution.corrects`（成交更正指向被更正的 execution_id，默认空）。
- 不变量：只记录券商事实，不做风控判断；金额 Decimal；时间 UTC 且严格递增；订单与成交不删除。

## 故障场景矩阵（V4.1 11.2，M1 范围 16 项）

| # | 场景 | 本任务的注入手段 | 验证该场景通过的任务 |
|---|---|---|---|
| 1 | 已接单但响应丢失 | `lose_next_ack()`（券商已接单、无回报）、`lose_next_request()`（券商未收到） | O-01 / O-02 |
| 2 | 成交回报重复 | `duplicate_execution(execution_id)` | O-01 |
| 3 | 回报乱序（成交先于确认） | `hold_events()` + `release_events(reverse=True)` | O-01 |
| 4 | 撤单中成交、部分成交后撤单 | `manual_cancel_confirm` + `fill()` + `confirm_cancel()` / `reject_cancel()` | O-03 |
| 5 | 拒单（价格、权限、合约） | `reject_next(ErrorCategory, reason)` | O-01 |
| 6 | 提交后进程崩溃 | `drop_client(id)` 后用同一 server 新建客户端，查单 | O-04 |
| 7 | 断线重连期间状态漂移 | `drop_client(id)`；断线期间 `fill()` / `broker_side_cancel()` / 到期，事件丢失，重连后查询 | O-04 / R-07 |
| 8 | 券商重启窗口内下单 | `enter_restart_window()` / `exit_restart_window()` | O-01 / B-03 |
| 9 | 行情陈旧或缺失 | 不属于券商（D-01 / D-05 注入） | R-01 |
| 10 | 风控无响应 | 不属于券商（R-01 注入） | R-01 |
| 11 | 持仓与券商不一致 | `adjust_position(symbol, delta)`（无回报的券商侧变动） | R-07 |
| 12 | 备份恢复后首次启动 | 不属于券商（C-03 / O-04） | O-04 |
| 13 | 夏令时与提前收市 | D-03 已覆盖（日历） | D-03 |
| 14 | 磁盘写满 / 数据库锁 | 不属于券商（C-03 注入） | C-03 / O-01 |
| 15 | tradingd 心跳丢失 | 独立 clientId 的 guard 连接；`cross_client_cancel` 开关（IBKR 实测见 B-03） | G-01 / R-05 |
| 16 | 拆股或分红 | `apply_split()`、`apply_dividend()` | R-07 |

## 验收标准

- [ ] 上表中属于券商侧的每个场景都有注入测试，断言注入后的券商事实与事件

## 必须覆盖的失败场景

- [ ] 响应丢失后 `lookup_order` 能查到（已接单）或查不到（未收到），不重复建单
- [ ] 断线期间的成交在重连后只能通过查询得到，事件流不补发
- [ ] 同一 clientId 未断开时重复连接被拒
- [ ] 重启窗口内一切调用失败，窗口结束前不能重连
- [ ] 资金不足的买单被拒且不占用资金

## 移交

- **T-04**：SimBroker 适配器用 `match_bar` 与 `Ledger`，结算日用 D-03 交易日历的下一交易日（FakeBroker 默认用下一个工作日）。
- **O-01 / O-03 / O-04 / R-07**：用上表的注入手段实现各自的故障场景测试；成交更正按 `corrects` 冲正原成交。
- **B-03 / B-05 待实测清单**（本 Fake 的行为都是假设，实测后修正 Fake 与依赖它的测试）：
  1. 跨 clientId 撤单是否可行（Fake 默认不允许，`cross_client_cancel` 可打开）。
  2. 现金账户能否用未结算卖出款买入（Fake 默认不能）。
  3. 现金账户卖单的检查口径：单张卖单超过持仓是否被拒；止损单与减仓单同时挂、合计超过持仓时是否被拒（Fake 只按单张检查）。
  4. 拆股、合股时 IBKR 对挂单（尤其保护性止损）是调整、撤销还是保持（Fake 保持不动）。
  5. 断线重连后 ib_async 是否主动同步挂单与成交并产生状态事件（Fake 不补发，只能查询）。
  6. DAY 订单到期报 Cancelled 还是 Inactive / Expired（Fake 两种都能注入）。
  7. 成交更正的 execId 规则（Fake 为“原始 id.序号”）与 avgCost 是否含佣金（Fake 不含）。
  8. 错误码与 ErrorCategory 的映射（Fake 用 `FAKE-<类别>`）。
