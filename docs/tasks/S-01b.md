## 范围

- `server/ipc/protocol.py`：分帧与按对端身份分发。
  - 帧格式：4 字节大端长度 + UTF-8 JSON 对象，单帧上限 1 MiB；超限、截断、非 JSON、非对象都断开连接。
  - 一问一答，一个连接内的请求按顺序处理。
  - workerd 只能提交意图，apid 只能提交命令（命令再由交易核心按 request_id 去重）；其他请求类型和越权请求一律拒绝。
  - 回答区分三种情况：
    - 入口拒绝（refused=true，给出原因，调用方不必重试）；
    - 暂时性失败（交易核心未就绪 `NotReadyError`、内部错误；只给异常类型名，不外泄细节）；
    - 成功。
- `server/ipc/outbox.py`：workerd 侧 meta.db 待发队列与投递。
  - 存储：SQLite，WAL + synchronous=FULL；意图与回执两张表都只追加（UPDATE、DELETE 被触发器拒绝）；
    结构版本或触发器不对就拒绝打开（失败即关闭）。
  - 入队：按 intent_id 幂等，同号同内容重复入队无副作用，同号不同内容抛冲突。
  - 投递顺序：按入队顺序。遇到连接失败、协议错误、交易核心未就绪或内部出错就停下，保持顺序，留待下次重投；
    重投由交易核心按 intent_id 去重，同一意图不会下两次单。
  - 回执：交易核心作出决定，或入口明确拒绝，都写回执，不再投。
  - 过期：意图生成后超过 `max_age` 仍未投出，或生成时间超前超过 `max_age`，作废并写过期回执，不补发（V4.1 3.4“避免追单”）。
- `server/platforms/`：**平台适配层**（Dylan 2026-10-28：最终同时支持 Windows 与 macOS；协调端定 Windows 为首要平台）。
  - 唯一允许判断操作系统的地方；业务代码只经 `server.platforms.local_channel()` 拿实现。
    由 `tests/arch/test_platform_isolation.py` 用 AST 强制：sys.platform、os.name、os.uname、platform 模块在其他包里出现即失败。
  - 新增 import-linter 契约 `platforms-leaf`：平台层不依赖任何业务层；并把它加入 domain 独立、broker 白名单、FakeBroker 三条契约
    （只加层、不放宽既有规则），在 arch_scan 的 KNOWN_LAYERS 登记。
  - `windows.py`：命名管道 `\\.\pipe\<名>`。
    - 服务端：`GetNamedPipeClientComputerNameW` 必须以 ERROR_PIPE_LOCAL 失败（拒绝远程经 SMB 连入）；
      `GetNamedPipeClientProcessId` 取进程号 → 打开进程令牌 → 账户 SID。
    - 客户端：`GetNamedPipeServerProcessId` → 服务端账户 SID。
    - 首个实例用 FILE_FLAG_FIRST_PIPE_INSTANCE 独占管道名，同名已存在则启动失败（防抢占）。
  - `linux.py`：Unix 域套接字 + SO_PEERCRED（对端 pid、uid，uid 按无符号解析），双向都读凭据。
    - 套接字权限 0660；绑定前只清理本账户遗留、且无进程监听的套接字，其他文件或活着的套接字拒绝。
  - `macos.py`：每个调用都明确抛 `PlatformNotImplementedError`（不静默降级），实现移交 P-MAC。
  - `files.py`：目录上锁的平台差异（原先在 `server/data/lake.py` 里直接判断 `os.name`，按新规则挪进平台层，行为不变）。
- `server/ipc/transport.py`：与操作系统无关的通道策略。
  - 每个角色一个端点：`qts-intents` 只接 workerd，`qts-commands` 只接 apid；角色由端点决定，不信任消息里的自报身份。
  - 服务端：对端账户不在该端点的允许集合里就立即断开。
  - 客户端：`connect_role(..., server_account=…)`，服务端账户不是 tradingd 账户就断开（防冒充）。
  - **同一系统账户内的角色区分不是安全边界**：同账户进程彼此可读写内存，只能防程序错误。
    本机桌面版很可能三个进程同一个 Windows 用户，**目前没有隔离**；
    上实盘前是否给 apid / workerd 单独账户，列为待 Dylan 决定项（见移交）。
- `server/risk/core.py`：新增 `NotReadyError(IntakeError)`。“尚未完成启动”改为可重试，不再被当成永久拒绝把意图丢掉。

## 测试

- `tests/integration/ipc/test_ipc.py`：真实交易核心 + FakeBroker，socketpair 承载真实流。
  - 分帧：往返；七种坏帧；最大合法帧可收；超大帧拒发；坏帧断开且不回答。
  - 分发：workerd 意图到达核心并得到决定；角色互换被拒，且越权命令没执行；未知类型被拒；apid 命令到达核心并按 request_id 回放；
    四种畸形意图、四种畸形命令被拒；拒绝原因原样带回；未就绪是暂时性失败；内部错误只给类型名；同一连接并发请求按序；对端挂断时抛出。
  - outbox：
    - 入队：幂等且有序；同号不同内容冲突；重开后仍在；
    - 只追加：四条 SQL 被拒；回执只写一次；
    - 失败即关闭：未知结构版本、被删触发器、打不开的路径；
  - 投递：
    - 端到端写回执；回答丢失后重投，不重复下单（券商挂单数与风控决定数不变）；
    - 六种暂时性失败都停下并保持顺序；
    - 拒绝写回执、不重试；
    - 过期：过期作废、超前不多的照常投、恰好 max_age 照常投、超前太多作废；max_age 必须为正；
    - 交易核心未启动时意图留在队列，启动后投递成功。
- `tests/integration/ipc/test_transport.py`：用当前系统的真实平台实现跑（本机 Windows 命名管道已跑通；
  Linux 套接字**只在 CI ubuntu-latest 上跑**，本机无 Linux 环境）。
  - 意图端点只收意图、命令端点只收命令，越权请求不到达核心；未登记账户被断开；客户端拒绝冒充的 tradingd；
    第二个实例不能抢占活着的端点且第一个仍可达；一个端点服务多个客户端；连不存在的端点报错。
  - 各平台：每个角色端点不同；空允许集合被拒；macOS 明确未实现；在错误平台上实例化别的平台实现会报错。
- `tests/arch/test_platform_isolation.py`：业务代码不判断操作系统（含检测器的正反用例）；平台层叶子契约齐全。
- 变异测试（scratchpad `mutate_ipc.py`）：protocol / outbox / transport 共 24 个变异。
  - 22 个被杀死。
  - “ok 不严格”起初存活：补了“ok 不是严格 true 当作异常回答”的用例后杀死。
  - “意图字段缺失判断改为只判 None”存活：等价变异，非字符串在后续校验仍被拒。
  - 只在 Linux 运行的套接字用例相关变异，本机无法执行，未做。
- 全套：见最终报告。

## 未做 / 移交

- **待 Dylan 决定（G 门材料）**：同一账户内的角色区分不是安全边界；上实盘前是否给 apid / workerd 单独的系统账户。
  在此之前文档与界面不得表述为“已隔离”。
- Windows 已知限制：按进程号查令牌，进程号在极短时间内被复用的情形不能完全排除；管道用 asyncio 默认安全描述符
  （非属主、非管理员只能读不能写），没有另设 DACL。
- Windows 其余已知限制（第二轮评审 P2）：
  - 远程客户端只靠 `GetNamedPipeClientComputerNameW` 一道防线；asyncio 建管道时没带 PIPE_REJECT_REMOTE_CLIENTS。
    以后改为自己调 CreateNamedPipeW，加 PIPE_REJECT_REMOTE_CLIENTS 与显式 DACL。
  - 依赖 asyncio 未公开的 `start_serving_pipe` / `create_pipe_connection`：accept 循环遇到异常会停止接受新连接；
    客户端遇到 ERROR_PIPE_BUSY 会一直重试。S-01c 的进程入口要给 `connect_role` 加超时，并监控 accept 循环。
  - 分账户部署时有三处走不通（会失败即关闭），属于“是否分账户”决定的一部分：
    - 默认 DACL 不给其他账户读写；
    - 客户端查另一账户进程的令牌通常被拒（可改为服务端 ImpersonateNamedPipeClient）；
    - 客户端连接没带 SECURITY_SQOS_PRESENT|SECURITY_IDENTIFICATION。
- Linux：绑定前检查与绑定之间有竞态（asyncio 会无条件删除已有套接字）。S-01c 在运行目录加单实例文件锁（放平台层）。
- macOS：P-MAC（docs/tasks/P-MAC.md，计划后段：launchd、macOS 身份核验、CI macos-latest、Tauri 苹果版）。
- 过期作废“记审计”：V4.1 3.4 要求写审计，而其他进程的审计要经同一通道补交 ledger.db，这条通道尚未实现。
  目前过期只写 outbox 回执与告警日志，审计补交留给后续任务。
- **S-01c 验收条件（来自本任务评审）：**
  - tradingd 入口按 created_at 限龄（限值若属风控参数由 Dylan 定），DAY 意图跨交易日作废（用交易日历）；
  - 各端点的允许账户集合与 tradingd 账户从系统服务配置读取；Linux 套接字目录属主 tradingd、0750；
  - workerd 只跑一个投递循环。
- S-01c 进程入口：
  - workerd 用 `Outbox` + `deliver_pending` 周期投递，`max_age` 由策略频率决定，日线建议数分钟；
  - tradingd 对两个角色各调一次 `serve_role(local_channel(), …)`；apid / workerd 用 `connect_role`；
  - apid 的操作者身份在 S-02 / S-03 鉴权后填写，tradingd 不信任自报的 actor 以外的任何字段。
