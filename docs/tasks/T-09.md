## 背景

V4.1 第 8.4 节定义了策略生命周期，第 9 章写明 AI 只能写“实验与候选策略”。但计划里没有任务负责策略库本身，
也就是策略定义、不可变的版本历史、生命周期阶段的权威存储，以及候选区。本任务补上这一块。

## 目标

- 策略定义注册：代码哈希加参数集构成不可变的版本，修改只能新建版本，旧版本保留（StrategyVersion，C-01）。
- 生命周期阶段按 8.4 存储：Idea → Hypothesis → Data Audit → Baseline → Backtest → Robustness → Paper → Review → Limited Live → Monitored Production → Retire。
  - 只能经 T-08 发布门禁晋级；进入 Paper 及之后的阶段，还需要 Dylan 审批；
  - AI 只能写入“候选”阶段（Idea / Hypothesis），不能批准，也不能晋级自己（V4.1 第 9 章）。
- 候选区：AI 或手动提出的策略进入候选，必须先完成回测与稳健性评估，才能往前走。
- 每次晋级都保存证据：数据版本（D-07）、commit、参数、成本模型、评测结果、审批人、退出条件。
- 交易核心只接受处于获批阶段的策略版本的意图，接到风控的策略级规则上，失败即关闭：查不到的版本一律拒绝。
- 界面展示归 S-05 的“策略中心”。

## 仓位控制原则（Dylan 2026-11-04 确认，策略库与风控面板都要遵守）

- 日常仓位由策略按规则自动计算，再经风控与 OMS 执行。
- Dylan 只在风控面板设置上限（单只持仓、总仓位、现金底线：调严立即生效，调松须二次确认并留记录），以及踩刹车（停止新增风险、撤单、紧急平仓）。
- 不提供逐笔手动调仓的入口。策略库的“候选”和“晋级”只改变策略版本的阶段，不能直接下单或改仓位。
- 资金阶梯只会自动降级，升级须 Dylan 批准。

## 手动添加、停用、删除（2026-11-04 补充，与因子库 T-10 同一套做法）

1. **手动添加**：在策略库页面新建策略，有两种方式：
   - 从现成模板配参数（例如动量轮动、均线趋势：标的池、调仓频率、持有数量）；
   - 代码式策略作为普通开发任务提交，经评审与测试。
   新建的策略一律从“候选”阶段开始，自动跑回测、稳健性检验，再经 T-08 门禁与模拟盘才能晋级。
2. **停用**：随时可以停用，立即生效。停用后不再产生新意图（交易核心按阶段拒绝）；已有持仓按策略的退出规则处理，或由 Dylan 人工处理。
3. **删除**：必须先停用。删除等于归档隐藏，一律不物理删除：历史版本、回测与稳健性报告、试验次数（多重检验要用）、订单与成交记录全部保留，按策略 ID 仍可追溯。被删除策略的 ID 不再复用。
4. **修改**：改参数或代码就是新建一个版本，旧版本保留；新版本同样从候选开始验证。
5. **权限**：添加、停用、删除只有 owner 能做，操作者取令牌身份，每一步写只追加记录与审计。AI 只能提议候选，不能晋级、停用或删除。
6. **不下单**：添加、晋级、停用只改变策略版本的阶段，不能直接下单或改仓位；交易仍经过交易名单与风控（S-14 第一节的三层定义）。

验收补充：
- [ ] 未停用的策略不能删除；删除后列表隐藏，但历史记录、报告、订单、成交、试验次数仍可查
- [ ] 删除后同一策略 ID 不能重新创建
- [ ] 添加、停用、删除只有 owner 能做，写审计；AI 路径没有删除与晋级入口
