# 运行手册：备份与恢复演练（S-08）

## 每日（盘后，由调度运行；首次接入前可手动执行）

1. 生成备份：`ledger`、`meta`、`api` 三个库，`config/`、`research/`、`backtests/` 三个目录，以及行情湖的 manifest。
2. 确认备份已通过校验。`create_backup` 内部已经校验过；失败会报 `BackupError`，必须告警。
3. 复制到异地副本（位置待定），并在目标处再校验一次。
4. 按保留份数清理旧备份。

## 每月：恢复演练（G4 / G6 要求）

1. 准备一台干净机器，或一个空目录。不要恢复到正在运行的数据目录。
2. 执行 `restore_and_halt(<备份目录>, <空目录>)`。它会先校验备份，再恢复，最后写入 SAFE HALT。
3. 用恢复出的数据目录启动服务，确认：
   - 运行状态为 SAFE HALT，不接受新的交易意图；
   - 启动对账完成。备份时刻之后券商侧的成交、撤单、公司行动都会以差异的形式出现，逐项核对、解释。
4. 对账通过后，由 Dylan 人工恢复。恢复命令需要确认。
5. 把演练结果写进 `docs/gates/`：备份时刻、恢复用时、对账差异及处理、恢复人。

## 注意

- 恢复目标必须是普通的空目录，或尚不存在的路径；不能是挂载点或盘符根目录。
- 备份的账本表结构落后于当前代码时，写入 SAFE HALT 可能失败，导致恢复失败（失败即关闭）。
  处理方法：先用同版本代码恢复，或在空目录里对恢复出的账本执行迁移（`server.storage.migrate.upgrade`）后再写 HALT。

- 备份不能代替券商对账：恢复出的账本可能落后于券商。
- `secrets/` 不在备份里。新机器上的密钥由 Dylan 按密钥管理流程（C-05）重新配置。
- 损坏的备份会被拒绝恢复，此时改用上一份备份，并排查损坏的原因（磁盘、复制过程）。
