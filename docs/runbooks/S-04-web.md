# 运行手册：Web 客户端（S-04）

## 开发与测试

```
cd web
npm ci
npm run typecheck
npm run build
npm run test:e2e
```

- 依赖版本全部写死，锁文件是 `web/package-lock.json`；改了依赖要连锁文件一起提交。
- 端到端测试拦截所有 `/v1` 请求，返回假数据，不连真实的 apid。
- 测试用本机已装的 Edge 跑。换浏览器时设置环境变量 `PW_CHANNEL`，例如 `chrome`。

## 本机试用

1. 启动 apid（S-03），并签发一个令牌：`python -m server.app token issue ...`。
2. `cd web && npm run dev`，打开 http://127.0.0.1:5173 。开发服务器会把 `/v1` 转发到 127.0.0.1:8730。
3. 输入令牌登录。令牌只存在当前标签页里（sessionStorage），关闭标签页即清除。

## 界面约定

- 顶部模式标识只有三种：PAPER、HALT、未知。连不上服务器、账本读不了、令牌失效时，一律显示“未知”，并提示“数据可能已过期，服务器仍在运行”。
- 急停是四个独立的控件。撤保护性止损和紧急平仓属于高危操作，需要两道确认：先由客户端自动申请二次确认，再由你逐字输入确认短语。
- 命令结果未知（504、断网、超时）时，只能点“用同一编号重试”，不会换编号重发。
  - 关闭面板、切换页面都不会丢编号；结果未知的那个控件会自动展开。
  - 刷新页面会丢掉编号（只存在内存里）：刷新前请先查看状态。要开始新的操作，必须先点“放弃这次操作”，因为上一次可能已经执行。
- 撤保护性止损的确认短语是：`确认撤销全部保护性止损`（tradingd 逐字核对）。紧急平仓的确认短语由预览给出，每次都不同。
- 二次确认号由客户端在你点“确认执行”时自动申请。人工确认是这三步：展开控件、输入确认短语、点“确认执行”。
- 令牌失效（401）时，会清除令牌并回到登录页。身份确认之前，不显示任何命令控件。
- 净值、现金、持仓、敞口目前显示“暂无数据”：要等 tradingd 发布账户快照后才有数据。
