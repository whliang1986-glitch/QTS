# 运行手册：手机告警与外部心跳（S-07）

## 告警分级

| 级别 | 例子 | 去向 |
|---|---|---|
| P0 | tradingd 心跳丢失、guardd 撤单失败、疑似重复下单、账户状态未知、实盘误切换、急停失效、保护性止损缺失 | 日志、面板、手机；确认之前每 5 分钟重复提醒 |
| P1 | 券商断线、行情严重陈旧、对账不一致 | 日志、面板、手机（推送一次） |
| P2 / P3 | 一般提示 | 只进日志和面板 |

- **确认**：确认只停止重复提醒，不会解除风险状态。HALT 要按恢复流程处理。
- **解除**：风险确实消失后（例如 tradingd 心跳恢复），由检测方自动解除告警；同一问题再次发生时会重新告警。
  确认以后，检测方每轮还会照常上报，但不会再推送。
- **确认入口**：面板里的确认按钮在 S-05（日志与告警页）做，经 apid 转给 guardd 的通道随 S-05 一起设计。
  在那之前，P0 会一直提醒，直到风险解除。
- **时限**：“1 分钟内送达”从检测到故障算起。tradingd 停下后，guardd 最长要 90 秒（心跳超时）加上一个检查间隔（15 秒）才能发现，
  所以从 tradingd 停下到手机收到推送，大约需要 2 分钟。
- **重复告警**：同一个问题在解除之前只算一条（不论是否已确认）；解除之后如果再次发生，会重新告警。
- **限速**：推送最多每分钟 20 条，超出部分顺延发送，不会丢。

## Telegram（Dylan 2026-11-04 选定）

1. 用 @BotFather 创建机器人，拿到机器人令牌。把机器人加进你的私聊或群组，再查出 chat_id（数字，群组的是负数）。
2. 令牌由你本人录入系统凭据库，服务名 `qts`，条目名 `telegram_bot_entry`。录入方法见 `docs/runbooks/protected-config-change.md`。令牌不写进任何文件，也不进日志或聊天。
3. chat_id 不是密钥，写进普通配置（接入配置文件时补上）。
4. 做一次演练：模拟 tradingd 心跳丢失，1 分钟内手机应收到 [P0] 推送（G4 要求）。

手机渠道配好之前，告警只写日志，健康状态显示“手机通路不可用”。这期间交易照常，但 G4 门禁不会放行。

## 外部心跳

- 在外部的“死人开关”服务（例如 healthchecks.io）建一个检查项，周期 1 分钟，宽限 3 分钟，告警发到你的手机。
- 把它的 ping 地址交给 guardd：地址必须是 https；如果地址里带私密路径，按凭据处理。之后 guardd 每分钟访问一次。
- 服务器断电或断网时，外部服务收不到 ping，会直接通知你。这条通路不经过本机。
- ping 失败只记日志，不影响交易。外部心跳在后台线程里运行，guardd 一启动就开始，在连接券商之前。
- 券商长时间断线时，guardd 会按崩溃退出，再由守护进程退避重启。每次重启都会推送一条 P1“券商连接断开”（同一进程内才会去重）。
  guardd 每次启动都会先发一次外部心跳，再连券商；重启退避最长 60 秒。外部服务的宽限期设 3 分钟，一般不会误报“服务器失联”，但不能完全排除。
- 撤单失败的 P0 会在 tradingd 心跳恢复时自动解除。这只说明 tradingd 回来了，不代表那几笔没撤掉的单已经处理好：请在面板或券商端核对。
