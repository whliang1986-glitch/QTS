# 操作清单：联调前的三件准备（F-05）

这份清单给 Dylan 本人照着做。做完这三件事，IBKR 的真实联调（B-03、B-04、B-05）就能开始。
每一步都写了“看到什么算成功”和“出错了怎么办”。

## 先记住四条规矩

1. **只用模拟账户（Paper Trading）。** 系统在 G4 之前不连实盘，代码也只放行模拟盘端口 7497。
   实盘端口（TWS 7496、IB Gateway 4001）不论什么模式都拒绝连接。
2. **密码、令牌不发到聊天里，也不发给 Ada。** 机器人令牌只录进本机的 Windows 凭据管理器（见第三部分）。
   IBKR 的用户名和密码只在 TWS 的登录框里输入，不写进任何文件。
3. **账户号码不要整串发出来。** 模拟账户号以 `DU` 开头。需要说明时只说后四位，例如“DU…1234”。
4. **要花钱的事由你决定。** 行情订阅有月费，订哪一档由你定。下面只写系统的最低要求。

---

## 第一部分：IBKR 模拟账户 + TWS + 打开 API

> 先用 TWS（带界面，方便你看到系统在做什么）。以后稳定了再换成 IB Gateway 加 IBC 自动登录。

### 1.1 开通模拟账户

1. 用浏览器登录 IBKR 的客户端门户（Client Portal），用你的真实账户登录。
2. 打开 设置 → 账户设置，找到“模拟交易账户”（Paper Trading Account），点“配置”或“申请”。
3. 按提示给模拟账户设一个用户名和密码。这套用户名和密码和真实账户不同，请单独保管。

- **看到什么算成功：** 页面上显示模拟账户的用户名和以 `DU` 开头的账户号。
- **出错了怎么办：**
  - 找不到这个入口：真实账户需要先完成开户并入金，模拟账户才能开。可以联系 IBKR 客服，说要“Paper Trading Account”。
  - 显示“处理中”：一般在一个工作日内生效，第二天再登录看看。

### 1.2 安装 TWS 并用模拟账户登录

1. 从 IBKR 官网下载 TWS，安装在要跑交易系统的那台电脑上。选“稳定版”（Stable）。
2. 打开 TWS。登录框里选择“Paper Trading”（模拟交易），输入第 1.1 步设的模拟账户用户名和密码。

- **看到什么算成功：** TWS 窗口顶部或标题栏有红色的“PAPER”“模拟交易”字样，账户号以 `DU` 开头。
- **出错了怎么办：**
  - 登录时提示用户名或密码不对：确认用的是模拟账户那一套，不是真实账户的。
  - 登录后没有 PAPER 字样：说明登进了真实账户，**立刻退出**，重新登录并选 Paper Trading。

### 1.3 打开 API 并设置端口

在 TWS 里：菜单 文件（File）或 编辑（Edit）→ 全局配置（Global Configuration）→ API → 设置（Settings）。逐项设置：

| 设置项 | 要设成 | 为什么 |
|---|---|---|
| Enable ActiveX and Socket Clients（启用 Socket 客户端） | 勾选 | 系统通过它连 TWS |
| Socket port（端口） | `7497` | 模拟盘端口；系统只认这个 |
| Allow connections from localhost only（只允许本机连接） | 勾选 | 外网和局域网都连不进来 |
| Read-Only API（只读 API） | **先勾选** | B-03、B-04 只读联调期间不允许下单；到 B-05 我会先告诉你，再由你取消勾选 |
| Master API client ID | 留空 | 系统不用主客户端 |
| Trusted IPs（可信 IP） | 只有 `127.0.0.1` | 同上 |

然后：全局配置 → 锁定与退出（Lock and Exit），把“自动重启”（Auto restart）时间设在美东时间半夜，
例如 23:45。IBKR 每天都要重启一次，设成自动重启可以避免第二天要手动重新登录。

点“应用”（Apply）和“确定”（OK）。

- **看到什么算成功：** 重新打开 API 设置，能看到端口 7497、两个勾选项都还在。
- **出错了怎么办：**
  - 端口改不了或保存后又变回去：先退出 TWS 再重开，重新设置一次。
  - 找不到这些选项：TWS 版本太旧，从官网重新下载稳定版。
  - 以后系统连接时，TWS 可能弹窗问“是否接受来自 127.0.0.1 的连接”，点接受即可。弹窗里不是 127.0.0.1 的一律拒绝，并告诉 Ada。

### 1.4 告诉 Ada

只需要在聊天里说一句：“模拟账户和 TWS 好了，端口 7497，只读已勾选，账户后四位是 xxxx。”
不要发用户名、密码或完整账户号。

## 第二部分：模拟账户的实时行情权限

**为什么必须有：** 系统下单前要检查行情是不是 5 秒内的新数据。没有实时行情，只有延迟 15 分钟的行情，
这道检查会拒绝全部订单（这是有意的，宁可不交易也不用旧价格）。所以这一项是硬条件，G2 门禁会核对。

### 2.1 在真实账户上订阅美股行情

1. 登录客户端门户 → 设置 → 用户设置（User Settings）→ 市场数据订阅（Market Data Subscriptions）。
2. 第一次订阅会要你填“非专业用户”（Non-Professional）身份问卷，并签几份交易所的数据协议。
   如果你是个人投资者，按实际情况选“非专业”即可，专业用户的费用高很多。
3. 选一个包含美国股票和 ETF 实时行情的套餐，例如美股基础行情包。
   系统交易的是 SPY、QQQ、IWM、EFA、TLT、GLD 这几只 ETF，有美股和 ETF 的实时报价就够了，不需要期权、期货或国际行情。
   具体选哪一档、每月多少钱，由你决定。

- **看到什么算成功：** 订阅列表里出现你选的套餐，状态是“有效”（Active）。
- **出错了怎么办：**
  - 提示账户余额不足：行情费从账户里扣，需要有足够的现金余额。
  - 状态一直是“待处理”：通常次日生效。

### 2.2 把行情共享给模拟账户

模拟账户本身不能单独订阅行情，要从真实账户共享过去。

1. 客户端门户 → 设置 → 账户设置 → 模拟交易账户。
2. 把“与模拟账户共享实时行情”（Share real-time market data subscriptions with paper trading account）设为“是”。
3. 保存。一般要等到下一次登录，有时最多要 24 小时才生效。

- **看到什么算成功：** 用模拟账户登录 TWS，打开 SPY 的报价。
  价格在交易时段内（北京时间晚上 9:30 或 10:30 以后，视夏令时而定）不停跳动，旁边**没有**“延迟”（Delayed）标记。
- **出错了怎么办：**
  - 报价旁边写着 Delayed，或价格颜色和平常不一样：共享还没生效，第二天再试；仍然不行，回到 2.2 检查开关。
  - 提示“Requested market data is not subscribed”（未订阅）或错误码 354、10167：订阅或共享没成功，回到 2.1 和 2.2 检查。
  - 行情时有时无：IBKR 同一时间只给一个登录会话推送行情。如果你同时在手机 App 或另一台电脑上登录了**真实账户**，
    模拟账户的行情可能被挤掉。交易系统运行期间，看行情请尽量用这台电脑上的 TWS。

### 2.3 告诉 Ada

在聊天里说一句：“模拟账户 SPY 有实时报价，不是延迟的。”最好附一张截图，截图里遮住账户号。

## 第三部分：Telegram 告警机器人

系统出 P0、P1 问题（例如 tradingd 心跳丢失、券商断线）时，会推送到你的 Telegram。G4 门禁要求做一次演练：
模拟故障后 1 分钟内收到推送。

### 3.1 创建机器人，拿到令牌

1. 在 Telegram 里搜索 `@BotFather`，认准带蓝色认证标记的官方账号。
2. 发送 `/newbot`，按提示起名字。最后一步的用户名必须以 `bot` 结尾，例如 `dylan_qts_alert_bot`。
3. BotFather 会回复一段令牌，样子类似 `123456789:AAH...`。

- **看到什么算成功：** 收到 BotFather 的回复，里面有令牌，还有机器人的链接。
- **出错了怎么办：** 提示用户名已被占用，换一个名字。
- **重要：** 这段令牌等于机器人的密码。**不要发到聊天里，也不要发给 Ada，不要截图，不要存进文本文件。**
  万一泄露了，在 BotFather 里发 `/revoke` 作废，再生成新的。

### 3.2 把令牌存进 Windows 凭据管理器

1. 在项目目录（`C:\Users\whlia\Desktop\量化自动交易系统`）打开 PowerShell。
2. 运行下面这行命令。它会提示你粘贴令牌，粘贴时屏幕上**不会显示**任何字符，这是正常的。粘贴后按回车：

   ```powershell
   uv run python -c "import getpass, keyring; keyring.set_password('qts', 'telegram_bot_entry', getpass.getpass('粘贴机器人令牌（不会显示）: ').strip()); print('已保存')"
   ```

3. 再运行这一行，检查是否存好。它只显示长度，不显示令牌本身：

   ```powershell
   uv run python -c "import keyring; v = keyring.get_password('qts', 'telegram_bot_entry'); print('已存好，长度', len(v)) if v else print('没有找到')"
   ```

- **看到什么算成功：** 第一条显示“已保存”，第二条显示“已存好，长度 46”左右（长度在 40 到 50 之间都正常）。
  也可以打开 控制面板 → 凭据管理器 → Windows 凭据，在“普通凭据”里看到一条和 `qts` 有关的记录。
- **出错了怎么办：**
  - 提示找不到 `uv`：关掉 PowerShell 重新打开再试。
  - 第二条显示“没有找到”：重新运行第一条命令。
  - 粘贴后什么都没发生：在 PowerShell 窗口里点一下右键试试，右键就是粘贴。
  - 令牌输错了：直接再运行一次第一条命令，新的会覆盖旧的。
- 这个令牌只存在这台电脑的系统凭据库里，交易系统运行时从这里读取，不写进任何文件，也不进日志。

### 3.3 查出 chat_id

chat_id 是你和机器人这个对话的编号，不是密钥。

1. 在 Telegram 里打开你的机器人（点 BotFather 给的链接），点“开始”（Start），再随便发一句话，例如“你好”。
2. 在同一个 PowerShell 里运行这一行。它用凭据管理器里的令牌去问 Telegram，只打印 chat_id，不打印令牌：

   ```powershell
   uv run python -c "import json, keyring, urllib.request as u; t = keyring.get_password('qts', 'telegram_bot_entry'); r = json.load(u.urlopen('https://api.telegram.org/bot' + t + '/getUpdates', timeout=10)); print('chat_id：', sorted({x['message']['chat']['id'] for x in r.get('result', []) if 'message' in x}) or '没有找到，请先给机器人发一句话')"
   ```

- **看到什么算成功：** 显示类似 `chat_id： [123456789]` 的一串数字。私聊是正数，群组是负数。
- **出错了怎么办：**
  - 显示“没有找到”：先在 Telegram 里给机器人发一句话，过几秒再运行。
  - 报错里有 `401` 或 `Unauthorized`：令牌不对，回到 3.2 重新录入。
  - 报错里有超时或连接失败：电脑可能连不上 Telegram，请检查网络或代理。这一点很重要：服务器连不上 Telegram，告警就发不出去，请告诉 Ada。
  - **不要**用浏览器打开带令牌的网址来查，那样令牌会留在浏览器历史记录里。

### 3.4 告诉 Ada

在聊天里只发 chat_id 这串数字（它不是密钥），再说一句“令牌已存进凭据管理器”。
Ada 会把 chat_id 写进配置，然后和你一起做一次推送演练。
