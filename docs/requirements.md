# 需求与决策纪要（摘要）

来源：项目中的“需求与决策纪要”文档（2026-10-21，Dylan 确认）。本文是开发用摘要，冲突时以纪要原文与 Dylan 的最新决定为准。

## 已确认的范围

| 事项 | 决定 |
|---|---|
| 券商 | 先接 IBKR，以后再加其他券商；所有券商调用隔离在统一接口（BrokerAdapter）后面 |
| 开户与入金 | 不在系统内，全部在券商自己的 App 完成 |
| 系统职责 | 收集市场资讯、分析研究、制定策略、下达买卖指令，并实时查看账户动态 |
| 形态 | 最终打包成桌面应用；下单核心作为后台服务常驻，桌面应用只做界面 |
| 时间基准 | 一律以美股交易时段为准，调度由交易日历驱动 |
| 首期交易范围 | 美股与 ETF 现货、日线低频、仅多头、无杠杆，先在 IBKR 模拟盘跑通 |
| 优先级 | 安全可靠第一，工期其次 |

## 2026-10-22 新增决定

- 客户端做成正常的原生桌面 App（Tauri，同一套 Web 前端）；后台下单核心是独立常驻服务，App 启动时接入或拉起，
  最小化、关闭都不影响订单与风控（ADR-04 修订）。
- IBKR 先用 TWS：TWS 打开时由后台服务自动连接；模拟模式只连模拟盘端口并核对模拟账户 ID，绝不误连实盘；
  IB Gateway + IBC 无人值守降为后续可选（ADR-06 修订）。
- 账户已就绪但尚未订阅实时行情；Dylan 会在模拟验证前订阅。开发期可用延迟行情（仅 PAPER，开关打开时拒绝实盘），
  G2 仍以实时行情为硬条件（ADR-06 修订）。
- 账户目前是现金账户，以后升级为保证金账户。真实类型以 IBKR 返回为准；界面可一键切到更严口径，放宽只能改受保护配置
  并重启且须与真实类型一致；检测到类型变化进入 SAFE HALT 等待人工确认；首期即使是保证金账户也杠杆 1.0、不做空、
  不做衍生品（ADR-15 修订）。

## 策略库与 AI 创建策略

- 策略库中每个策略都有版本；可手动添加或改参数，也可让 AI 分析并创建候选策略。
- AI 只能提议，不能批准。候选策略依次通过回测、稳健性检验、至少几周模拟盘，最后由 Dylan 批准才能上实盘。
- 防过拟合是硬性要求，由系统自动强制：封存 AI 看不到的保留数据、先写假设再回测、登记全部试验次数并据此打折
  （Deflated Sharpe、PBO）、限制参数个数、参数扰动与成本加倍检验、前向模拟盘作为最终裁判。
- AI 优先用预先做好的积木（指标、信号、仓位规则）组合策略，写新代码须经人工审查。

## 开发方式

- 以《V4.1 开发计划》为蓝本，按任务包和门禁（G0–G9）推进，P0 任务由 Dylan 批准计划并验收。
- M1 之前先做一次策略研究，确认基准策略扣除成本后值得自动化；增加“经济门禁”：策略要跑赢买入持有 SPY 才考虑上实盘。
- 不触碰实盘：G4 之前不接实盘账户，实盘需 Dylan 逐项批准。
