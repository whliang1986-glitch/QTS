## 摘要
从零开发。最早可上线测试的版本（IBKR 模拟盘端到端跑通）约需 9–15 周；含回测与 AI 指挥中枢的完整系统，单人加 Claude Code 串行约需 24–26 周，双线并行可压到约 15–17 周。
形态： 服务器常驻交易核心 + 瘦客户端（Web 界面，可选桌面壳）。行情、账本、审计、研究等全部数据存放在你的本地服务器，客户端不持有数据库和任何密钥。
首期范围： 美股与 ETF 现货、日线低频、仅多头、无杠杆。AI 不进入首期，待模拟盘跑稳后再接入。
工作量： 70 个任务包、约 105.5 个工作日（其中 45 个为 P0），另有 10 道阶段门禁，每道都需要你审阅证据后放行。
你的投入： P0 任务各需审批计划和验收报告，合计约 26–36 小时，按每天 30–60 分钟审阅估算；风控参数、实盘授权等决策只有你能做。
实盘： 不是开发完成的自然结果。必须通过 G7 门禁，并由你逐项批准账户、策略、限额和时间窗。
开工前需确认： 第 16 章列出 10 项待确认事项，最紧的三项是服务器设备、回测数据供应商、IBKR 账户（含账户类型与实时行情权限）。
本方案从零开发，不再依赖旧的 Codex 代码；旧代码只作为需求参考。
## 1. 目标、范围与非目标
首期目标只有一个：在你的本地服务器上，让一套确定性策略在 IBKR 模拟盘里全自动、可对账、可急停地跑起来，其余一律后置。
核心目标
覆盖行情、研究、策略、回测、组合、风控、执行、对账、监控和审计的本地交易工作台。
在预先授权的账户、策略、资产和风险预算内可无人值守运行；不得自行提高限额、发布未批准策略或扩大资产权限。
每笔交易都能追溯到数据快照、策略版本、风控决策、订单链路和最终成交。
券商、数据源、模型供应商都可替换，业务逻辑不绑定任何一家的专有接口。
范围分期

非目标
不做高频交易、交易所共置或低延迟基础设施。
不使用 Docker，不依赖 OpenClaw。
首期不支持做空、杠杆、衍生品；这些在风控层默认硬性禁用。
不允许 LLM 执行任意 shell、SQL、券商 API 或修改风控配置。
不以单次回测收益、模型自评或多模型投票作为实盘批准依据。
不承诺收益；系统只提供研究与执行工具，任何策略上线都需你审批并持续监控。

## 3. 总体架构
服务器上常驻四个进程加 IB Gateway，客户端只经 apid 访问。tradingd 是唯一能下单、唯一写账本的进程；回测、模拟盘、实盘共用同一份 OMS 与风控，只换券商适配器。
### 3.1 进程划分
| 进程 | 职责 | 写入 | 明确不能做 |
| tradingd | 独占交易 clientId 连接券商；数据门禁 → 风控 → OMS；对账、急停、ModeManager；审计事件的唯一入口；命令与意图去重 | ledger.db | 不运行策略与 AI，不托管客户端会话 |
| apid | 认证、REST + WebSocket；把命令经 ADR-14 的通道交给 tradingd | api.db（会话、令牌、客户端设置，不含任何交易数据）；对 ledger.db 只读 | 不连券商，不直接改订单与限额 |
| workerd | DataJob、回测、策略运行器、研究库、AI（M3）；意图经 outbox 投递 | meta.db（含意图待发队列）、数据湖、研究库 | 不连券商；对 ledger.db 只读；策略只能提交意图 |
| guardd | 看门狗与外部心跳；独立 clientId，只能逐单撤销未成交的开仓单 | 自己的滚动日志 | 不平仓，不下新单，不撤保护性止损单，不使用全局撤单 |
| IB Gateway + IBC | 券商网关；IBC 负责自动登录与每日重启 | 无 | API 端口不对外，只绑 127.0.0.1 |
| 客户端 | 显示与遥控（Web、手机浏览器、可选 Tauri 壳） | 无 | 不持有数据库、券商密钥、模型密钥 |
### 3.2 一笔订单的路径
workerd 里的策略按交易日历生成目标仓位，输出带幂等键 intent_id 的 OrderIntent，先写入 outbox，再投递给 tradingd。
tradingd 先过数据门禁：行情新鲜度、规格、账户同步。
预交易风控给出 ALLOW、REDUCE、REJECT 或 HALT；风控不可用时不放行。
OMS 登记状态机与幂等键，先持久化 orderId，再经 BrokerAdapter 提交。
回报按 execution_id 去重后入账；超时进入 UNKNOWN，先查券商再行动。
状态经 apid 推送给客户端；日终与券商对账。
### 3.3 同一条代码路径，换出口
| 场景 | 行情 | 券商适配器 | OMS 与风控 | 记录去向 |
| 回测 | 历史数据湖，绑定数据版本 | SimBroker（撮合内核与 FakeBroker 共用） | 同一份代码；OMS 在 workerd 内以内存 Repository 运行（T-04） | Parquet 回测明细，不写 ledger.db |
| 故障测试 | 脚本化 | FakeBroker，可精确注入 11.2 的故障场景 | 同一份代码 | 测试库 |
| 模拟盘 | IBKR 实时行情（G2 硬条件：模拟账户必须拿到实时行情） | IBKR 适配器，模拟账户 | 同一份代码 | ledger.db，标记 PAPER |
| 实盘 | IBKR 实时行情 | IBKR 适配器，实盘账户，启动时校验账户 ID | 同一份代码 | ledger.db，标记 LIVE |
只有 oms 能调用 broker 的下单接口，任何包都不能绕过 risk 向 oms 提交订单；这两条由第 4 章的架构测试在 CI 中强制。
### 3.4 进程间通信（ADR-14）
通道： 本机 Unix 域套接字（Windows 用命名管道），不走 TCP，不对局域网暴露；连接时校验对端进程身份。
命令（apid → tradingd）： 带 request_id，tradingd 在 ledger.db 的命令日志里去重并返回原结果；apid 自身不保存命令状态。
意图（workerd → tradingd）： 先写 meta.db 的 outbox，状态为“待投递”；tradingd 落库后回执，workerd 再标记“已投递”。tradingd 不可用时意图留在 outbox，恢复后按 intent_id 重投，重复投递被去重。
过期： 意图带有效期；超过有效期仍未投递的作废并记审计，不在恢复后补发，避免追单。
审计： 其他进程的审计事件也走这条通道追加进 ledger.db；tradingd 不可用期间先写本地暂存文件，恢复后按序补交。

## 5. 数据与存储设计
所有数据只存放在服务器本地：账本类放 SQLite，时序类放 Parquet + DuckDB，文件类放目录；其中“不可替代”的部分必须备份到异地。
### 5.1 存储分工
| 数据 | 存放 | 来源 | 唯一写入者 | 备份 |
| 订单、成交、持仓快照、风控决策、模式与急停状态、命令日志、审计事件 | SQLite ledger.db | 系统产生 | tradingd | 必须，每日 + 异地 |
| 实验、策略版本、DataJob、意图待发队列、模型调用记录 | SQLite meta.db | 系统产生 | workerd | 必须 |
| 客户端会话、令牌、客户端设置 | SQLite api.db | 系统产生 | apid | 必须（令牌可吊销重发） |
| 回测明细（净值曲线、成交明细） | Parquet | 系统产生 | workerd | 必须 |
| 研究库（Markdown、证据原文）与索引 | 文件 + SQLite 全文索引 | AI / 你 | workerd | 文件必须，索引可重建 |
| 历史行情、公司行动、交易日历 | Parquet + DuckDB | 数据供应商 / IBKR | workerd（数据任务） | 可选，可重下，但要留版本与哈希记录 |
| 特征与决策输入快照 | Parquet | 系统产生 | workerd | 与实盘/模拟盘决策关联的必须 |
| 日志、诊断包 | 滚动文件 | 系统产生 | 各进程 | 按保留期，不备份 |
其他进程（apid、workerd）产生的审计事件一律通过 tradingd 的审计接口追加进 ledger.db，保证审计链只有一个写入口（见 3.4）。

### 5.3 历史数据下载与更新
接口： DataProvider 抽象（list_symbols、fetch_bars、fetch_corporate_actions、fetch_calendar、capabilities、rate_limit），每家供应商一个适配器，策略与回测不直接调用供应商 SDK。
M1 数据来源： D-01 先实现 IBKR 历史数据适配器，满足基准策略的信号计算；回测供应商的适配器在 D-08 实现，T-04 之前完成并签约。
回补： 首次全量回补按“标的 × 年”分片，由 DataJob 驱动：带限速、断点续传、失败重试、幂等覆写（同一分片重跑结果相同）。
落盘顺序： 原始层（不可变）→ 标准化 → 质量报告 → 登记 manifest（供应商、拉取时间、哈希、授权条款链接）。
增量： 每个交易日收盘后按交易日历拉取当日数据，次日盘前再校验一次。
修正： 供应商修订数据时写入新版本分区，旧版本保留，回测绑定具体版本。
首期数据集： 关注标的池（数十到数百只 ETF 与个股）的日线、公司行动、交易日历；分钟线按需再加。
### 5.4 容量估算与保留
下表是量级估算，实际取决于字段数和压缩。首期 1TB SSD 足够；若要全市场分钟线，建议至少 2TB。
| 数据 | 量级 | 估算依据 |
| 全市场日线，20 年 | 约 4000 万行，约 1–2GB | 8000 只 × 5000 个交易日 |
| 全市场分钟线，每年 | 约 7.9 亿行，十几到几十 GB | 8000 只 × 390 分钟 × 252 天 |
| 500 只标的分钟线，每年 | 约 4900 万行，约 1GB | 500 只 × 390 × 252 |
| 逐笔成交/报价 | TB 级 | 首期不做 |
| 数据 | 默认保留期 |
| 账本、审计、风控决策、实验元数据 | 永久，不物理删除 |
| 回测明细 | 每个策略保留最近 10 个版本 + 所有已发布版本（可配置） |
| 特征与决策输入快照 | 与交易决策关联的永久，其余 90 天 |
| 模型调用输入输出 | 12 个月压缩归档；摘要与哈希永久 |
| 报价抓取快照 | 30 天 |
| 日志 | 90 天；与 P0/P1 事件关联的随审计永久保留 |
| 诊断包 | 30 天 |
### 5.5 备份（3-2-1）
三份拷贝： 在线数据在服务器本地盘；第 2 份在另一块物理盘或 NAS（每日）；第 3 份是加密后的异地副本（云对象存储或另一地点的设备）。
只备份不可替代的部分： ledger.db、meta.db、api.db、research/、config/、backtests/。行情湖默认不备份，但保留 manifest。
一致性： SQLite 用在线备份接口或 VACUUM INTO 生成快照，附校验和；不直接拷贝正在写入的文件。
演练： 每月一次恢复到干净机器，启动后先进入 HALT，完成券商对账才允许恢复交易。备份不能代替券商对账。
### 5.6 SQLite 使用约束
数据库文件只放服务器本地 SSD，禁止放在 NAS 或网络共享上。
ledger.db：WAL、synchronous=FULL、foreign_keys=ON、设置 busy_timeout。
单写者：每个库只有一个写进程（ledger.db 属于 tradingd，meta.db 属于 workerd，api.db 属于 apid），其他进程用只读连接；AI 进程只拿只读连接。
金额与数量用 Decimal 字符串或整数最小单位，不用浮点数。
唯一约束覆盖 execution_id、intent_id、request_id、券商 permId；订单、成交、审计表用触发器和 Repository 双重禁止 UPDATE/DELETE。
迁移用 Alembic，迁移前自动备份，每次迁移配回滚或向前修复脚本。
出现多个进程并发写入同一库，或需要数据库角色隔离时，再迁到 PostgreSQL；Repository 抽象保证迁移不改业务代码。
## 6. 交易核心与 IBKR 适配
交易核心有三条原则：回测、模拟盘、实盘走同一条代码路径，券商事实优先，状态不确定时先查证再行动。
### 6.1 领域模型
Instrument：资产类别、交易所、币种、乘数、最小跳动、交易时段；规格缺失即禁止下单。
MarketBar / Quote：UTC 时间戳、来源、延迟标记、质量标记、复权版本。
Account / Position / CashBalance（区分已结算与未结算现金，见 ADR-15）；以及主链路 OrderIntent → RiskDecision → BrokerOrder → Execution。
Mode / HaltState；StrategyVersion / Experiment / ModelRun / EvidenceRecord / AuditEvent。
约束：金额用 Decimal，时间用 UTC，关键 ID 建唯一约束，订单、成交、审计不物理删除。
### 6.2 运行模式（ModeManager）
模式共 6 种：RESEARCH、BACKTEST、PAPER、ASSISTED_LIVE、LIMITED_AUTO_LIVE、HALT。模式的唯一事实来源是 ModeManager，不靠 UI 按钮或环境变量。启动时校验账户 ID、配置、权限与限额，任何歧义都拒绝启动。切换到实盘需要确认账户、限额和二次确认，并写入审计。HALT 持久化，重启后不自动恢复。ASSISTED_LIVE 下每个意图都进入待审批队列，由你在客户端逐笔批准或拒绝（S-10）；超过有效期未批准的意图自动作废。
### 6.3 OMS 状态机
| 状态 | 含义 | 允许的后续 |
| CREATED | 策略或用户创建意图 | 风控校验；失败则 REJECTED_BY_RISK |
| RISK_APPROVED | 风控放行 | SUBMITTING |
| SUBMITTING | 请求已发出 | SUBMITTED、REJECTED、UNKNOWN |
| SUBMITTED | 券商已确认接收 | PARTIALLY_FILLED、FILLED、CANCEL_PENDING、REJECTED、EXPIRED |
| PARTIALLY_FILLED | 部分成交 | FILLED、CANCEL_PENDING、EXPIRED |
| CANCEL_PENDING | 撤单请求已发，期间仍可能成交 | CANCELLED、PARTIALLY_FILLED、FILLED |
| UNKNOWN | 本地无法确认结果 | 只能查券商状态后转入上述状态，禁止重发 |
| FILLED / CANCELLED / REJECTED / EXPIRED | 终态 | 仍需对账 |
### 6.4 OMS 不变量
同一 OrderIntent 只能形成一条有效订单链，幂等键在重试中不变。
网络超时进入 UNKNOWN，先查券商再决定下一步，禁止盲目重发。
成交按 execution_id 去重，重复或乱序回报不重复入账。
撤单请求发出不等于撤单成功，撤单期间的成交必须正确入账。
重启、重连、恢复后先拉取券商状态并对账，完成前不恢复自动交易。
状态转移只能走转移表，非法转移被拒绝并告警。
订单分为“开仓单”“减仓单”“保护性止损单”三类，类别在创建时确定且不可修改；guardd 与急停按类别撤单。
### 6.5 IBKR 适配要点
| 主题 | 设计 |
| 订单关联 | 把 intent_id 写入 orderRef；发单前从 nextValidId 分配 orderId 并先持久化；收到 permId 后落库。UNKNOWN 时按 orderRef 匹配开放订单、近期成交和已完成订单 |
| 订单生命周期 | 开仓与再平衡限价单一律带有效期（当日有效或 GTD 到收盘），当日未成交即过期，不自动追价；是否次日按新信号重下由策略决定。可选收盘限价单（LOC），它是限价单，不违反市价单禁令 |
| 对账数据 | 启动与重连用 API 查账户、持仓、开放订单、近期成交；日终用 Flex Query 报表核对成交、现金、佣金。API 的成交查询只覆盖近期，不能单独支撑历史对账 |
| 每日重启与二次验证 | TWS/Gateway 需要每日重启，并大约每周一次要求带二次验证的完整登录，这一步需要你在手机上确认。用 IBC 自动处理每日重启，重启时间设在北京时间白天；系统维护“券商窗口”状态：窗口内禁止新增订单，窗口结束后重连、查询、对账、恢复 |
| 行情 | 区分实时与延迟；模拟账户的实时行情依赖主账户订阅共享，G2 前必须确认可用；订阅条数和历史数据请求有频率限制，需限速队列 |
| 错误与限流 | 错误码映射为内部错误类别，请求速率限制全部封装在适配器内 |
| 模拟盘差异 | 模拟盘成交较理想化，不能证明执行质量。B-06 记录每笔订单的预期价与实际成交价之差（影子成交记录），实盘前再复核 |
| 连接隔离 | tradingd 独占交易 clientId；guardd 用独立 clientId，只能逐单撤销开仓单（跨 clientId 撤单的可行性在 B-03 实测，见 7.6）；TWS API 端口只绑定 127.0.0.1 |
| 时钟 | 启动与定时检查 NTP 偏差，超阈值拒绝新增风险 |
### 6.6 对账
启动对账： 先拉取券商账户、持仓、开放订单、成交，与账本比对；不一致则进入 SAFE HALT 并生成差异报告。
盘中对账： 按参数化间隔比对持仓与开放订单。
日终对账： 订单、成交、现金（区分已结算与未结算）、持仓、佣金逐项核对，差异必须逐项解释；未解决时次日保持 HALT 或受限模式。
公司行动： 拆股、合股、分红导致的持仓数量、成本价和现金变化，先与 D-04 的公司行动数据匹配；匹配上的记为已解释差异，并同步调整保护性止损的数量与价格，匹配不上的才进入 SAFE HALT。
券商事实优先，但不静默覆盖：每次差异都生成事件和报告。
## 7. 风控、急停与故障降级
本地确定性风控拥有最终否决权；任何状态不确定都默认拒绝新增风险；本地失联时，已有持仓还有券商侧的保护。
### 7.1 风控结果
ALLOW： 所有校验通过，仍需经 OMS 状态与幂等检查。
REDUCE： 只允许减风险动作，不能把反向开仓伪装成减仓。
REJECT： 拒绝并记录命中规则，禁止备用路径绕过。
HALT： 系统、账户或数据状态重大不确定，持久化停止状态。
### 7.2 规则层级
| 层级 | 示例 | 默认行为 |
| 系统级 | 模式、全局急停、数据与券商健康、时钟偏差、数据库可用性 | 任一异常禁止新增风险 |
| 账户级 | 总敞口、杠杆（首期固定 1.0）、现金缓冲、已结算现金、日内亏损 | 拒绝新单 |
| 策略级 | 资金预算、回撤、连续亏损、订单频率 | 暂停策略并保留现场快照 |
| 标的级 | 单标的市值、集中度、流动性、价格偏离、止损后冷却期 | 拒绝或缩小 |
| 订单级 | 最大金额/数量、限价偏离、最小跳动、重复订单、允许的订单类型与有效期 | 拒绝并解释 |
| 默认禁用 | 做空、杠杆、衍生品、市价单（紧急平仓用带保护价的限价单） | 无专项规则即禁止 |
| 专项豁免 | 保护性止损单：方向只能卖出、数量不超过对应持仓、类型与价格规则来自附录 A、只能由 OMS 随持仓创建 | 满足全部条件才放行；任何一条不满足即拒绝 |
每条规则包含：rule_id、版本、作用范围、阈值、计算窗口、严重等级、触发动作、是否允许人工覆盖、有效期。阈值见附录 A，由你批准并版本化，AI 无权修改。
### 7.3 急停四级（四个独立操作，不合并成一个按钮）
停止新增订单：关闭新风险入口，持久化 HALT。
撤销未成交订单：逐单撤单并等待确认，请求发出不算成功。默认只撤开仓单与减仓单，保护性止损单保留；需要连止损一起撤时，另行二次确认。
减少风险：只按预先批准的规则和流动性约束执行。
紧急平仓：单独授权和二次确认，展示潜在滑点、市场冲击、交易时段和失败风险。
急停状态持久化，重启后不自动恢复；恢复交易需要重新完成数据、账户、订单、风险和数据库健康检查和对账，实盘阶段再加人工确认。
### 7.4 运行状态
| 状态 | 条件 | 行为 |
| NORMAL | 关键服务健康，数据与账户同步可信 | 允许已授权策略运行 |
| DEGRADED | 非关键组件故障（如模型、数据源），或处于券商重启窗口 | 只允许不依赖故障组件且明确获准的策略；窗口内不新增订单 |
| SAFE HALT | 账户、订单、风险或关键数据状态不可信 | 停止新增风险，持久化，不因网络恢复而自动解除 |
### 7.5 故障失效矩阵
| 故障 | 动作 | 恢复门槛 |
| 行情陈旧或异常 | 拒绝依赖该数据的新增订单 | 时间戳、来源、价差校验通过 |
| IBKR 断线或提交超时 | 停止相关新增订单；订单进入 UNKNOWN，先查再行动 | 同步订单、成交、现金、持仓后恢复 |
| IBKR 每日重启窗口 | 窗口内禁止新增，窗口后重连并对账 | 对账通过 |
| tradingd 崩溃 | 系统服务自动重启，启动后先对账；guardd 告警并逐单撤销开仓单；workerd 的意图留在 outbox | 对账完成，实盘阶段加人工确认 |
| 风控模块异常 | fail closed，拒绝新增风险 | 规则版本确认、健康检查通过 |
| 本地与券商账本不一致 | 暂停相关账户或策略，生成差异报告 | 差异逐项解释或处理后对账 |
| 公司行动导致持仓变化 | 与公司行动数据匹配则记为已解释并调整保护单；匹配不上则 SAFE HALT | 差异解释完毕 |
| 服务器断电或断网 | 已有持仓由券商侧保护性止损兜底；UPS 与备用网络；外部心跳告警 | 恢复后先对账 |
| 数据库损坏 | 保持 HALT，从备份恢复 | 券商状态核对、审计连续 |
| 磁盘将满 | P1 告警，暂停数据回补，为账本写入保留空间 | 清理后恢复 |
| 时钟偏差超阈值 | 拒绝新增风险 | NTP 同步恢复 |
| 数据供应商失败 | 只影响回补与回测；盘前校验失败则当日不跑依赖该数据的策略 | 数据校验通过 |
| 客户端断连 | 服务器状态不变，不影响订单与风控 | — |
AI 相关故障（模型超时、限流、全部不可用）见第 9 章。
### 7.6 券商侧第二道防线
失效矩阵只写“停止新增风险”，回答不了“本地失联期间已有持仓由谁保护”，所以增加三层兜底：
保护性止损单： 每个持仓对应一张挂在券商端的保护性止损单，价格规则来自你批准的参数，由 OMS 创建并纳入对账（R-06）。
普通止损单触发后按市价成交，因此在 R-04 中作为专项豁免处理（见 7.2），不放开一般市价单。止损限价单在跳空时可能不成交，失去兜底意义，首期不用。
止损单在跳空或流动性不足时可能以更差价格成交，这是为避免“完全无保护”而接受的代价。
保护单是常驻挂单，单独计数，不占用“最大未成交订单数”的额度。
止损成交后，该标的进入冷却期（附录 A），冷却期内策略不得买回；冷却期结束后按下一次再平衡信号决定。
券商订单预防设置： 把 TWS/Gateway 的单笔数量、金额、价格偏离上限按参数草案配置，纳入 F-05 与上线检查清单。
guardd 独立撤单进程： 独立进程、独立 clientId、只有撤单权限。tradingd 心跳丢失超过阈值时，逐单撤销全部未成交的开仓单；不平仓、不下新单、不撤保护性止损单。
不使用全局撤单：它会撤掉账户里所有挂单，包括保护性止损，恰好在最需要止损的时候把它撤了。
独立 clientId 通常只能撤自己下的单，跨 clientId 撤销 tradingd 的订单需要额外配置，可行性在 B-03 实测。
若实测不可行：开仓单一律带短有效期（当日或 GTD），即便无人撤单也会自动过期；guardd 退化为只告警，替代方案写入 ADR。
## 8. 数据平台、策略与回测
首期用日线低频策略，数据平台只做“够用且可信”；回测与实盘共用同一套 OMS 与风控代码，由 SimBroker 撮合成交。
### 8.1 数据标准化与门禁
所有行情统一为 UTC 时间戳加交易所本地时区，交易日历覆盖夏令时、提前收市和节假日。回测必须绑定具体数据版本，供应商修订数据写新版本。
| 检查 | 判定 | 失败时行为 |
| 新鲜度 | 报价时间戳超过阈值 | 禁止新增风险，显示原因 |
| 完整性 | 关键字段为空、OHLC 逻辑不成立、规格缺失 | 隔离记录，不进入策略或回测 |
| 连续性 | 异常缺口、重复、时间逆序 | 标记并出质量报告，禁止静默填充 |
| 来源一致性 | 主备数据源价差超阈值 | 报警，不盲目下单 |
| 前视检查 | 特征使用了当时未发布的数据 | 回测失败 |
| 复权一致性 | 拆股/分红调整与成交、持仓口径不一致 | 停止相关标的回测与自动交易 |
### 8.2 策略与组合
策略接口： initialize(config)、on_bar(data)、on_event(event)、generate_targets(context)、on_fill(fill)、snapshot_state()、restore_state(snapshot)。策略不持有券商连接，不修改风险限额，只输出目标仓位或订单意图。
首期基准策略： 低频 ETF 趋势/动量轮动（周度或月度再平衡、仅多头、保留现金仓位）。目的是验证系统链路而非追求收益，具体规则在 T-02 与你确认。
链路冒烟策略（仅模拟盘）： 基准策略月度再平衡时，20 个交易日的观察期里只会下一次单，样本太少。冒烟策略每天小额买卖一两只高流动性 ETF，并按计划制造撤单与改单，专门积累下单、撤单、对账的样本；它不参与绩效评估，也不进入实盘。基准策略验证信号正确性，冒烟策略验证执行链路。
订单生命周期： 再平衡限价单当日有效、不自动追价；当日未成交部分按策略规则决定次日是否重下（见 6.5）。
止损后再入场： 保护性止损成交后，策略在冷却期内不得买回该标的（附录 A）。
调度： 按交易日历在固定时点生成目标仓位并以限价单执行，时点与价格偏离为参数。
组合层（M2）： 把目标权重转为目标数量，计入现金（只用已结算现金规划买入）、在途订单、成本和预算；输入不完整时不输出无约束仓位，回退到不交易。
### 8.3 回测引擎
共用路径： 回测中的 OMS、风控、策略接口与实盘是同一份代码，成交由 SimBroker 模拟（与 FakeBroker 共用撮合内核）。
时间语义： 信号可用时间 < 下单时间 < 成交时间，禁止同一根 bar 偷看收盘后信息再按收盘价成交。
成本： 佣金、监管费、买卖价差、滑点、部分成交、限价未成交、借券与融资成本（适用时）。
防过拟合： 样本内/外、walk-forward、参数邻域敏感性、子区间、不同市场环境、交易次数与换手。
数据偏差： 股票池包含退市标的（幸存者偏差）、复权口径固定、前视泄漏测试阻断。
可复现： 实验绑定数据快照、代码 commit、参数、股票池、成本模型、随机种子、依赖版本。
探索工具： 允许用向量化工具快速探索，但结果不能作为发布依据。
### 8.4 策略生命周期与发布门禁
Idea → Hypothesis → Data Audit → Baseline → Backtest → Robustness → Paper → Review → Limited Live → Monitored Production → Retire。每次晋级保存数据版本、commit、参数、成本模型、评测结果、审批人和退出条件。T-08 发布门禁自动检查：回测可复现、样本外表现、成本压力测试、模拟盘观察期达标、风控参数匹配。AI 可以提议，不能批准。
### 8.5 绩效指标
收益（累计、年化、超额）、风险（最大回撤、波动率、下行波动）、风险调整收益（Sharpe、Sortino、Calmar，注明无风险利率与年化口径）、交易质量（换手、滑点、费用占比）、稳健性（子区间、参数邻域、压力场景）、容量（成交额参与率、规模变化下的收益衰减）。
## 9. AI 指挥中枢（M3，后置）
AI 在 M3 才接入，职责限于研究、提议、复核，永远不持有券商密钥、不直接下单；任何交易意图都要经过策略预算、本地风控和 OMS。开始条件：G4 已通过，且 M1 的模拟盘已进入 G6 观察。
### 9.1 职责边界
| 可以做 | 必须受控 | 不得做 |
| 新闻与财报摘要、证据提取、反方论证、异常解释、日终摘要 | 提出策略候选与参数（必须回测与评估）；提交 OrderIntent（只能在已批准策略预算内、经风控）；生成代码（经审查与测试） | 调用券商 API、修改风控或限额、批准自己、执行 shell 或 SQL、把第三方文本当指令 |
### 9.2 ModelGateway
统一接口 generate_structured、call_tool、health_check、estimate_cost；供应商（OpenAI、xAI Grok、Anthropic 等）各一个适配器，策略与 OMS 不引用任何供应商 SDK。
模型 ID、推理等级、预算由配置控制，由评测集选型，不硬编码；不要把订阅产品的模型名等同于 API 可用模型。
请求上下文带 task_id、correlation_id、模型与提示版本、输入快照 ID、deadline、budget。
严格结构化输出（Pydantic，未知字段拒绝）；超时、限流、重试、退避、取消、熔断、备用路由；交易相关动作禁止盲目重试。
密钥走凭据存储，不进代码、日志、提示词或知识库。模型 API 的网络可达性在 F-05 实测。
### 9.3 记录与回放
实验要求可复现，但 LLM 输出有随机性。所以每次模型调用按（模型版本、提示版本、输入快照哈希）缓存输出；回测、复盘、测试一律回放缓存，不重新调用。ModelRun 记录 provider、模型与提示版本、输入快照、输出哈希、延迟、费用、状态。
### 9.4 评测与前视偏差
模型的训练数据已包含历史事件，“历史盲测”不能证明真实预测能力。
AI 驱动信号的批准依据是：冻结模型与提示版本后的前向模拟盘表现，观察期至少 4–8 周，并在评测计划中预先定义，不能事后为通过而修改。历史回放只用于排除明显缺陷和回归测试。
固定评测集（A-09）：模型或提示升级前必须回归通过，未评测的版本不得晋升。
### 9.5 权限矩阵
权限按“角色 × 动作 × 范围”定义，在服务端 API 层强制，不依赖提示词；AI 进程只拿只读数据库连接；工具白名单每次调用都校验参数、权限与预算。
| 角色 | 可读 | 可写 | 可提交订单意图 | 限制 |
| 研究 Agent | 行情、研究库、账户只读快照 | 研究库（标注 AI 产物） | 否 | — |
| 策略 Agent | 同上 + 回测结果 | 实验与候选策略（研究分支） | 否 | 不得批准发布 |
| 复核 Agent | 同上 + 证据原文 | 复核结论 | 否 | 复核失败则拒绝新增风险 |
| 交易助手 Agent | 账户只读、风控结果 | 待审批摘要 | 仅在已批准策略预算内，经风控 | 实盘首期只提交待审批意图（进入 S-10 审批队列） |
| 运维 Agent | 日志、指标 | 诊断报告 | 否 | 不执行任意命令、不改生产配置 |
| guardd（非 AI） | 心跳、订单状态 | 逐单撤销未成交开仓单 | 否 | 不平仓、不下新单、不撤保护性止损 |
### 9.6 外部情报与 Grok
Grok 用于 X 舆情线索与反方论证；未核实的社交媒体内容只标记为“未核实证据”，不能单独触发交易。
所有第三方内容（新闻、网页、社交媒体）一律视为不可信输入，提示注入测试为 P0；内容不能改变权限或风控配置。
Grok 不可用只影响依赖它的研究任务。聊天机器人只用于告警通知，不作为控制接口。
### 9.7 调用模式与降级
三类调用： 快速模式（事件分类、摘要）、深度推理（财报与宏观重大事件、策略切换、异常诊断）、独立复核（重大风险动作、模型冲突、数据异常）。多模型多数票不构成风险授权，复核的价值在独立证据与冲突识别；复核失败则拒绝新增风险。
降级： 模型超时或限流→有限重试后停止 AI 依赖型新增风险；全部不可用→本地已批准的确定性策略照常运行；恢复后重新评估，不自动追单；预算超限→降到快速模式或停止。
### 9.8 结构化对象与知识库
EvidenceRecord、DecisionProposal、RiskAssessment、OrderIntent、ModelRun 使用版本化 schema；每个交易意图必须关联数据快照、策略版本、决策与风险结果。
知识库：Markdown 研究库 + SQLite 全文索引 + 本地向量索引（选型在 A-06 决定）；Embedding 服务可配置（如阿里百炼 text-embedding-v3），记录模型名、版本、维度，可重建；原文与 AI 摘要分开保存，摘要可回溯原文。
## 10. 服务端 API、客户端与运维
客户端只是遥控器和显示器：服务器照常运行，客户端断线不影响订单与风控，所有控制动作都走认证、可审计的 API。
### 10.1 API 设计
协议： REST（命令与查询）+ WebSocket（订单、行情、风险、告警事件流），路径带 /v1 版本号，由 OpenAPI 生成 TypeScript 类型。
命令分级： 只读；控制（启停策略、撤单、停止新增、审批或拒绝待审批意图）；高危（紧急平仓、切换到实盘、连同保护性止损一起撤单）。高危命令需要二次确认令牌并写入审计。
限额不走 API： 风控限额只能通过受保护的配置文件修改并版本化，任何 API 都不能提高限额。
幂等： 所有命令带 request_id，由 tradingd 去重（见 3.4）。
### 10.2 认证与网络安全
服务只监听局域网或本机，不做端口映射、不暴露公网；外出访问通过 VPN（WireGuard 或 Tailscale）。
客户端用可吊销的长随机令牌或客户端证书；局域网内使用 TLS（自签证书并在客户端固定）。
服务器防火墙只向局域网放行 API 端口；TWS API 端口只绑定 127.0.0.1；进程间通信只走本机套接字。
客户端不持有券商密钥、模型密钥和数据库。
角色：owner（你）、viewer（只读），以后可扩展。所有会话与操作写入审计。
### 10.3 客户端（Web，可套桌面壳）
| 页面 | 必须显示 |
| 总览 | 模式、券商连接、数据健康、净值、现金（已结算/未结算）、当日盈亏、风险状态、急停 |
| 市场 | 观察列表、报价时间、价差、延迟标识 |
| 策略中心 | 策略版本、运行状态、资金预算、当前信号、最近异常 |
| 待审批队列（S-10） | 待审批意图、方向、数量、限价、名义金额、风控结果、来源（策略或 AI）、剩余有效期；逐笔批准或拒绝 |
| 回测实验室（M2） | 实验列表、参数、数据版本、收益与回撤、样本外结果 |
| 组合与风险 | 资产分布、敞口、集中度、风控规则命中、保护性止损覆盖情况 |
| 订单与成交 | 状态机、订单类别、成交明细、拒单原因、券商订单号、本地关联 ID、影子成交偏差 |
| 研究知识库（M3） | 来源、AI 摘要、证据与实验链接 |
| 日志与告警 | 错误分级、连接状态、审计事件、诊断包导出 |
| 系统设置 | 只读展示券商连接、数据源、备份、版本；修改项走受保护流程 |
PAPER/LIVE 用固定位置的高对比标识；订单预览显示方向、数量、类型、限价、名义金额、费用与风险估算、策略来源、风控结果。
报价必须显示时间戳与延迟状态；撤单、停止新增、急停、紧急平仓是四个独立控件，高危操作二次确认。
告警可以确认，但不能通过关闭通知解除实际风险状态；服务器不可达时明确提示“数据可能已过期，服务器仍在运行”。
桌面壳只是加载服务器地址的外壳（Tauri），手机浏览器在认证后也可查看和急停。
服务器不可达时的兜底：运行手册（S-11）写明用 IBKR 官方手机 App 或 TWS 手动撤单的步骤，并定期演练。
### 10.4 运行环境
硬件： 常开运行机（x86 小主机或 Mac mini 等），16GB 以上内存、首期 SSD ≥ 1TB、UPS、备用网络（第二条宽带或手机热点）、断电恢复后自动开机。操作系统待你确认；Linux 无图形环境运行 IB Gateway 需虚拟显示。
系统服务： tradingd、apid、workerd、guardd 作为系统服务常驻，崩溃自动重启并带退避；tradingd 启动后先对账。
告警： P0（重复下单风险、账户状态未知、实盘误切换、急停失效、保护性止损缺失）走手机推送并重复提醒；P1 券商断线、行情严重陈旧、对账不一致；P2/P3 进面板。手机渠道可选 Telegram、飞书、企业微信或短信（S-07）。
外部心跳： 服务器每分钟向外部监控（Healthchecks 类服务或你自己的云函数）发心跳，超时即通知，整机宕机也能被发现。国内网络的可达性要在 F-05 实测。
升级： 实盘期间不热升级核心；升级前进入停止新增状态并处理在途订单，升级后只读健康检查与对账通过才恢复；先升级服务端再升级客户端。
### 10.5 每日运行节奏
| 阶段 | 美东时间 | 北京时间（夏令时 / 冬令时） | 动作 |
| 盘前检查 | 08:30 | 20:30 / 21:30 | 模式、账户 ID、连接、数据新鲜度、启动对账、策略清单与限额 |
| 常规交易 | 09:30–16:00 | 21:30–04:00 / 22:30–05:00 | 监控订单、风险、行情延迟、目标与实际仓位偏差 |
| 盘后 | 16:30 起 | 04:30 / 05:30 起 | 日终对账、日报、备份与结果检查、归档 |
| Gateway 重启 | — | 北京时间白天（如 12:00） | IBC 自动重启；每周一次完整登录需要你在手机上完成二次验证 |
美国夏令时将于 2026 年 11 月 1 日结束，之后开盘为北京时间 22:30。调度一律由交易日历驱动，不硬编码北京时间。若对账有未解释差异或出现 P0/P1 事故，次个交易日保持 HALT 或受限模式。
## 11. 测试与质量门禁
交易路径靠“可复现的故障注入”而不是人工目测：FakeBroker 能精确复现每一种危险时序，CI 中任何不变量被破坏都会阻断合并。
### 11.1 测试分层
| 层级 | 内容 | 门禁 |
| 单元 | 状态机、风控规则、仓位计算、费用模型、时区与日历 | 核心分支与边界全覆盖 |
| 属性/不变量 | 成交数量守恒、现金与持仓一致、重复事件幂等、状态合法转移（hypothesis 生成随机事件序列） | 不变量在随机序列中成立 |
| 契约 | BrokerAdapter 契约套件同时跑 FakeBroker 与 IBKR 模拟盘 | 两者行为一致 |
| 集成 | 数据库、API、进程间通信、OMS + 风控 + FakeBroker 端到端 | 可自动重建、可重复 |
| 故障注入 | FakeBroker 场景库（见 11.2） | 不重复下单、不重复记账，不确定状态 fail closed |
| 架构 | import-linter、“唯一下单出口”扫描、受保护文件检查 | 违反即阻断合并 |
| 回测验证 | 已知数据集、手工核算样例、前视泄漏测试 | 与独立计算一致 |
| 安全 | 提示注入、权限越权、密钥扫描、模式错配 | 越权 100% 拒绝 |
| 前端端到端 | Playwright：模式标识、急停四控件、断连提示、待审批队列 | 关键流程通过 |
| 模拟盘运行 | 持续运行、重启恢复、日终对账、冒烟策略样本 | 无未解释差异 |
### 11.2 FakeBroker 故障场景库（全部 P0）
共 17 项：前 16 项属于 M1 范围，第 17 项属于 M3（在 G9 验证）。V4.1 新增第 15、16 项。
已接单但响应丢失（超时）：进入 UNKNOWN，查单后不重发。
成交回报重复两次：只入账一次。
成交回报乱序（成交先于确认）。
撤单过程中成交，以及部分成交后撤单。
拒单：价格偏离、无权限、合约未找到。
提交后进程崩溃：重启后先查单。
断线重连期间状态漂移：重连后对账。
券商重启窗口内的下单请求：被拒。
行情陈旧或缺失：拒绝新增。
风控模块无响应：不放行。
账户持仓与券商不一致：SAFE HALT。
备份恢复后首次启动：先对账，保持 HALT。
夏令时切换日与提前收市：日历正确。
磁盘写满或数据库锁：账本写失败时 fail closed。
tradingd 心跳丢失：guardd 只撤开仓单，保护性止损保留；tradingd 恢复后 outbox 中的意图不重复成交。
拆股或分红后持仓与现金变化：对账识别为公司行动，保护性止损同步调整，不误入 SAFE HALT。
恶意新闻文本要求下单（M3）：权限拒绝，提示注入被隔离。
### 11.3 CI 与报告规则
每次提交：ruff、mypy、单元 + 属性 + 架构测试、gitleaks。
每个 P0 任务合并前：契约 + 故障注入 + 集成测试。
每个里程碑门禁：完整套件 + 模拟盘证据。
测试报告必须列出实际执行的命令与结果，未运行的测试明确标注；FakeBroker 通过不能代替 IBKR 真实联调，只能标为 PARTIALLY VERIFIED。
### 11.4 不可折中的安全指标
这些指标的目标值都是 0，不能用更高收益、更低成本或模型自评来抵消。共 10 项，V4.1 新增最后一项。
| 指标 | 目标 |
| 未授权实盘订单 | 0 |
| 超出硬性限额的已授权订单 | 0 |
| 因超时盲目重发导致的重复订单 | 0 |
| 重复成交回报导致的重复入账 | 0 |
| 风险服务不可用时放行新增风险 | 0 |
| 无法关联到决策、策略、风控检查的实盘订单 | 0 |
| 急停后应用重启自动恢复交易 | 0 |
| 客户端断连导致订单状态改变 | 0 |
| 策略要求保护但未被券商侧止损覆盖的实盘持仓 | 0 |
| guardd 或急停在未经二次确认时撤销保护性止损单 | 0 |

### 12.3 任务状态
NOT STARTED → READY → IN PROGRESS → BLOCKED（需外部决策或依赖）→ IMPLEMENTED → IN REVIEW → ACCEPTED / REJECTED；DEFERRED 用于有明确理由的延后。实现完成不等于验收通过。
### 12.4 越界与变更控制
需要修改任务范围外的公共接口时停下，提交变更请求：原因、影响模块、兼容性、测试、回滚。
任何涉及实盘、限额、风控规则、账户权限、密钥、订单执行的变更，必须由你明确批准。
无法联调真实 IBKR 时标 BLOCKED 或 PARTIALLY VERIFIED，不得用模拟测试冒充。
测试失败不得标 ACCEPTED；已有失败需证明未被扩大。

## 附录 A. 风控参数草案
