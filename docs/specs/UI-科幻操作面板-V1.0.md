## 第一部分：规范要点

### 1. 目标与原则

- **风格**：专业级 AI 量化交易控制台。
  - 底色：深蓝黑。
  - 主光：电光蓝、青色；辅助光：紫色。
  - 状态色：绿色表示安全，橙红色表示风险。
  - 质感：细线霓虹边框、轻玻璃拟态、克制的科技动效。
- **这是可操作的真实界面**，不是装饰大屏。每个关键数字、新闻、状态和图表都来自后端数据。只有在全局醒目标记的 DEMO 模式下才显示样例。
- **桌面优先**，重点适配 1920×1080 和 2560×1440。缩放时核心控件不遮挡、文字不重叠、风险信息不裁切。
- **动效只表达扫描、更新和状态变化**，不持续干扰阅读，并提供“减少动态效果”设置。
- **高风险操作**都要有后端权限校验、必要的二次确认、审计记录和明确的结果反馈。

### 2. 布局

| 区域 | 位置 | 内容 | 交互 |
|---|---|---|---|
| 顶部系统栏 | 全宽 | 系统名、运行状态（正常/降级/停止）、市场时间、当前模式、券商连接、设置 | 模式醒目；时间带时区；PAPER 与 LIVE 一眼可分 |
| 主导航 | 第二行 | 总览、市场分析、AI 指挥中枢、策略管理、交易执行、风险控制、数据中心、系统设置 | 切换不丢全局状态；权限不足的项禁用 |
| 左：市场概览 | 约 20–23% | 三大指数卡片、涨跌、迷你趋势图、周期选择、主行情图 | 周期切换、悬停详情、来源与实时/延迟标记 |
| 中：AI 指挥中枢 | 约 52–56% | 决策分析视图、全球情报视图，一键切换 | 不刷新整页，不影响外围面板的订阅 |
| 右：账户概览 | 约 22–25% | 净清算价值、可用资金、持仓市值、当日盈亏、账户曲线、持仓分布 | 金额带币种与更新时间；可下钻 |
| 底部信息带 | 约 25–30% | 决策与交易动态、策略表现、风险控制、系统运行状态 | 可展开；告警可定位；状态不只靠颜色 |

### 3. 中枢双视图

- **切换**：
  - 两个选项固定在中央模块上方，有选中、悬停、键盘焦点和禁用四种状态。
  - 切换时只替换中央内容，用 180–350 ms 的淡入或扫描过渡。
  - 当前视图在会话内保持。视图偏好不能和交易模式、权限混在一起。
  - 一个视图加载失败时，显示原因和重试入口，另一个视图照样可以切换。
- **视图 A：决策分析**：
  - 中央是 AI 核心视觉，四周显示主模型、研究助手、决策质量、决策模式和风险状态。
  - 动画只表达状态，不暗示系统没有的能力。
  - 未配置的模块明确显示“未配置”。
  - “决策质量”要写明口径。模型给自己的评分不能冒充客观准确率。
  - 决策模式只读，显示后端的授权状态。
- **视图 B：全球情报地图**：
  - 深色平面世界地图，带热点脉冲、扫描环和事件连线，并配固定图例。
  - 事件流按时间倒序排列，支持筛选、搜索、暂停滚动、标记已读和打开原文。
  - 点开事件详情，显示：标题、摘要、来源链接、发布时间、抓取时间、地区、类别、重要性、关联资产与行业、证据状态。
  - AI 影响分析要标明“模型观点”，并附证据、置信度和分析时间。不能把相关性画成因果关系。
  - 每个热点都要有定位依据和置信度。定位不了的事件进“未定位事件”列表，不随意放坐标。
  - 没有新事件时显示“当前无新增事件”，不制造假热点。
  - 新闻要去重、聚合，同时保留原始来源和抓取时间。
  - 地图或新闻源故障时，显示异常状态，并降级为只显示事件列表。

### 4. 周边面板

- **市场概览**：
  - 至少有 S&P 500、Nasdaq（写明是 Composite 还是 Nasdaq 100）、Dow Jones。
  - 周期：1D、1W、1M、3M、1Y、ALL。
  - 未订阅实时行情时，标注“延迟”或“收盘”。
- **账户与持仓**：
  - 所有金额带币种和计算时间。
  - 持仓分布可以按资产类别、行业、标的分组，并能下钻到明细。
  - 同步失败或数据过期时，显示最后更新时间。
- **决策与交易动态**：
  - 用时间线展示：研究结论、风险检查、交易意图、订单提交、券商回报、成交、撤单、数据更新、人工操作。
  - 明确区分四个阶段：建议、风控通过、已提交券商、已成交。
  - 尽量关联策略版本、订单 ID、执行 ID 和审计记录。
- **策略表现**：
  - 指标：收益率、胜率、盈亏比、Sharpe、最大回撤。
  - 写明统计周期、样本数、费用口径，以及是 PAPER 还是 LIVE。
  - 样本不足时显示 N/A，不填假数字。
- **风险与急停**：
  - 风险指标来自独立的风险引擎，前端不自行计算后当作最终判断。
  - 急停入口全局显眼，和普通设置分开。触发后要有状态反馈和审计记录。
- **系统状态**：
  - 覆盖：行情、IBKR、数据库、策略引擎、AI 服务、OMS。
  - 状态分为：正常、警告、降级、故障、未知。
  - 显示最后心跳时间和错误摘要，并反映系统是否处在 DEGRADED 或 SAFE HALT。

### 5. 视觉与动效

| 元素 | 规范 | 性能与可访问性 |
|---|---|---|
| 背景 | 深蓝黑底，低对比的网格或粒子 | 可以关掉；不降低文字对比度 |
| 主色 | 电光蓝和青色用于选中、交互、扫描；紫色辅助 | 统一用设计令牌 |
| 状态色 | 绿=正常，黄=警告，橙=高风险，红=严重或停止 | 同时显示图标和文字 |
| 地图热点 | 呼吸脉冲、扫描环、短时连线、光晕 | 热点多时聚合；动效节流 |
| 数据更新 | 数值轻微高亮；图表平滑更新 | 局部刷新，不因每个 tick 重渲染整页 |
| 卡片 | 细线霓虹描边、层次阴影、轻玻璃拟态 | 不牺牲清晰度 |
| 字体 | 清晰的无衬线中文字体；关键数字用等宽数字字形 | 缩放后仍然清晰 |

### 6. 数据与前后端边界

- 界面只通过后端的数据契约取数。界面不连券商、不持有密钥、不绕过风控和 OMS。
- 原文建议的契约：
  - 行情：MarketSnapshot、Bar、Quote；
  - 账户：Account、Position；
  - AI：ModelHealth、DecisionStatus；
  - 交易动态：Decision、Order、Execution 事件；
  - 情报：NewsEvent、IncidentEvent；
  - 风险：RiskSnapshot、RiskAlert；
  - 健康：ServiceHealth、SystemMode。
- 每条数据都带数据时间、接收时间、来源和质量状态。新闻同时带发布时间和抓取时间。
- 实时通道要支持：断线重连、序列号或游标、去重、乱序处理、全量快照补偿。
- 外部新闻、社交媒体和网页一律视为不可信输入。
- 没有数据时显示空状态。禁止用随机数或静态样例填充生产界面。

### 7. 异常降级

| 场景 | 界面表现 | 系统行为 |
|---|---|---|
| 正常 | 状态正常，时间戳持续更新 | 只有真实心跳成功才显示正常 |
| 行情延迟 | 显示 DELAYED 和最后更新时间 | 过期行情不得用于新增风险 |
| 新闻源断开 | 显示数据源异常，保留历史事件 | 不伪造新事件 |
| 模型不可用 | 显示 DEGRADED 或 ERROR | 不扩大备用模型的权限 |
| IBKR 或 OMS 不可用 | 交易连接告警；订单状态显示 UNKNOWN | 停止新增风险；恢复后先对账，不盲目重发 |
| 演示模式 | 全局醒目标记 DEMO / SIMULATED | 样例数据与生产账本隔离 |

### 8. 验收标准（AC-01 至 AC-14）

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC-01 | 视觉布局 | 目标分辨率下没有重叠、裁切、错位 |
| AC-02 | 双视图 | 一键切换，不刷新整页，外围状态不丢，可以用键盘操作 |
| AC-03 | 全球地图 | 热点可点击，和事件列表联动，可以缩放、平移 |
| AC-04 | 实时事件 | 去重、乱序处理、时间戳、来源都正确；断线后能恢复 |
| AC-05 | 数据真实性 | 生产环境绑定真实接口；演示数据全局标记 |
| AC-06 | 数据时效 | 行情、账户、新闻、系统状态都显示最后更新时间 |
| AC-07 | 风险显示 | 风险数据来自独立引擎；SAFE HALT 不能被界面隐藏 |
| AC-08 | 交易语义 | 建议、风控通过、提交、成交四个阶段分开，ID 可追溯 |
| AC-09 | 异常降级 | 地图、行情、模型、IBKR、OMS、数据库异常时，状态显示正确 |
| AC-10 | 安全权限 | 不能绕过后端权限、风控、OMS；高风险动作有确认和审计 |
| AC-11 | 性能 | 事件高峰时有聚合或节流，界面不卡死 |
| AC-12 | 长时间运行 | 连续运行 8 小时以上，没有内存泄漏、订阅累积或状态失真 |
| AC-13 | 可访问性 | 状态不只靠颜色；键盘焦点可见；减少动效模式可用 |
| AC-14 | 测试证据 | 有自动化、契约和异常测试记录及截图；没执行的项标 NOT RUN |

**交付物**：
- 截图：1920×1080 和 2560×1440 两种尺寸，四组场景（总览、决策分析、全球情报、异常降级），真实模式和 DEMO 模式都要有；
- 一段短录屏；
- 组件清单、接口契约、已知限制。

**本规范不授权的事项**：
- 不指定行情或新闻供应商；
- 不授予 AI 实盘权限；
- 不改变权限层级、硬风控、SAFE HALT 或 OMS 规则；
- 不要求重写现有模块。

## 第二部分：与 V4.1 的对齐（Ada 补充）

### A. 首期范围内的调整

首期范围：美股和 ETF 现货、只做多、不用杠杆、IBKR 模拟盘。

| 效果图 / 原文 | 首期做法 | 原因 |
|---|---|---|
| 持仓分布含“期权” | 只有股票、ETF、现金三类；另有按行业、按标的两种维度 | 首期不做衍生品 |
| “保证金比例”“保证金使用率” | 换成现金、已结算现金、未结算现金（ADR-15） | 现金账户，不用杠杆 |
| 账户下拉可切换 | 只显示登记的一个模拟账户，不提供切换 | 账户由 B-03a 核验锁定 |
| 主模型、研究助手、AI 模型服务 | 显示“未启用”（灰色加文字），AI 模块上线后再接 | 首期没有 AI |
| 三大指数实时点位 | 没有实时授权时标“延迟”或“收盘”；也可以先用 SPY、QQQ、DIA 代替，并写明口径 | 不承诺免费实时行情 |
| 全球情报地图的真实数据 | 依赖 A-11 至 A-15；在那之前只有 DEMO 模式和“情报未接入”的空状态 | 情报模块在 M3 |
| “交易监控中”“系统运行正常” | 只有真实心跳成功才显示正常；HALT、UNKNOWN、数据过期的优先级最高，不加花哨动效（S-16 原则 2） | fail closed |
| 风控面板的“阈值上限” | 只读显示风险引擎给的值；放宽限额仍走 ADR-16 的二次确认 | 限额只有 Dylan 能改 |

### B. 协调助手的两条决定（2026-11-05）

1. **DEMO 模式在 LIVE 模式下不能开启。**
   - 生产构建里不包含随机数、硬编码余额或伪造新闻。
   - 演示样例只放在独立的演示数据模块里，生产构建不打包它，有测试检查。
   - DEMO 模式下全局显示 DEMO 标记，不连真实账本。
2. **急停沿用现有设计。**
   - 急停只撤开仓单、保留保护性止损，并持久化 HALT。
   - 不是一键市价平仓，也不使用全局撤单。
   - 界面的急停入口调用现有的 apid 接口，不另做一套。

### C. 工程约束（沿用现有规则）

- **地图底图**：用公共领域或开源许可的世界地图数据（例如 Natural Earth，属于公共领域），打包在本地，不联网加载。登记到 `docs/licenses/`。
- **字体**：通过 H-01 的字体许可检查（OFL、Apache、MIT），不加载网络字体。
- **依赖**：不为视觉效果引入大型依赖。新增依赖要过许可证检查和漏洞扫描。
- **实时通道**：沿用 apid 现有的接口。断线重连、去重和快照补偿按 UI-07 补齐。
